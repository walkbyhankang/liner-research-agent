# 해커톤 구현 계획: 벤처기업 자금조달 상담 준비 에이전트

> 작성 2026-11-21(토). 제출 마감 **2026-11-25(수)**, 남은 개발일 4일.
> 근거: 팀 기획 대화(ChatGPT 공유 "벤처금융 웹사이트 기획"), 대회 공고(contests.liner.com/hackathon/exe-thon-2611), 각 API 공식 페이지.
> 이 문서는 **작업을 시작할 때 세운 계획**이다. 이후 방향이 "자금 찾기 + 공고문 자격 대조"로 바뀌어 실제 구현은 이 문서와 다르다.

## 1. 무엇을 만드는가

창업자가 **회사와 자금 목적**을 넣으면, 에이전트가 국내 은행대출·보증·정책자금·벤처펀드 자료를 찾아
**① 어디에 연락할지 ② 왜 그곳인지 ③ 첫 상담에서 무엇을 물을지**를 한 장의 상담 메모로 정리한다.

- 병목(문제 정의 30%): 창업자가 기업마당·벤처투자종합포털·은행 사이트를 오가며 직접 하는 **조건 대조와 후보 비교**.
- 시연 기업: 주최사 **라이너**. 공개자료만으로 세 시점(시리즈 A 2020 / B 2022 / C 2026)을 재구성한다.
- 메인 시연: **시나리오 B** — "라이너가 조달한 110억 원은 전부 투자금이었을까요?" → 원문에서 기관별 역할(투자 주도 / 투자 참여 / 보증부 대출)을 짚고, 투자·대출별 금액은 **공개자료에서 확인 불가**라고 답한다.
- 완성 기준 1순위: **우선순위(지분 희석 최소화 ↔ 투자자 찾기)를 바꾸면 후보 순서와 상담 질문이 함께 바뀐다.**

가입이 **필요 없는** 것: 은행 상품(IBK 등)·기보/신보 보증 제도·운용사 포트폴리오는 공개 API가 없어 **Liner Search + 원문 확인(fetcher)** 으로 수집하고 시드 카탈로그로 검수한다. DB·인증·호스팅 계정도 쓰지 않는다(파일 저장, 로컬 실행).

### 확인한 것 / 못 한 것
- 확인(공식 페이지 원문): 기업마당 요청 URL `https://www.bizinfo.go.kr/uss/rss/bizinfoApi.do`, 변수 `crtfcKey·dataType·searchCnt·searchLclasId·hashtags·pageUnit·pageIndex`, 응답 필드 `pblancNm·pblancUrl·pblancId·jrsdInsttNm·excInsttNm·bsnsSumryCn·reqstBeginEndDe·trgetNm·refrncNm·rceptEngnHmpgUrl·flpthNm·printFlpthNm·hashTags·totCnt`. "마감되지 않은 공고에 한해 제공".
- 확인: KVIC `https://www.kvic.or.kr/api/fundType`(`fundType` 필수: 00 전체/7 모태, `year·fd·mng·asn·expS/E·amtS/E·caS/E·of·key`), 응답 `year·fd·mng·asn·exp·amt·ca`. 현황은 **한국모태펀드만**, 1회 최대 10,000건.
- 확인: Liner Search `include_knowledge` 기본 true(미전송 시 $2/1,000) — 기존 코드의 `false` 명시 전송 유지. Scholar 엔드포인트, MCP(`platform.liner.com/api/v1/mcp`) 존재.
- **미확인**: 기업마당 `searchLclasId` 금융 코드(행사정보 API 페이지에는 01=금융으로 기재, 지원사업 API 코드표는 키 발급 후 실응답으로 확인), 두 API의 호출 한도, KVIC `fd`(출자분야) 값이 항상 채워지는지(샘플은 빈 값), DART에서 라이너 같은 비상장사가 조회되는지, Liner Model의 구조화 출력 상세(기존 `liner_client.responses` 동작 방식 유지).
- **미검증 사실**: 기획 대화에 나온 라이너 라운드 수치(50억/110억/270억/500억, 투자사 명단, MAU 등)는 ChatGPT 답변 기준이다. 스냅샷을 만들 때 원문 대조를 거쳐 `confirmed`만 확정 표기한다.

## 3. 시스템 설계

```
Web (Next.js) ──HTTP/SSE──▶ API (FastAPI) ──▶ funding/ (신규 엔진) ──▶ 기존 flat 모듈 ──▶ Liner API
                                   │                 ├─ connectors: 기업마당, KVIC (무료 공공 API)
                                   │                 └─ data/: 시드 카탈로그, 시나리오 스냅샷
                                   └─ 실행 저장: results/<run_id>/ (기존 방식)
Streamlit(app.py) ─ 내부 검증용으로 그대로 유지
```

원칙: **기존 flat 모듈은 이동·재작성하지 않고 import만 한다**(CLAUDE.md). 신규 코드는 새 디렉터리에만 둔다.

```
funding/
  schema.py        # Pydantic: CompanyProfile, Backer, FundingOption, Evidence, MatchResult, ConsultMemo
  connectors/      # bizinfo.py, kvic.py  (httpx, MockTransport 테스트, 키는 .env)
  catalog.py       # 시드 + 커넥터 결과 병합, 펀드명·운용사명 검색
  roles.py         # 기관 역할 분류: 투자 주도 / 투자 참여 / 대출 / 보증  (원문 근거 문장 필수)
  matcher.py       # 규칙 기반 대조: 용도·업력·지역·접수상태 / 분야·단계·유사사례 → 맞는 이유·확인할 점·제외 사유
  memo.py          # Liner Model: 후보별 첫 상담 질문·준비자료 생성(근거 인용)
  scenarios.py     # 라이너 A/B/C 고정 스냅샷 로드
  flow.py          # 실행 흐름 + 진행 이벤트
api/               # FastAPI: main.py, jobs.py(프로세스 내 백그라운드), store.py
web/               # Next.js(App Router, TypeScript, Tailwind)
data/catalog_seed.json, data/scenarios/{a_2020,b_2022,c_2026}.json
tests/test_funding_*.py
```

### 실행 흐름(실시간 조사 1회)
1. 기업 프로필: Liner Search(공식 발표·보도) → 원문 확인 → Model 추출(사업 분야, 최근 라운드, 기관별 **역할**).
2. 후보 수집: 기업마당(금융 분야) + KVIC(모태 자펀드) + 시드 카탈로그 + Liner Search(은행 상품·보증 제도·운용사 사례).
3. 조건 추출: Model이 대상·용도·기간·분야와 **근거 문장**을 JSON으로 추출. 원문에 없으면 `자료 확보 불가`.
4. 대조: 규칙 기반. **점수·확률은 만들지 않고** "맞는 이유 / 추가 확인할 점 / 제외 사유"를 낸다. 우선순위에 따라 레인 순서와 질문 세트가 바뀐다.
5. 상담 메모: 저장한 후보 2~3곳의 공식 문의처·첫 질문·준비자료·출처.

호출 한도는 기존 값 유지(검색 ≤50, Model ≤6, Agent ≤1, Deep Research 미사용). Model 6회 배분: 프로필 / 대출·보증 / 정책자금 / 펀드·운용사 / 대조 설명 / 상담 메모.

### 시연 안정성: 고정 스냅샷 + 실시간 실행 병행
실시간 조사는 3~5분이 걸린다(기존 실측 246초). 시연과 영상은 **검수한 스냅샷**(시나리오 A/B/C)을 즉시 로드하고, 임의 기업 입력은 SSE로 진행 과정을 보여주는 실시간 실행으로 제공한다. 스냅샷에는 생성 일시·호출 기록·출처·확인일을 그대로 담아 "미리 조사해 고정한 결과"임을 화면에 표시한다.

### 반드시 지킬 판단 규칙(제품의 차별점이자 검증 항목)
- **투자 참여 ≠ 대출 거래.** 은행이 투자사로 등장한 문장에 대출 이력을 붙이지 않는다(IBK·KDB 사례).
- **운용사 ≠ 펀드.** 개별 조합이 출처에서 확인될 때만 펀드에 연결한다.
- **약정액 ≠ 기업당 투자금.** 범위가 없으면 "투자금액 범위 미공개 · 분야 일치"로 표기.
- **기존 투자자는 신규 후보로 추천하지 않는다.** 후속 투자·소개 요청 대상으로 분리.
- **마감 공고 제외**, 제외된 후보는 사유와 함께 보여준다.
- 과거 시점(A·B) 시나리오의 후보는 **현재(2026) 카탈로그 기준**임을 표시하고, 당시 실제 결과는 "실제 조달 결과 열기"로 분리한다. 서로 정의가 다른 지표(MAU vs 누적 사용자)는 하나의 그래프로 잇지 않는다.

| 화면 | 핵심 요소 |
|---|---|
| ① 시작 | "라이너로 체험하기" 시점 카드 3장(A 해외 사용자 증가 / B 투자와 대출 조합 / C 해외 기업 고객) + 문장형 입력(지역·업력·업종·용도·금액 칩) |

| ③ 조달 경로 비교 | 두 레인(**빌리기** 대출·보증·정책자금 / **투자받기** 펀드·운용사), 우선순위 토글, 후보 카드(맞는 이유 · 확인할 점 · 근거 보기), 제외 후보, 역할 배지 |
| ④ 상담 메모 | 후보별 문의처·첫 질문·준비자료·출처. A4 인쇄 레이아웃, Markdown 복사 |
| B 전용 | "110억 원 중 투자금은?" 질문 → 원문 하이라이트로 역할 분류 공개 → "실제 조달 결과 열기" |

디자인 방향: 금융 문서의 신뢰감. 밝은 종이색 배경 + 잉크색 본문 + 포인트 1색, Pretendard. 상태는 색이 아닌 **배지 문구**(확인됨 / 추가 확인 / 출처 충돌 / 미공개)로 구분하고 점수·퍼센트·게이지는 쓰지 않는다. 우선순위 토글 시 카드 재정렬 애니메이션이 유일한 강조 모션. 모든 수치 옆에 출처·확인일을 여는 "근거 보기" 서랍.
