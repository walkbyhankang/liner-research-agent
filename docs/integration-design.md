# 성장노트 설계 (초안)

> 2026-11-22 작성. 코드 수정 전 설계 문서다. Streamlit 통합 기업분석(`app.py`, `research/`)과 펀딩노트(`web/`, `api/`, `funding/`)를 하나로 합쳐 **성장노트**를 만든다.

## 0. 정해진 것

| 항목 | 결정 |
|---|---|
| 화면 | Next.js (`web/`) |
| 서버 | FastAPI (`api/`) |
| 기조 | 통합 회사분석. 우리 회사를 객관적으로 분석하고, 그 결과로 받을 수 있는 자금, 심사 준비, 필요하면 판로까지 잇는다 |
| 특허 | 기본 분석에 넣는다 |
| 나라장터 | 판로 단계에 넣는다 |
| 서비스 이름 | **성장노트** (같은 이름의 서비스는 웹 검색 2회로 찾지 못함. 상표 등록 여부는 확인 안 함) |
| 값의 상태와 출처 | 상태(얼마나 확인됐나)와 출처(어디서 왔나)를 따로 표시한다. "공식"이라는 상태는 두지 않는다 (3.8절) |
| 호출 상한 | 전체 합산 상한 하나(지금 60회) 대신 API별·단락별·하루 단위로 나눈다. 초기값은 6.4절 제안값으로 확정 |
| 경쟁사 | 국내 기업으로 한정한다. 해외 기업은 보여 주지 않는다 (4.1절) |
| 공공 API 값 | `CLAUDE.md`의 `confirmed` 정의에 "공공 API 원자료"를 더했다 (2026-11-22) |
| 단계 | 시제품(PoC) 단계를 두지 않는다. 실제 사이트로 바로 공개하고 그곳에서 고치고 더한다 (10절) |
| 화면 원칙 | 꼭 필요한 정보만 압축해 먼저 보여 주고, 나머지는 줄이거나 없앤다. 자세한 내용은 사용자가 누르거나 펼칠 때 보여 준다. 긴 글을 한 번에 늘어놓지 않는다. 바탕은 흰색으로, 전문 정보를 다루는 사이트의 분위기 (3.8절) |
| 팀원 코드 | 제출할 때 `research/`, `app.py`, `app_legacy.py`와 팀원이 공용 파일에 더한 부분이 지워질 수 있다. 그래서 성장노트가 쓰는 기능은 모두 FastAPI 쪽 성장노트 코드로 옮긴다. 성장노트 코드는 `research/`를 불러오지 않는다 (6.1절) |
| Liner 크레딧 | 2026-11-22 잔액 $1.20(팀 공유). 유료 호출은 꼭 필요할 때만 하고, 잔액이 떨어지면 실제 호출 검증은 빼고 "확인 못 함"으로 남긴다 |
| 진행 방식 | 이 세션이 오케스트레이터, 개발은 Opus·xhigh 서브에이전트가 병렬로 한다. 디자인은 `frontend-design`(1단계) 뒤 `impeccable`(2단계), 두 단계는 겹치지 않게 나눈다 |
| 기준 기업 | 실측·테스트의 기준 기업은 **기준 기업** |
| Streamlit | 지우지 않고 참고용으로 남긴다. 앞으로 실행은 성장노트만 한다 |
| Liner 유료 호출 | 실측과 테스트에 쓰도록 승인됨 (2026-11-22) |

## 1. 문제 정의와 사용자

**문제 정의**: 흩어진 공공·민간 자료로 우리 회사를 객관적으로 분석하고, 그 분석을 근거로 받을 수 있는 자금, 심사 준비, 판로 개척까지 바로 잇는다.

- 주 사용자: 자금 조달과 판로를 준비하는 중소·벤처기업 대표, 재무 담당자.
- 같은 흐름을 쓰는 사용자: 여러 회사를 돕는 지원기관 담당자, 액셀러레이터 심사역. 회사명만 바꿔 쓴다. 사용자별 모드는 만들지 않는다.
- 차별점: 분석 보고서로 끝나지 않고, 분석 단락마다 다음 행동(자금 후보, 공고문 대조, 운용사, 입찰공고)으로 이어진다. 점수나 선정 확률은 만들지 않는다.

## 2. 정보 구조와 흐름

```
시작 ─▶ 회사 확정 ─▶ 회사 분석 (중심 화면, 보고서)
         (수 초)        개요 · 재무·고용 · 투자 · 최근 동향 · 기술 · 경쟁사
                                     │ 분석 값이 그대로 넘어감
                ┌────────────────────┼────────────────────┐
                ▼                    ▼                    ▼
            자금 조달             심사 준비                판로
         정책자금·운용사       공고문 자격 대조       나라장터 입찰공고
                               운용사 요약          기업마당 내수·수출 지원사업
                               미팅 근거 묶음
                └────────────────────┴────────────────────┘
                                     ▼
                              노트 (공유·인쇄)
```

- 상단 메뉴: **회사 분석 · 자금 조달 · 심사 준비 · 판로 · 노트** (+ 사례).
- 처음에는 위 순서로 안내하고, 회사가 확정된 뒤에는 어느 화면이든 바로 간다.
- 자금 조달은 회사 분석이 다 끝나기를 기다리지 않는다. 지역·업력·업종·기업 유형이 확인되면(공식 자료, 실측 6.7~9.4초) 바로 열린다.

### 주소(라우트)

| 주소 | 화면 | 지금 있는 것과의 관계 |
|---|---|---|
| `/` | 시작 | 지금의 자금 찾기 첫 화면을 바꾼다 |
| `/c/[id]` | 회사 분석 | 새로 만든다. `id`는 법인등록번호, 법인이 없으면 이름 기반 값 |
| `/c/[id]/funding` | 자금 조달 | 지금 `Finder`를 옮긴다 |
| `/c/[id]/review` | 심사 준비 | `NoticeCheck`, `GpBrief`, `RivalCompare`를 모은다 |
| `/c/[id]/sales` | 판로 | 새로 만든다 |
| `/c/[id]/note` | 노트 | 사례 화면의 상담 메모 부품(`Workspace`의 `Memo`)을 실제 데이터로 쓴다 |
| `/funding` | 회사 없이 자금만 둘러보기 | 지금 자금 찾기 그대로 |
| `/cases`, `/s/[id]` | 사례 | 그대로 둔다. 노트가 생기면 "예시 회사 노트"로 바꿀지 다시 정한다 |

## 3. 화면 설계

### 3.1 시작

```
┌──────────────────────────────────────────────────────────────┐
│ 성장노트                                          사례 보기 │
├──────────────────────────────────────────────────────────────┤
│  우리 회사를 객관적으로 분석하고,                               │
│  받을 수 있는 자금·심사 준비·판로까지 잇습니다                   │
│                                                              │
│  [ 회사 이름 ____________________ ]  [ 분석 시작 ]             │
│    홈페이지(선택) ______________                              │
│                                                              │
│  예시 회사로 보기 · 회사 없이 자금만 둘러보기                    │
│                                                              │
│  쓰는 자료: 금융위원회 · 국민연금 · 기업마당 · 한국벤처투자       │
│            · 나라장터 · 특허 공개 원문 · 뉴스 · Liner             │
└──────────────────────────────────────────────────────────────┘
```

- 최근에 분석한 회사가 있으면 입력란 아래에 "이어서 보기"로 보여 준다(브라우저 저장).
- 예시 회사는 지금처럼 저장해 둔 결과 파일이 있을 때만 보인다.

### 3.2 회사 확정

```
"뤼튼"으로 찾은 법인 (금융위원회 기업기본정보)
┌────────────────────────────────────────────────────┐
│ ● 주식회사 ○○○○                                     │
│   대표 ○○○ · 설립 2021-04-13 · 서울 강남구 …          │
├────────────────────────────────────────────────────┤
│ ○ (다른 동명·유사 상호 후보)                          │
├────────────────────────────────────────────────────┤
│ ○ 목록에 없음 (법인 전이거나 이름이 다름)               │
│   → 공개자료만으로 분석합니다. 공식 재무·고용은 없습니다 │
└────────────────────────────────────────────────────┘
                                        [ 이 회사로 분석 ]
```

- 후보가 하나이고 이름이 정확히 같으면 이 화면을 건너뛰고 바로 분석으로 간다.
- 법인등록번호로 확정하면 뒤의 모든 조회(재무, 국민연금, 캐시)가 같은 회사를 본다.

### 3.3 회사 분석 (중심 화면)

```
┌ 회사 표시줄 ──────────────────────────────────────────────────────────┐
│ ○○○○ · 서울 · 업력 4년 · 벤처                    [값 고치기] [다시 분석] │
├ 회사 분석 ● ─ 자금 조달 ○ ─ 심사 준비 ○ ─ 판로 ○ ─ 노트 ○ ────────────┤
├────────────┬─────────────────────────────────────────────────────────┤
│ 목차        │ 핵심 값                                                  │
│ 개요     ✓  │  설립 ○○○○-○○ [원문 확인·금융위]  지역 ○○ [원문 확인·금융위]    │
│ 재무·고용 ✓  │  매출(2022, 별도) ○○억원 [원문 확인·금융위 재무]              │
│            │  국민연금 가입자 ○○명 [참고·국민연금]                          │
│ 투자     …  │  투자 라운드 ○건 [보도·PDL]   국내 특허 ○건 [원문 확인·특허 원문] │
│ 최근 동향 …  │  이 값으로 자금 후보를 찾을 수 있습니다  [자금 조달 보기 →]    │
│ 기술     …  │ ───────────────────────────────────────────────         │
│ 경쟁사      │ ■ 개요       사업·제품·핵심 기술, 출처 n건                    │
│            │ ■ 재무·고용   [막대: 매출·영업이익 3년] [선: 가입자 12개월]     │
│            │ ■ 투자       라운드 표 · 투자기관 · 관련 법인(따로 표시)         │
│            │ ■ 최근 동향   중요 사건 · 기사 목록(접기)                      │
│            │ ■ 기술       특허(연도 추이·주요 특허) · 논문 [분석하기 ▸]      │
│            │ ■ 경쟁사     후보 5곳 [맞음/아님/추가] · [깊이 비교하기 ▸]       │
└────────────┴─────────────────────────────────────────────────────────┘
```

- 단락마다 상태를 표시한다: 확인 중 / 완료 / 미확보(사유). 공식 자료가 먼저 나오고 나머지는 준비되는 대로 채운다.
- 단락 끝에 "이어지는 곳"을 둔다(5절 표). 예: 특허 단락 끝에 "기술 요건이 있는 공고에서 근거로 씁니다 → 심사 준비".
- 휴대폰 폭에서는 목차를 위쪽 가로 탭으로 바꾼다.

| 단락 | 내용 | 기본/열 때 |
|---|---|---|
| 개요 | 사업 설명, 제품·서비스, 핵심 기술, 대표, 주소, 동명 법인 후보 | 기본 |
| 재무·고용 | 최근 3개 사업연도 재무(표·막대), 국민연금 12개월(선, 신규 취득·상실) | 기본 |
| 투자 | 투자 라운드·금액·투자기관, 누적 투자액(통화별), 관련 법인 카드(따로) | 기본 |
| 최근 동향 | 최근 12개월 중요 사건 요약, 기사 목록(분류 필터, 중복 묶음) | 기본 |
| 기술 · 특허 | 출원인이 확인된 국내 특허 수, 출원연도 추이, 주요 특허 목록, 언급만 된 특허(따로) | **기본** |
| 기술 · 논문 | 분야별 발표 추이, 주요 연구기관, 회사가 직접 참여한 논문, 논문 요약 | 열 때 |
| 경쟁사 · 후보 | 국내 경쟁사 후보 이름과 관계, 사용자가 확정 | 기본 |
| 경쟁사 · 깊은 비교 | 확정한 경쟁사의 재무·고용·투자·특허 비교, 누적 투자 비교, 경쟁사 요약 | 열 때 |

### 3.4 자금 조달

지금 자금 찾기(`Finder`)를 옮긴다. 바뀌는 점만 적는다.

```
자금 조달                       회사 분석 값으로 채움: 서울 · 벤처 · AI·딥테크  [바꾸기]
┌ 빌리는 돈 (융자·보증·지원사업) ─────────┐ ┌ 투자받는 돈 (모태펀드 운용사) ──────────┐
│ 공고 카드: 맞는 점 / 확인할 점 / 마감    │ │ 운용사 카드                              │
│ [회사 사업과 관련] 표시                  │ │ [기존 투자자] [경쟁사에 투자] 표시         │
│ [심사 준비로 담기]                      │ │ [운용사 요약] [심사 준비로 담기]           │
└────────────────────────────────────────┘ └────────────────────────────────────────┘
```

- 조건(지역, 기업 유형, 관심 투자 분야)을 회사 분석 값으로 미리 채운다. 사용자가 바꿀 수 있다.
- "회사 사업과 관련": 회사 분석의 기술 키워드가 공고 제목·요약·태그에 있으면 표시한다(`research/gov.py`의 `match_programs` 규칙). 정렬에만 쓰고 공고를 빼지 않는다.
- "경쟁사에 투자": 경쟁사 깊은 비교를 했을 때만 나온다. 안 했으면 "경쟁사 투자 운용사를 보려면 경쟁사 깊은 비교를 실행하세요"를 보여 준다.
- "저장"은 "심사 준비로 담기"로 바꾼다. 담은 항목이 심사 준비와 노트로 이어진다.

### 3.5 심사 준비

```
심사 준비                                                  [정책자금] [투자]
── 정책자금 ──────────────────────────────────────────────────────────
 담은 공고 3건
 ┌ ○○ 정책자금 융자 ─────────────────────────────────────────────┐
 │ [공고문으로 자격 대조]  → 조건별 충족 / 미충족 / 확인 필요           │
 │   근거 문장(공고문 원문) · 회사 값(출처) · 기관에 물을 질문          │
 │ [경쟁사 조건이라면?]                                              │
 └──────────────────────────────────────────────────────────────┘
 부족한 요건 모음: 담은 공고 전체에서 '미충족'과 '확인 필요'만 모아 보기
── 투자 ─────────────────────────────────────────────────────────────
 담은 운용사 2곳 → [운용사 요약] 투자 분야·단계, 맞닿는 점, 물어볼 것
 미팅 근거 묶음: 재무·고용 추이 · 투자 이력 · 특허 · 최근 성과(중요 사건)
                 항목마다 출처·기준일. 인쇄하면 한 장
```

- 공고문 자격 대조는 지금 기능 그대로 쓴다. 회사 값이 공식 자료로 바뀌어 근거가 단단해진다.
- 특허 수와 국민연금 가입자 수는 회사 값의 메모(`notes`)로 대조에 넘긴다. 국민연금 가입자 수는 "상시근로자 수"와 다르다는 설명을 붙인다.
- 미팅 근거 묶음은 회사 분석에서 이미 받은 결과만 쓴다(추가 호출 없음). 점수나 투자 가능성은 쓰지 않는다.

### 3.6 판로

```
판로
── 공공 조달 입찰공고 (나라장터, 최근 28일) ─────────────────────────────
```

### 3.7 노트

- 한 장 요약: 회사 핵심 값(출처·기준일) → 담은 자금 후보와 대조 결과 → 운용사 요약 → 판로 후보 → 다음 할 일(기관에 물을 질문, 준비할 자료).
- 공유: 주소 복사(지금 자금 찾기의 저장·공유 방식을 넓힌다), 인쇄(인쇄용 스타일 이미 있음).
- 회사 정보는 지금처럼 브라우저에 저장한다. 분석 결과는 서버 캐시에 있다(4.4절).

### 3.8 공통 요소

- **압축과 펼치기**(사용자 지시): 화면마다 결정에 필요한 몇 가지(핵심 값, 한 줄 요약, 건수)만 먼저 보여 준다. 기사 목록, 특허 목록, 근거 문장, 출처 목록, 재무 표 같은 긴 내용은 접어 두고, 누르거나 터치하면 펼친다. 같은 내용을 두 번 보여 주지 않고, 꼭 필요하지 않은 단락은 없애거나 줄인다.
- **바탕**: 흰색을 기본으로 해 전문 정보를 다루는 사이트 분위기를 낸다.
- **회사 표시줄**: 모든 화면 위쪽. 회사명, 지역, 업력, 기업 유형, [값 고치기].
- **상태와 출처를 따로 표시한다.** 상태는 "얼마나 확인됐나", 출처는 "어디서 왔나"다. 값마다 둘 다 붙인다.
  - 출처 표기 형식: `기관·자료 이름 (자료 종류) · 기준일`. 예: `금융위원회 기업기본정보 (공공 API) · 2026-11 조회`, `금융위원회 요약재무제표 (공공 API) · 2022 사업연도 · 별도`, `○○일보 기사 (원문 확인) · 2026-03-02`, `People Data Labs 회사 카드 (Liner Premium)`.
  - 공공 API 값의 상태는 "원문 확인"으로 둔다. 기관이 낸 원자료를 그대로 받은 값이라서다. 출처에 공공 API라고 적혀 있으니 웹 원문 확인과 구별된다.
- **상태 표시**(두 앱 공통으로 통일, 6종):

  | 표시 | 뜻 | 자동으로 채우는가 |
  |---|---|---|
  | 원문 확인 | 원문 본문 또는 공공 API 원자료에서 값을 확인함 (`confirmed`) | 예 |
  | 보도 | 보도·자료·투자 DB에 적혀 있으나 원문 본문으로 확인하지 않음 (`reported`) | 예 |
  | 추정 | 모델 판단이나 간접 근거 (`inferred`) | 아니요 |
  | 엇갈림 | 출처끼리 값이 다름 (`conflicting`). 하나를 고르지 않고 둘 다 보여 줌 | 아니요 |
  | 미확보 | 자료를 얻지 못함. 사유 표시 | — |
  | 참고 | 대체 지표 (예: 국민연금 가입자 수는 직원 수와 다름) | 아니요 |

- **값 고치기**: 사용자가 고친 값은 "직접 입력"으로 표시하고, 다시 분석해도 덮어쓰지 않는다.
- **진행 표시**: 단락별 "확인 중 · 경과 초". 전체를 막는 대기 화면은 쓰지 않는다.
- **비용 안내**: "열 때 실행" 단추 옆에 예상 시간을 적는다. 노트 아래에 "이 분석에 쓴 Liner 호출 n회"를 적는다.
- **차트**: 재무(막대), 국민연금(선), 누적 투자(막대, 통화별로 나눔), 특허·논문 연도(선). 작은 SVG 부품 4개를 직접 만든다(새 라이브러리 없이, 인쇄에도 그대로 나옴).

## 4. 데이터 원칙

### 4.1 값마다 출처 하나로

| 값 | 우선 출처 | 다음 출처 | 엇갈리면 |
|---|---|---|---|
| 상호·대표·설립일·주소 | 금융위 기업기본정보 | 웹 조사(펀딩노트 엔진) | 공공 API 값을 쓰고 웹 값은 "엇갈림"으로 나란히 |
| 지역 | 금융위 주소에서 시·도 | 웹 조사의 본사 소재지 | 같음 |
| 업종 | 금융위 업종 + 웹 조사의 주요 사업 | — | 둘 다 표시 |
| 매출 | 금융위 요약재무제표(최근 연도, 연결 우선, 기준 표시) | 웹 조사 | 같음 |
| 직원 수 | 웹 조사의 직원 수 | 국민연금 가입자 수는 "참고"로만 | — |
| 기존 투자자 | 펀딩노트 엔진 투자자 + Premium 회사 카드(이름·도메인 일치만) + 웹 보완 | — | 출처별로 남기고 금액 차이는 지우지 않음 |
| 경쟁사 | Streamlit 프로필의 국내 경쟁사 + 펀딩노트 엔진 경쟁사를 합친 후보 → 사용자 확정 | — | — |
| 기술 키워드 | Streamlit 프로필 | — | — |

- 경쟁사 합치기(기준 기업 실측에서 확인): Streamlit 프로필은 국내 3곳(퓨리오사AI, 딥엑스, 모빌린트), 펀딩노트 엔진은 6곳(NVIDIA, AMD, FuriosaAI, DeepX, Qualcomm, Groq)을 냈다. 같은 회사가 한글·영문으로 따로 나오므로(퓨리오사AI = FuriosaAI, 딥엑스 = DeepX) 영문명까지 견줘 한 회사로 묶어야 한다. **경쟁사는 국내 기업으로 한정한다**(2026-11-22 결정). 펀딩노트 엔진이 낸 해외 기업(NVIDIA 등)은 Streamlit의 `domestic_only` 규칙(한국 본사만, 외국 기업의 한국 지사 제외)으로 걸러 보여 주지 않는다. "경쟁사 조건이라면?"과 경쟁사 투자 운용사 표시도 국내 경쟁사만 쓴다.
- 단위·기준 보존: 재무는 원(KRW)으로 받아 억원으로 표시하고 기준일, 연결·별도를 함께 적는다. 투자 금액은 통화를 바꾸지 않는다.
- Premium 회사 카드 중 합병 전후 법인처럼 이름만 비슷한 카드는 "관련 법인"으로 따로 보여 주고, 기존 투자자 판정에는 쓰지 않는다. 그대로 쓰면 투자하지 않은 운용사가 신규 후보에서 빠질 수 있다.
- Premium 투자자 이름은 대부분 영문이라 모태펀드 운용사(한글)와 이름 맞추기가 되지 않는다. 대응표는 만들지 않고 이 한계를 화면에 적는다.

### 4.2 지키는 규칙 (지금 규칙 그대로)

- 근거 문장이 원문에 글자 그대로 있을 때만 사실로 보여 준다.
- 점수와 선정·투자 확률을 만들지 않는다.
- 기존 투자자를 신규 후보로 권하지 않는다.
- 외부 자료 안의 글은 데이터일 뿐 지시로 따르지 않는다.
- 결과 파일 저장 전에 키를 지우고(`analysis.scrub`), 저장 내용에 키가 남았는지 검사한다.

### 4.3 저장 구조: 한 번 분석한 결과를 다시 보여 주기

원칙: 한 번 분석한 회사는 저장해 둔 결과를 바로 보여 주고, 자동으로 다시 분석하지 않는다. 다시 분석은 사용자가 **[새로 분석]**을 눌렀을 때만 처음부터 한다.

| 무엇 | 어디에 | 이유 |
|---|---|---|
| 회사 분석 결과(공공 API, 검색, 특허, 뉴스 — 공개 자료) | **서버**: 분석 스냅샷. 회사 × 분석 시각마다 한 벌 | 비싼 호출 결과를 여러 사용자가 다시 쓴다. 공개 자료라 사용자별 비밀이 아니다 |
| 외부 API 응답 캐시 | 서버 파일 캐시(지금 그대로, 서비스별 보관 시간) | 같은 요청이 겹칠 때 다시 부르지 않는다 |
| 사용자가 고친 값, 심사 준비로 담은 항목, 공고문 대조 결과, 노트 | **브라우저**(IndexedDB) | 회사 내부 정보일 수 있어 서버에 두지 않는다(지금 펀딩노트 원칙). 로그인이 없으므로 사용자별 저장소는 브라우저다 |
| 최근 본 회사 목록, 마지막 스냅샷 사본 | **브라우저**(IndexedDB) | 다시 열 때 서버를 거치지 않고 바로 보여 준다 |
| 쿠키 | 쓰지 않는다 | 한 개당 약 4KB 한도이고 모든 요청에 실려 간다. 분석 결과를 담을 수 없다 |

- **브라우저 저장소는 IndexedDB를 쓴다.** localStorage는 출처(사이트)당 약 5MB이고 처리가 동기식이라, 회사 몇 곳이면 찬다. 기준 기업 결과는 약 730KB이고 그중 뉴스 기사 목록이 571KB(693건, 건당 약 0.8KB)다.
- 브라우저 사본에는 뉴스를 줄여 넣는다(중요 사건 요약 + 최근 기사 상위 일부). 전체 기사 목록은 서버 스냅샷에서 필요할 때 받는다.
- 브라우저 저장은 지워질 수 있다(사용자가 사이트 데이터 삭제, 시크릿 창). 그래도 서버 스냅샷이 있어 회사 분석은 다시 볼 수 있다. 사용자가 고친 값과 노트만 사라질 수 있으므로, 노트 화면에 "파일로 내보내기"를 둔다.

**동작**

1. **처음 분석**: 서버 작업 → 단락별 결과 → 서버 스냅샷 저장 → 브라우저에 사본 저장.
2. **다시 열기**(같은 브라우저): 브라우저 사본을 바로 보여 주고 "2026-11-22 20:44 분석"처럼 분석 시각을 표시한다.
3. **다른 사람이 같은 회사를 열 때**: 서버에 스냅샷이 있으면 그것을 보여 주고 분석 시각을 표시한다. 분석한 지 30일이 넘었으면 "오래된 분석입니다"를 함께 보여 준다(자동으로 다시 분석하지는 않음).
4. **[새로 분석]**: 확인 창에 예상 시간과 호출 수(기본 분석 약 2분 30초, Liner 약 19회)를 보여 준 뒤, 서버 캐시를 건너뛰고 처음부터 분석한다. 새 스냅샷을 만들고 이전 스냅샷은 지우지 않는다(전과 비교할 수 있게).
5. **단락만 새로**: 뉴스처럼 자주 바뀌는 단락은 그 단락만 [새로 분석]할 수 있게 한다.
6. 사용자가 고친 값은 스냅샷 위에 "직접 입력"으로 덮어 보여 주고, 새 스냅샷이 와도 그대로 둔다.

- 비용 보호: 같은 회사의 [새로 분석]은 하루 횟수를 제한한다(6.4절 하루 상한과 별도).
- 스냅샷 저장 전 키 지우기·누출 검사는 지금 규칙 그대로다. 뉴스 발췌 같은 제3자 글은 제목·짧은 발췌·링크만 보여 준다.

## 6. 서버 설계 (FastAPI)

### 6.1 구조

- 지금 `api/main.py`에 분석 작업을 붙인다. 작업 묶음이 커지므로 `api/analysis.py`로 나눈다.
- 제출할 때 `research/`가 지워질 수 있으므로, 성장노트가 쓰는 `research/`의 기능(공공 API 수집, 프로필, 뉴스, 특허, 논문, 투자 이력, 나라장터, 국내 경쟁사 거르기)은 성장노트 서버 패키지로 옮겨 온다. 성장노트 코드는 `research/`를 불러오지 않는다. 팀원이 공용 파일(`liner_client.py`, `config.py`)에 더한 학술 검색도 지워질 수 있다고 보고, 필요한 부분은 성장노트 패키지 안에 둔다.
- `funding/`(펀딩노트 코드)와 기존 엔진(`pipeline.py` 등)은 그대로 불러 쓴다. `research/controller.run`(한 번에 전체 실행)은 쓰지 않는다.

### 6.2 엔드포인트

| 엔드포인트 | 하는 일 | 유료 |
|---|---|---|
| `GET /api/corp/search?name=` | 금융위 법인 후보 | 없음 |
| `POST /api/analysis` `{name, crno?, homepage?}` | 분석 작업 시작, 기본 단락 실행 → `{jobId, companyId}` (202) | 기본 분석 |
| `GET /api/analysis/{jobId}` | 단락별 상태·결과 `{sections: {key: {status, stage, seconds, result, error}}, paid}` | 없음 |
| `POST /api/analysis/{jobId}/sections/{key}` | 열 때 실행 단락 시작(`papers`, `rivals_deep`, `sales`) | 단락별 |
| `POST /api/notice/analyze` | 공고문 자격 대조 | 지금 그대로 |
| `POST /api/gp/brief` | 운용사 요약 | 지금 그대로 |
| `GET /api/health` | 서버 상태, 유료 호출 사용량 | 없음 |

### 6.4 호출 상한과 서비스별 호출 정책

지금 펀딩노트 서버는 모든 유료 호출을 합쳐 서버 실행당 60회(`FUNDING_MAX_PAID_CALLS`)로 막는다. 호출 종류마다 비용·속도가 크게 다르고, 무료 API에도 제공자 한도가 있어 합산 하나로는 관리할 수 없다. 그래서 세 겹으로 나눈다.

**1겹: 단락별 상한 (분석 한 번 안에서)** — 6.3절 표의 값. 단락마다 따로 `LinerClient`를 만들어 종류별 한도를 건다. 한 단락이 상한에 닿아도 다른 단락은 계속한다.

**2겹: API별 하루 상한 (서버 전체)** — 하루(한국 시간 0시 기준) 사용량을 파일로 남겨 서버를 다시 시작해도 이어서 센다. 상한에 닿으면 그 API를 쓰는 단락만 "오늘 호출 상한 도달"로 미확보 처리한다.

| 서비스 | 호출 종류 | 단가(지금 가격표) | 하루 상한 (초기값, 확정) | 기본 분석 1회 실측 |
|---|---|---|---|---|
| Liner | 웹 검색 | $0.001 | 500회 | 11회 |
| Liner | Premium 검색 | $0.002 | 100회 | 2회 |
| Liner | 모델 | 응답에 따라 다름 | 200회 (하루 금액 상한은 두지 않음, 10.1절) | 6회 |
| Liner | 학술 검색 | 가격표에 없음(확인 필요) | 200회 | 0회 |
| 공공데이터포털 | 금융위 기업기본정보·재무, 국민연금, 나라장터 | 무료 | API마다 제공자 일일 한도 이하 (한도 값 확인 필요) | 28회 (금융위 3, 국민연금 25) |
| NAVER | 뉴스 검색 | 무료 | 제공자 일일 한도 이하 (확인 필요) | 14회 |
| OpenAlex | 논문 | 무료 | 제공자 권장 한도 이하 (확인 필요) | 0회 |
| Google Patents | 공개 원문 | 무료 | 분석당 30쪽, 동시 4 | 30쪽 확인 (캐시에 남은 성공 응답 19건) |

- 하루 상한 값은 기본 분석 실측(19회, 6.5절) 기준으로 약 40번 분석할 수 있게 잡은 초기값이다. 운영하면서 조정한다.
- 모델은 회당 비용 차이가 커서 횟수와 금액을 함께 센다. 응답에 비용이 오는 호출(게이트웨이 Chat Completions)은 그 값을 쓰고, 오지 않는 호출(회사 조회 엔진의 Responses)은 따로 확인이 필요하다(6.5절).

**3겹: 동시 요청 상한** — 지금 값을 그대로 쓴다(`research/common.LIMITS`: 공공데이터포털 6, NAVER 3, OpenAlex 3 / `research/liner.CONCURRENCY`: 검색 4, Premium 3, 학술 4, 모델 3 / 특허 원문 4).

**서비스별 호출 정책** (지금 코드의 값, 한 설정 파일로 모은다)

| 서비스 | 재시도 | 캐시 | 키 |
|---|---|---|---|
| Liner | 524·429·5xx에 최대 1회(Retry-After), 타임아웃은 재시도 안 함 | 24시간 | `LINER_API_KEY` |
| 공공데이터포털 | 5xx·429·네트워크 오류에 1회 | 24시간(나라장터 12시간) | `DATA_GO_KR_SERVICE_KEY` |
| NAVER | 429에 1회 | 6시간 | `NAVER_CLIENT_ID`·`SECRET` |
| OpenAlex | 지금 코드 확인 필요 | 72시간 | `OPENALEX_API_KEY`(선택) |
| Google Patents | robots.txt 준수, 차단·유료 우회 안 함 | 7일 | 없음 |

- 상한과 정책은 한 파일(예: `api/limits.py`)에 표로 두고 환경변수로 덮어쓸 수 있게 한다. `GET /api/health`가 API별 오늘 사용량과 남은 양을 돌려준다.
- 같은 회사를 24시간 안에 다시 열면 캐시를 쓰고 호출하지 않는다. "다시 분석"은 캐시를 무시한다.

## 9. 외부 스킬 활용 (조사 결과, 2026-11-22)

### 9.1 쓰는 방식

| 방식 | 판단 |
|---|---|
| 스킬을 그대로 실행(Claude API Skills, OpenAI 호스팅 셸) | 쓰지 않는다. 공급자 컨테이너가 필요한데, Liner 게이트웨이는 Messages API의 `container`를 400으로 거부하고 코드 실행 도구를 무시한다(Liner 문서 확인) |
| Claude Agent SDK로 파일시스템 스킬 실행 | 보류. Liner의 Anthropic 호환 엔드포인트로 돌아갈 가능성은 있으나 실측하지 않았다. 서버에 에이전트 하위 프로세스와 격리 환경이 필요하다 |
| **스킬 내용(체크리스트·질문 목록·문서 목차·데이터 규칙)을 우리 프롬프트와 화면으로 옮김** | **쓴다.** 순수 Markdown이라 떼어 쓸 수 있다. Apache-2.0은 번역·각색을 허용하며, 저장소에 넣으면 라이선스 사본·출처·변경 고지를 남긴다 |
| 스킬 로더를 직접 구현(이름·설명만 프롬프트에 두고 함수 호출로 본문 제공) | 나중에. 함수 호출만으로 되고 Liner로도 가능하지만, 지금은 옮긴 내용이 몇 개뿐이라 고정 프롬프트로 충분하다 |

openai/plugins의 금융 스킬(public-equity-investing, data-analytics)은 Proprietary 라이선스이거나 ChatGPT 전용 기능에 묶여 있고, 상장사 전용이라 옮기지 않는다.

### 9.2 단계별로 옮길 내용 (anthropics/financial-services)

| 성장노트 단계 | 옮길 내용 (원본 스킬) | 빼는 것 (우리 규칙과 충돌) |
|---|---|---|
| 회사 분석 | 데이터 무결성 규칙: 못 찾은 값은 비우고 표시, 기준일 명시, 기간 섞지 않기, 학습 지식으로 빈칸 채우기 금지 (`tear-sheet`). 비상장사 프로필 4칸: 개요 / 사업 / 재무 / 최근 동향·지분 (`strip-profile`). 경쟁사 비교의 같은 기간 비교·모든 숫자에 출처 규칙 (`competitive-analysis`) | 출처가 엇갈릴 때 순위 높은 출처를 고르는 규칙(우리는 "엇갈림" 유지), 시나리오 확률, 등급 표시, USD 환산 |
| 자금 조달 | 투자 라운드 필드: 발표일, 금액, 리드 투자자, 라운드 종류. 회사 식별 규칙: 자회사는 자체 라운드 없음, 브랜드명과 법인명이 다를 수 있음, 결과 없음 ≠ 활동 없음 (`funding-digest`). 재무적 투자자 표의 열: 펀드 규모, 분야, 최근 활동 (`buyer-list`) | 가능성(Likelihood)·우선순위(A/B/C)·등급 열, 미국 규모 기준($100M 이상) |
| 심사 준비 | 회사 측 실사 대비 자료 목록: 재무, 사업, 법무, 운영, 인사, IT, ESG (`dd-checklist`). 투자 미팅 예상 질문 15~20개 (`dd-meeting-prep`). 기준과 실제를 나란히 두는 대조표 (`deal-screening`). 규칙별 판정·근거 출력 형식과 "승인하지 않는다" 원칙 (`kyc-rules`): 지금 공고문 자격 대조 형식과 같은 틀 | 통과·탈락 판정, 위험 심각도, 투자 추천, IRR, 점수. 미국·EU 규제 항목(GDPR, SOC2 등) |
| 판로 | 해당 스킬 없음. 참고로 전략적 구매자 4분류: 직접 경쟁 / 인접 / 수직통합 고객·공급사 / 플랫폼 (`buyer-list`) | — |
| 노트 | 갱신 기록 형식: 날짜, 자료, 영향받은 근거 (`thesis-tracker`). 숫자 일관성 검사 (`ib-check-deck`). 출처 없는 문장 표시 (`market-researcher`의 `[UNSOURCED]` → 우리 "미확보") | 확신도, 매수·매도, 목표가 |

- 저장소 전체에 한국 공시(DART), K-IFRS, 원화 관련 내용은 없다(조사 에이전트 검색 결과). 미국 공시·세율·금리 전제는 옮기지 않는다.
- 옮길 때는 한국어로 다시 쓰고, 옮긴 파일 머리에 원본 경로와 "변경함" 고지를 적고, 저장소에 Apache-2.0 사본을 둔다. S&P Global(`partner-built/spglobal`) 내용을 옮기면 Kensho 저작권 고지도 남긴다.
