# 기존 Streamlit 프로토타입의 의도와 자금 찾기 접목

> 옛 펀딩노트(자금 찾기) 시절의 기록이다. 지금 서비스는 성장노트이며 `README.md`와 `docs/integration-design.md`를 본다.
>
> 2026-11-21. 루트 저장소의 코드(`app.py`, `pipeline.py`, `categories.py` 등)를 읽고 모의 실행으로 확인한 내용이다.
> 루트와 이 워크트리의 엔진 파일은 내용이 같다. 워크트리에는 `config.py`·`liner_client.py`·`requirements.txt`에 추가분이 있다.

## 1. Streamlit 앱이 하려던 것

**회사명만 넣으면 그 회사를 조사해 주는 도구**다. Liner Search·Search Agent·Model로 기업 정보를 6개 분야로 모으고, 사실마다 출처와 확인 상태를 붙여 보여 준다. 목적은 "Liner API로 기업 정보를 얼마나 정확히 모을 수 있는가"를 검증하는 것이다.

| 단계 | 하는 일 | 함수 |
|---|---|---|
| 검색 계획 | 주제 16개(개요, 재무, 경쟁사, 뉴스, 투자자, 지원사업 등)의 검색어 | `planner.build_search_plan` |
| 검색 | 주제별 Liner Search, 선택적으로 Search Agent 1회 | `pipeline._do_search`, `run_agent` |
| 출처 정리 | URL 병합, 같은 이름의 다른 회사 제외, 출처 신뢰도 | `sources.build_identity`, `build_sources` |
| 원문 확인 | 공개 페이지를 읽어 값이 본문에 있는지 대조 | `fetcher.Fetcher`, `verify_value` |
| 분야별 추출 | 분야마다 Model 1회, JSON으로 사실 추출 | `pipeline.run_models`, `categories.normalize_category` |
| 통합 | 검증 상태 부여, 충돌 표시, 지원사업 적격성 판정 | `pipeline.assemble` |

화면은 탭 8개다: 검색·실행, 기업 개요, 재무·투자, 경쟁사, 뉴스·타임라인, VC·투자자, 정부지원·사업기회, API 성능·품질.

기본 설정 1회 실행은 검색 약 18회, Model 6회, Agent 1회이고 문서상 3~5분이 걸린다.

## 2. 두 작업의 관계

| | Streamlit 프로토타입 | 자금 찾기(이 워크트리) |
|---|---|---|
| 출발점 | 회사명 | 회사 조건 |
| 조사 대상 | 회사 | 공고와 펀드 |
| 지원사업 정보 | 검색으로 찾은 공고 몇 건 | 기업마당 공고 1,303건 전체 |
| 약점 | 공고·펀드 범위가 좁다 | 회사 정보를 사용자가 직접 넣어야 한다 |

서로의 약점을 채운다. 자금 찾기에 없던 "회사 쪽 정보"를 기존 엔진이 만든다.

## 3. 접목한 것

### 가. 회사명으로 회사 정보 채우기
- `funding/profile.py`가 기존 엔진을 **필요한 주제만 골라** 돌린다: 개요(`identity`), 직원·투자(`headcount_funding`), 기존 투자자(`vc_existing`), 경쟁사(`competitors`). 검색 4회, 원문 확인 8쪽, Model 최대 4회.
- 결과를 화면의 회사 정보 형식으로 바꾼다: 설립 연월, 본사 소재지, 주요 사업, 직원 수, 매출, 기존 투자자. 값마다 확인 상태와 출처를 붙인다.
- 화면의 "우리 회사 정보"에서 회사명을 넣고 "공개자료로 채우기"를 누르면 빈칸만 채운다. 이미 적은 값은 바꾸지 않는다.
- 실측("라이너", 홈페이지 힌트 포함): 약 110초. 본사 소재지(원문에서 확인), 직원 수(보도), 설립 2012-09(출처 간 불일치), 기존 투자자 15곳을 얻었다. 매출은 얻지 못했다.

### 나. 기존 투자자를 운용사 목록에 표시
- 조회로 얻은 기존 투자자를 모태펀드 운용사 목록과 대조해 "기존 투자자"로 표시하고 목록 앞에 따로 둔다. 신규 후보가 아니라 후속 투자·소개 요청 대상이다.
- 표기가 다른 이름을 맞춘다: 법인 표기 제거, 대문자 약어의 한글 표기 변환(`KB인베스트먼트` = `케이비인베스트먼트`). `web/lib/finder.ts`의 `gpKey`.

### 다. 경쟁사 분석 (2026-11-21 추가)
- **경쟁사 목록**: 회사 조회에 엔진의 경쟁사 주제(`competitors`)를 더했다. 이름, 관계, 제품, 직원 수, 매출, 투자 유치를 출처와 함께 보여준다.
- **경쟁사가 받은 투자**: `funding/rivals.py`가 경쟁사 상위 3곳의 투자 유치를 검색해 라운드·금액·투자사를 뽑는다. 근거 문장과 투자사 이름이 검색 결과에 실제로 있는 것만 남긴다. 검색 1회, 모델 1회.
- **경쟁사 투자 이력 표시**: 경쟁사에 투자한 곳이 모태펀드 운용사 목록에 있으면 "경쟁사 투자 이력"으로 표시한다. 순서는 바꾸지 않고, 직접 경쟁사의 투자사는 이해충돌로 투자를 피할 수 있다는 안내를 붙인다.
- **경쟁사 조건이라면?**: 공고 자격 대조 결과에서 경쟁사를 골라 같은 공고를 다시 대조한다. 지역·기업 유형·필요 자금은 우리 회사 값을 두고 업종·직원 수·매출·투자 이력만 경쟁사 값으로 바꿔, 경쟁사 수준이면 충족되는 조건(갖추면 열리는 요건)을 보여준다. 공고 조건은 저장본을 쓰므로 추가 호출은 대조 1회다.
- 실측("라이너"): 조회 전체 약 114초(검색 4회 + 1회, 모델 3회 + 1회). 경쟁사 5곳(구글, 오픈AI, 퍼플렉시티 등)과 퍼플렉시티의 투자 5건을 얻었다. 경쟁사가 해외 대기업이라 직원 수·매출이 비어 있었고, 경쟁사 조건 대조에서도 새로 충족되는 조건이 나오지 않았다. 국내 중소 경쟁사가 있는 회사에서 어떻게 나오는지는 확인하지 못했다.
- 한계: 경쟁사가 받은 융자·보증은 찾지 않는다(대부분 비공개). 경쟁사 정보가 비어 있으면 대조 결과에 차이가 드러나지 않는다. 같은 회사를 다시 조회해도 결과가 달라질 수 있다(이번 조회에서는 기존 투자자 분야가 출처 없음으로 건너뛰어졌고, 앞선 조회에서는 15곳이 나왔다).

- **영문 이름 인식과 경쟁사 주제 보정 (추가)**: 기존 엔진은 검색 결과의 제목·발췌에 조회한 회사 이름이 없으면 자료를 버린다. 한글 이름만 알면 영문 자료가 모두 버려져, 업스테이지 조회에서 경쟁사 자료 15건 중 14건이 버려졌다. 두 가지로 보정했다.
  - 검색 결과가 `회사명(English Name)` 꼴로 두 건 이상 짝지어 보여준 영문 이름을 별칭으로 넘긴다(`funding/profile.py`의 `find_aliases`). 라이너는 투자자 자료가 2건에서 8건으로 늘었다.
  - 경쟁사 주제는 회사 이름이 없어도 쓰게 했다. 업스테이지의 경쟁사 자료가 1건에서 15건으로 늘었다. 기존 투자자 주제에는 적용하지 않는다(다른 회사의 투자 기사를 이 회사의 투자자로 읽을 위험).
- **경쟁사별 검색 (추가)**: 경쟁사 세 곳을 한 검색어로 묶으면 자료가 많은 한 곳의 결과만 나와, 경쟁사마다 따로 검색해 합친다. 뤼튼 조회에서 퍼플렉시티에만 몰리던 결과가 라이너 3건, 오픈AI 1건까지 나왔다.
- **경쟁사 규모 조사 (추가)**: 엔진이 낸 경쟁사 기록은 직원 수·매출·투자 칸이 대부분 비어 있어 "경쟁사 조건이라면?"에 넘길 값이 없었다. 경쟁사마다 검색을 한 번 더 해(투자 1회, 규모 1회) 직원 수·매출·누적 투자·설립 시기를 찾는다(`funding/rivals.py`의 `research`, 검색 최대 6회·모델 1회, 뤼튼 실측 약 18초·$0.03).
  - 수치는 근거 문장이 검색 결과에 그대로 있고, 그 자료가 해당 경쟁사를 다루며, 값 전체(숫자·단위·통화)가 근거 문장에 통째로 있을 때만 남긴다. 숫자 조각만 맞추면 "248억 원" 근거로 "24억 원"이나 "248조 원"이 통과하기 때문이다. 공백과 쉼표만 무시하고, 앞뒤로 숫자·단위·통화가 더 이어지는 값(248억 → 248억 5천만, 15억 → 15억 달러)도 받지 않는다. 앞뒤 글자는 모델이 옮긴 인용문이 아니라 원 자료에서 본다(인용문이 금액 중간에서 끊겨 있을 수 있다). 복합 금액의 뒷마디(3억 500만 원 → 500만 원), 통화 기호·코드를 뺀 값(USD 15억 → 15억), 범위의 한쪽 끝(100~200명), 한계 표현(100억 원 미만·이상)도 받지 않는다. 판정은 원문의 띄어쓰기를 기억해서 한다. "시리즈 B2 270억원"의 270억원은 온전한 값이지만 "1270억원"의 270억원은 아니다. 의심스러우면 버리는 쪽이라, 온전한 값이 드물게 버려질 수 있다(예: "300억 2025년"). 기준 시점은 그 자료에 적혀 있을 때만 남긴다. 투자 라운드의 이름·금액·시기도 같은 방식으로 자료와 맞을 때만 남긴다. 기업가치는 받지 않는다.
  - 이렇게 확인한 수치에는 `figuresStatus: reported`와 출처 주소를 붙인다. 엔진이 추정으로 적어 둔 수치는 확인된 수치와 섞이지 않게 지운다. 화면은 경쟁사 기록이 추정이어도 확인된 수치만은 대조에 넘기고, 추정된 사업 내용·관계는 넘기지 않는다.
  - 설립 시기는 연도만 확인되는 경우가 많아 설립 연월 칸이 아니라 메모로 넘긴다(달을 지어내지 않는다).
  - 뤼튼 실측: 라이너는 설립·직원 수·매출·누적 투자가 모두 채워졌고, 퍼플렉시티는 설립·누적 투자, 오픈AI는 투자 라운드만, 업스테이지는 찾지 못했다(엔진이 넘긴 경쟁사는 앞의 세 곳까지만 조사한다). 같은 조사를 다시 돌리면 잡히는 자료가 달라 값이 바뀐다(라이너 누적 투자가 440억 원과 940억 원으로 다르게 나왔다. 기준 시점이 다른 자료다).
  - 한계: "2026년 중소기업 정책자금 융자계획"처럼 업력·체납·부채비율이 조건인 공고에서는 경쟁사 수치를 채워도 새로 충족되는 조건이 나오지 않았다. 매출·고용·투자 유치 실적을 요구하는 공고에서만 차이가 드러난다.

### 라. 공용 부품 재사용
- `LinerClient`의 호출 한도·재시도·호출 기록을 자격 대조와 회사 조회가 함께 쓴다. 게이트웨이 호출용 `chat_json`을 추가했다.
- `analysis.scrub`으로 결과 파일에서 키를 지운다.

## 4. 접목하지 않은 것과 이유

| 기존 기능 | 판단 | 이유 |
|---|---|---|
| 지원사업 적격성 판정(`assess_eligibility`) | 쓰지 않음 | 입력이 숫자 업력 상한과 문자열 제한 3개뿐이고 업종·규모는 비교하지 않는다. 모의 실행에서 소재지가 대전일 때 지역 제한 "전국", "충청권(대전·세종·충남·충북)"을 미충족으로 판정했다. 공고문 근거 기반 대조(`funding/notice.py`)로 대체 |
| 지원사업 검색(`support` 분야) | 쓰지 않음 | 검색으로 찾는 몇 건보다 기업마당 전체 목록이 낫다 |
| 신규 VC 후보 추천 | 쓰지 않음 | 모태펀드 운용사 목록이 근거가 분명하다 |
| 뉴스 분야 | 쓰지 않음 | 자금 찾기에 필요하지 않고 시간이 늘어난다 |
| Streamlit 화면 | 그대로 둠 | 엔진 검증용 내부 도구로 유지 |

## 5. 알아 둘 한계

- **조회 결과는 초안이다.** 엔진의 "원문에서 확인"은 값의 낱말이 본문 어딘가에 있으면 통과한다. 모의 실행에서 "12명"이 "112명"이 든 본문에서 확인됨이 됐다. 그래서 화면은 값을 자동 확정하지 않고 사용자가 확인하게 한다.
- **기업 유형, 벤처확인, 체납, 기존 대출, 정책자금 이용 이력은 엔진이 만들지 못한다.** 자격 대조에서 "확인 필요"로 남는 항목 대부분이 이것이라 직접 입력해야 한다.
- **설립 월이 없으면 연도만 표시한다.** 월을 지어내지 않는다.
- **이름이 같은 다른 회사**는 홈페이지 같은 힌트가 없으면 구분하지 못한다. 화면에는 아직 홈페이지 입력란이 없다(API는 받는다).
- **무명 소기업은 공개자료가 적어 대부분 빈칸일 수 있다.** 실제 조회는 한 회사로만 확인했다.
- **약 2분이 걸리는데 진행 표시가 없다.** "찾는 중" 문구만 나온다.
- 조회에 쓰는 모델은 엔진 기본값(`liner-gpt-router`)이다. 요청마다 모델이 달라질 수 있다.
