# 데모 영상 대본 (초안)

> 라이너 해커톤 제출용. 제한 5분, 목표 길이 **4분 30초**. 작성 2026-11-21.
> 시연 회사는 **뤼튼**이다. 회사 조회는 저장해 둔 실제 결과("예시 회사로 체험")를 쓰고, 공고문 자격 대조와 운용사 요약은 촬영 중에 실제로 호출한다.
> 말하는 문장은 초안이다. 소요 시간은 이 저장소에서 실제로 잰 값이다.

## 영상이 전해야 할 세 가지

1. **문제**: 공고 목록은 이미 있다. 없는 것은 "우리 회사가 되는가"다.
2. **해결**: 공고문을 대신 읽고, 조건마다 근거 문장과 함께 답한다. 모르는 것은 "확인 필요"로 남긴다.
3. **Liner API**: 검색은 Liner Search, 판단은 Liner로 부른 모델, 그 결과는 코드가 원문과 대조한다.

## 촬영 전 준비

| 할 일 | 이유 |
|---|---|
| `scripts/run_local.sh` 실행. 펀딩노트 `http://127.0.0.1:3100`, 기존 프로토타입 `http://127.0.0.1:8501` | 두 화면을 모두 찍는다 |
| 브라우저 창 1280×800 안팎, 확대 100%, 즐겨찾기 막대 숨김 | 첫 화면에 결과 카드 2장이 보이는 크기 |
| `web/public/data/sample-company.json`이 있는지 확인 | 예시 회사 파일은 저장소에 넣지 않는다. 이 파일이 있어야 "예시 회사로 체험" 단추가 나온다. 없으면 회사명 조회를 미리 한 번 해 두고(2분 이상) 그 화면에서 시작한다 |
| "회사 정보 모두 비우기"로 빈 상태에서 시작 | "예시 회사로 체험" 단추는 빈 상태에서만 보인다 |
| 대조할 공고를 **촬영 전에 한 번 대조해 둔다** | 공고문 조건 추출이 서버에 저장돼, 촬영 때는 대조만 돌아 20~25초에 끝난다. 처음이면 40~50초 |
| 공고 카드의 "공고문으로 자격 대조하기" 단추가 눌리는지 확인 | 분석 서버가 꺼져 있으면 단추 대신 "분석 서버가 켜져 있을 때 쓸 수 있습니다"가 보인다 |
| Liner 잔액 확인 | 한 번 촬영에 대조 1~2회, 운용사 요약 1회(합계 약 $0.1~0.2) |

기다리는 구간(대조 20~25초, 요약 약 7초)은 **편집으로 줄이되 화면에 "실제 약 25초"라고 자막을 넣는다.** 속도를 숨기지 않는다.

## 장면

### 1. 문제 (0:00~0:25)
- **화면**: 기업마당 공고 목록 → 공고문 PDF 47쪽을 넘기는 모습(또는 정지 화면 두 장).
- **말**: "자금이 필요한 중소기업 대표는 공고를 찾는 데서 끝나지 않습니다. 접수 중인 공고가 천삼백 건이 넘고, 우리 회사가 대상인지는 공고마다 첨부된 공고문을 읽어야 알 수 있습니다. 이 공고문은 47쪽입니다."
- **자막**: 접수 가능 공고 1,303건(기업마당, 2026-11-21) · 신청기간의 71%는 날짜가 아닌 문구

### 2. 자금 찾기 (0:25~1:05)
- **화면**: 펀딩노트 첫 화면. 지역 "서울", 기업 유형 "창업·벤처기업", 필요한 지원 "융자·보증"을 고른다. 공고 수와 제외된 건수가 바뀌는 것을 보여 준다. 카드 한 장의 "자세히"를 열어 "확인할 점"을 보여 준다. 오른쪽 운용사 목록을 잠깐 비춘다.
- **말**: "펀딩노트는 정책자금 공고와 벤처캐피탈 운용사를 한 화면에 모았습니다. 조건을 고르면 바로 걸러지고, 빠진 공고는 왜 빠졌는지, 남은 공고는 무엇을 확인해야 하는지 보여 줍니다. 여기까지는 공공 데이터만 씁니다. 하지만 업력이나 매출 같은 세부 자격은 여기에 없습니다."
- **주의**: 마감 표시(D-n)가 보이는 카드를 하나 비춘다.

### 3. 회사 정보 (1:05~1:35)
- **화면**: "우리 회사 정보"를 열고 **"예시 회사(뤼튼)로 체험"**을 누른다. 설립일·업종·매출이 채워지고, 조회 결과 상자에 출처 링크와 "원문에서 확인 / 보도·자료 기재" 표시, 기존 투자자 13곳, 경쟁사가 보인다. 운용사 목록 맨 위의 "기존 투자자" 표시를 비춘다.
- **말**: "회사명만 넣으면 공개자료에서 회사 정보를 찾아 출처와 함께 채웁니다. 실제 조회는 2분쯤 걸려서, 영상에서는 오늘 미리 조회해 저장한 결과를 불러왔습니다. 값마다 출처가 붙고, 추정이거나 출처가 엇갈리는 값은 자동으로 채우지 않습니다. 이미 투자한 곳은 운용사 목록에서 신규 후보와 따로 표시됩니다."
- **자막**: 저장된 조회 결과(2026-11-21 조회) · 실제 조회 약 2분
- **화면(이어서)**: "그 밖의 사항"에 `벤처기업 확인, 세금 체납 없음`을 직접 입력한다.
- **말**: "인증이나 체납 여부 같은 내부 정보는 공개자료에 없으니 직접 적습니다. 이 값은 시연을 위한 가정입니다."
- **자막**: 시연 가정 값

### 4. 공고문 자격 대조 (1:35~2:50) — 영상의 중심
- **화면**: 결과 안에서 찾기에 `정책자금 융자계획`을 넣고 "2026년 중소기업 정책자금 융자계획 변경 공고"의 "자세히" → **"공고문으로 자격 대조하기"**. 진행 표시가 도는 모습을 2~3초 보여 주고 결과로 넘어간다.
- **말(기다리는 동안)**: "지금 47쪽 공고문에서 자격 조건을 뽑아, 방금 넣은 회사 정보와 견주고 있습니다."
- **화면**: 종합 판정 "확인 후 판단"과 이유. 조건 목록에서 "충족" 하나와 "확인 필요" 하나(부채비율 등)를 차례로 가리킨다. 리허설에서는 충족 1건, 확인 필요 9건이 나왔다. 조건 아래의 **공고문 근거 문장**을 확대한다. "담당 기관에 물어볼 것" 목록을 보여 준다.
- **말**: "조건마다 충족, 미충족, 확인 필요로 답하고, 공고문의 어느 문장을 근거로 했는지 보여 줍니다. 이 근거 문장은 모델이 쓴 글을 그대로 믿지 않고, 공고문에 글자 그대로 있는지 코드가 확인한 것만 남긴 것입니다. 회사 정보에 없는 것은 추측하지 않고 '확인 필요'로 두고, 대신 담당 기관에 무엇을 물어야 하는지 정리해 줍니다. 선정 확률이나 점수는 만들지 않습니다."
- **자막**: 실제 약 25초 · 조건 추출 `openai/gpt-6.2-sol` · 대조 `anthropic/claude-opus-5.5` · Liner 게이트웨이

### 5. 운용사 요약 (2:50~3:25)
- **화면**: 운용사 목록에서 관심 분야 "창업 초기". "기존 투자자"가 아닌 첫 후보 카드에서 **"대신 검색해 요약하기"**. 확인된 사실 2~3줄과 출처, "우리 회사와 맞닿는 점", "운용사에 확인할 것"을 보여 준다. "웹에서 더 찾기" 링크를 가리킨다.
- **말**: "운용사는 이름만으로는 우리 회사와 맞는지 알 수 없습니다. 대신 검색해서, 검색 결과에 실제로 적힌 사실만 한 줄씩 정리하고 회사와 맞닿는 점을 짚어 줍니다. 더 찾아보고 싶으면 웹 검색으로 바로 이어집니다."
- **자막**: 실제 약 7초 · Liner Search 1회 + 모델 1회

### 6. 경쟁사 (3:25~3:45) — 선택
- **화면**: 조회 결과 상자의 경쟁사 목록(라이너: 설립·직원 수·매출·누적 투자와 "수치 출처")과 "경쟁사가 받은 투자" 목록.
- **말**: "경쟁사가 어떤 투자를 받았는지도 출처와 함께 봅니다. 금액은 숫자와 단위가 자료에 그대로 있을 때만 보여 줍니다."
- **주의**: "경쟁사 조건이라면?" 대조는 **이 공고에서는 차이가 나오지 않는다**(조건이 업력·체납·부채비율이라 매출·직원 수를 바꿔도 같다). 차이가 드러나는 공고를 찾기 전에는 영상에 넣지 않는다. 넣는다면 결과를 그대로 보여 주고 "이 공고는 규모가 기준이 아니어서 차이가 없습니다"라고 말한다.

### 7. 어떻게 만들었나 (3:45~4:15)
- **화면**: 구성도 한 장(직접 만든 그림): `공공 API(기업마당·한국벤처투자) → 목록` / `Liner Search → 검색 결과` / `Liner 모델 → 추출·대조` / `코드 → 근거 문장이 원문에 있는지 확인`. 이어서 기존 Streamlit 프로토타입 화면(`:8501`)을 3~4초 비춘다.
- **말**: "검색은 Liner Search가 하고, 판단은 Liner로 부른 모델이 합니다. 모델에게 검색을 맡기지 않고 코드가 검색한 결과만 주기 때문에, 모델이 낸 사실을 검색 결과와 대조할 수 있습니다. 공고문 추출은 모델 네 종을 같은 공고로 비교해 골랐습니다. 회사 조회는 대회 전에 만든 이 기업분석 프로토타입의 엔진을 다시 썼고, 나머지는 대회 기간에 새로 만들었습니다."
- **자막**: 기존: 기업분석 엔진(Streamlit) · 신규: 펀딩노트 화면·분석 서버·공고문 대조·운용사 요약

### 8. 한계와 다음 (4:15~4:30)
- **화면**: 펀딩노트 첫 화면으로 돌아와 "저장한 항목" 보기 → "목록 복사해서 공유".
- **말**: "아직 회사 조회는 2분이 걸리고, 표가 많은 공고문은 근거가 일부만 잡힙니다. 다음은 세부 자금이 여러 개인 공고에서 회사에 맞는 자금을 먼저 고르는 것입니다. 펀딩노트는 공고를 찾아 주는 데서 멈추지 않고, 우리 회사가 되는지를 근거와 함께 답합니다."

## 촬영 중 문제가 생기면

| 상황 | 대응 |
|---|---|
| 자격 대조가 실패하거나 1분 넘게 걸린다 | 다시 누른다(추출은 저장돼 있어 대조만 다시 돈다). 계속 실패하면 준비 때 대조해 둔 화면을 따로 찍어 둔 것으로 대체하고 자막에 "사전 촬영"이라고 쓴다 |
| 대조 결과가 준비 때와 다르다 | 대조는 실행마다 문장이 조금 달라진다. 판정(충족·확인 필요)이 같으면 그대로 쓴다 |
| 운용사 요약에 "찾지 못했습니다"가 나온다 | 다른 운용사로 다시 한다. 검색 결과에 근거가 없으면 비워 두는 것이 정상 동작이다 |
| "분석 서버가 켜져 있을 때 쓸 수 있습니다"가 보인다 | `scripts/run_local.sh`를 다시 실행하고 화면을 새로 고친다 |
| 유료 호출 상한(서버 실행당 60회)에 닿았다 | 분석 서버를 다시 시작하면 횟수가 초기화된다 |

## 말하지 않을 것

- 줄어드는 시간이나 비용의 수치. 재 본 적이 없다.
- 선정 가능성, 투자 가능성. 서비스가 판단하지 않는다.
- "모든 공고", "정확하다" 같은 표현. 목록은 공공 API가 주는 범위이고, 세부 자격은 대조를 실행한 공고만 확인된다.

- [ ] 가정 값과 저장된 결과에 자막을 넣었는지
