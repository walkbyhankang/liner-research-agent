## 1. 한 줄 소개

**성장노트는 회사 이름 하나로 공공 자료와 공개 보도를 모아 우리 회사를 객관적으로 분석하고, 그 분석을 근거로 받을 수 있는 자금, 심사 준비, 판로까지 잇는 서비스다.** 값마다 확인 상태와 출처를 붙이고, 점수나 확률은 만들지 않는다.

## 2. 문제 정의

### 누구의 어떤 일인가

자금이 필요한 중소·벤처기업 대표나 재무 담당자는 다음 일을 따로따로 한다.

1. **우리 회사를 정리한다.** 재무, 고용, 투자 이력, 특허, 최근 기사를 기관과 사이트마다 찾아 모은다.
2. **맞는 자금을 찾는다.** 기업마당, 벤처투자 관련 사이트를 오가며 공고와 운용사를 찾는다.
3. **자격을 확인한다.** 공고문(PDF·HWP)을 내려받아 우리 회사가 대상인지 읽는다. 운용사마다 무엇에 투자하는지 검색한다.
4. **판로를 찾는다.** 입찰공고와 판로 지원사업을 따로 찾는다.

1번에서 모은 값이 2~4번의 근거인데, 지금은 이 값이 한 곳에 없다. 목록은 이미 공공 사이트에 있지만 **"우리 회사가 되는가"와 그 근거는 목록에 없다.** 같은 흐름을 여러 회사를 돕는 지원기관 담당자나 액셀러레이터 심사역도 쓴다.

### 데이터로 확인한 것

| 확인한 사실 | 의미 | 출처 |
|---|---|---|

| 신청기간의 71%(923건)가 날짜가 아니라 "예산 소진시까지", "상시 접수" 같은 문구 | 목록만으로는 지금 신청할 수 있는지 모른다 | 같음 |

| 기준 기업 설립일이 자료끼리 다르다(금융위 2022-01-04, 웹 조사 2020-09) | 자료끼리 값이 다를 수 있어, 하나를 골라 보여 주면 틀릴 수 있다 | 예시 분석 (2026-11-23 확인), `docs/integration-design.md` 6.5 |
| 국민연금 가입자 수는 직원 수와 같지 않다 | 대신 볼 수 있는 값과 그 값 자체를 구분해야 한다 | `docs/integration-design.md` 3.8 |

### 확인하지 못한 것

- **실제 경영자를 대상으로 한 검증은 하지 않았다.** 위 문제 정의는 데이터와 팀의 판단에 근거한다.
- 사람이 같은 일을 하는 데 걸리는 시간을 재지 않았으므로, **줄어드는 시간이나 비용을 수치로 주장하지 않는다.** 잰 것은 서비스 쪽 소요 시간과 호출 수뿐이다(6절).

## 3. 해결 방법

### 화면별 기능

| 화면 | 사용자가 얻는 것 | 유료 호출 |
|---|---|---|
| **회사 확정** | 회사 이름으로 금융위원회 법인 후보를 보여 주고(대표·설립일·본사), 사용자가 고른다. 이름이 같은 후보가 여럿이면 사업자번호·건물까지 나온 주소·이전 이름(법인등록번호로 이름 이력을 한 번 더 조회)을 더 보인다. 고른 법인의 자료만 쓴다. 법인이 없으면 공개 자료만으로 분석한다 | 없음 |
| **회사 분석** | 핵심 값 4칸(매출, 국민연금 가입자, 누적 투자, 검색으로 확인한 특허)과 그 아래 **"지금 확인할 것"**(엇갈린 값, 미확보 값, 14일 안 마감인 담은 공고, 미충족 요건의 개수. 누르면 그 자리로 간다), 5개 단락(개요, 재무·고용, 투자, 최근 동향, 기술). 단락은 도착하는 대로 채우고, 값마다 상태와 출처를 붙인다. 자료끼리 다른 값은 둘 다 보여 준다. 긴 내용은 접어 두고 누를 때 펼친다. 논문 동향은 누를 때만 실행한다 | 분석 시작, 새로 분석, 열 때 실행 |
| **경쟁사 분석** | 심사역이 회사 다음으로 보는 것. 회사 분석이 찾은 경쟁사 후보 가운데 비교 대상(최대 5곳)을 "포함/제외"로 정하고(목록에 없으면 "경쟁사 직접 추가"), 누를 때만 비교 대상의 법인·재무·국민연금·투자·특허·최근 기사를 받아 **우리 회사와 같은 항목으로 나란히** 놓는다(매출(사업연도·연결/별도), 국민연금 가입자, 누적 투자, 검색으로 확인한 특허, 최근 라운드, 주요 투자자, 설립). 칸마다 기준·상태·출처를 붙이고 없는 값은 "미확보"와 사유. 표 아래에는 출처와 따로 항목별 한계(사업연도가 회사마다 다를 수 있음, 국민연금 가입자는 직원 수와 다름, 특허는 검색으로 확인한 건수라 전체 보유 수가 아님 등)를 둔다. 점수·순위·우열 판정은 만들지 않는다. 경쟁사별 사업·제품·최근 변화, 경쟁사에 투자한 투자기관(자금·판로 "경쟁사에 투자" 표시와 이어짐) | 비교 자료 받기(누를 때만) |
| **자금·판로** | 분석 값으로 조건을 채워 세 갈래를 거른다: 빌리는 돈(정책자금 공고), 투자받는 돈(모태펀드 운용사), 판로(회사 기술 낱말로 찾은 나라장터 입찰공고 최근 28일, 기업마당 판로 지원사업 내수·수출). 빠진 이유와 확인할 점을 보여 준다. 기업 유형은 근거가 없어 사용자가 한 번 고른다. 이미 투자한 운용사는 따로 묶는다. 회사 기술 낱말이 들어간 공고에는 "회사 사업과 관련"을 붙인다. 두 갈래에 함께 나오는 수출 공고는 담기 상태가 하나다 | 없음(나라장터 조회는 무료) |
| **심사 준비** | 담은 공고의 공고문으로 자격을 대조해 조건마다 충족·미충족·확인 필요와 근거 문장, 기관에 물어볼 것을 준다. 부족한 요건만 모아 본다. 담은 운용사를 대신 검색해 확인되는 사실·맞닿는 점·물어볼 것을 정리한다. 투자 미팅 근거 묶음(회사 분석 결과만 씀), 예상 질문 19개, 실사 대비 자료 26개 | 자격 대조, 운용사 요약 |
| **노트** | 회사 핵심 값(출처·기준일), 담은 자금 후보와 대조 결과, 운용사, 판로 후보, 다음 할 일을 한 장으로. 인쇄·PDF 저장, 텍스트 복사, 파일로 내보내기 | 없음 |

### 지키는 원칙

자금 정보는 틀리면 사용자가 시간을 잃는다. 그래서 **모르는 것을 아는 것처럼 보이지 않게 하는 것**을 제품의 중심에 뒀다.

- **근거 없는 값은 만들지 않는다.** 자료를 얻지 못하면 "미확보"와 사유를 보여 준다.
- **근거 문장과 금액은 원문에 글자 그대로 있을 때만 남긴다.** 모델이 만든 근거는 코드가 원문과 대조해 버린다.
- **자료끼리 다르면 하나를 고르지 않는다.** "엇갈림"으로 두 값을 나란히 보여 준다. 연결·별도, 통화, 단위, 기준일을 바꾸지 않는다.
- **점수와 선정·투자 확률을 만들지 않는다.** 대신 충족·미충족·확인 필요와 그 근거를 준다.
- **상태와 출처를 따로 붙인다.** 상태(원문 확인 / 보도 / 추정 / 엇갈림 / 미확보 / 참고)는 얼마나 확인됐는지, 출처(기관·자료 이름·기준일)는 어디서 왔는지다.
- **추정 값은 자동으로 채우지 않는다.** 기존 투자자를 신규 후보로 권하지 않는다.

## 4. 사용 흐름 (예시 회사: 기준 기업)

1. 시작 화면에 "기준 기업"을 넣는다. 회사 확정 화면에 "기준 기업" 법인이 둘 나온다. 대표와 시군구는 같고 설립일·사업자번호·건물 주소가 다르며, 지금 법인에는 이전 이름(2024-12 변경)이 붙는다. 지금 법인을 고른다.
2. 회사 분석이 단락별로 채워진다. 실측으로 공식 자료 약 12초, 개요 약 10초, 투자·특허·뉴스 30초 안, 원문 확인 사실과 기존 투자자(`facts`) 약 176초다. 고른 법인에는 금융위 재무가 없어 재무는 "미확보"와 사유가, 국민연금 가입자는 12개월 추이가 "참고"로 보인다. "지금 확인할 것"에 엇갈림 값 1개(설립)와 미확보 값이 모인다. 값을 누르면 출처와 기준일이 열린다.
3. 경쟁사 분석에서 경쟁사 후보 가운데 비교 대상을 정하고("포함/제외"), 서버에 저장해 둔 비교 자료로 우리 회사와 경쟁사의 매출·국민연금 가입자·투자·특허를 같은 항목으로 나란히 본다. 재무 자료가 없는 경쟁사 칸은 "미확보"와 사유로 남는다.
4. 자금·판로에서 기업 유형을 고르면(업력과 투자 라운드가 있으면 "창업·벤처기업으로 보입니다(추정)"를 옆에 보이되 사용자가 눌러야 적용) 공고와 운용사가 나온다. 이미 투자한 운용사는 따로 묶여 있다. 공고 하나와 운용사 하나를 담는다.
5. 같은 화면의 판로 갈래에서 회사 기술 낱말로 찾은 나라장터 입찰공고와 판로 지원사업을 본다(무료).
6. 심사 준비에서 담은 공고의 "공고문으로 자격 대조"를 누른다. 조건별 판정, 공고문 근거 문장, 기관에 물어볼 것이 나온다. 담은 운용사의 "운용사 요약"을 누른다.
7. 노트에서 한 장 요약을 인쇄하거나 PDF로 저장한다.

시연은 서버에 저장해 둔 기준 기업 분석("예시 회사")으로 한다. 실제 기업의 분석 결과라 저장소에는 넣지 않는다.

## 5. Liner API 활용

### 어디에 무엇을 쓰는가

| Liner 기능 | 쓰는 곳 | 기본 분석 1회 실측 |
|---|---|---|
| 웹 검색(`include_knowledge=false`) | 개요 자료(3회), 원문 확인 사실 조사(4회), 뉴스 보완(2회), 특허 후보 찾기(`site:patents.google.com`, 2회), 투자 이력 웹 보완(라운드가 3건 미만일 때), 운용사 요약, 경쟁사 깊이 비교 | 11회 |
| Premium 검색(`include_knowledge=true`) | 투자 라운드·투자기관(People Data Labs 회사 카드), 경쟁사 깊이 비교 | 2회 |
| 모델(게이트웨이 Chat Completions) | `openai/gpt-6.2-sol`: 개요·경쟁사 후보·기술 낱말 정리, 중요 사건 요약, 투자 이력 보완, 논문 요약, 운용사 요약, 공고문 조건 추출. `anthropic/claude-opus-5.5`: 공고문과 회사 값 대조 | 6회(아래 Responses 포함) |
| 모델(Responses, `liner-gpt-router`) | 원문 확인 사실(`facts`): 해커톤 이전 기업분석 엔진의 분야별 사실 추출 | (위에 포함, 4회) |
| 학술 검색 | 논문 동향(누를 때만)의 추가 논문 | 0회 |

- 기준 기업 기본 분석(합친 서버, 캐시 없음, 1회): 약 178초, Liner 요청 19회, 크레딧 잔액 차이 $0.26(잔액은 팀 공유). 이어서 같은 이름의 다른 법인을 분석했을 때는 캐시가 있어 Liner 11회, $0.19.
- 공고문 자격 대조(2026-11-21 실측, `docs/notice-analysis-results.md`): 조건 추출 7~16초·$0.02~0.09, 회사 대조 22~25초·약 $0.05. 추출은 공고마다 한 번만 하고 서버에 저장한다. 조건은 회사와 상관없으므로 모든 사용자가 같은 결과를 쓴다.
- 운용사 요약: 검색 1회와 모델 1회, 약 7초(2026-11-21 실측).

### 왜 이렇게 나눴는가

- **검색은 Liner 검색, 판단은 모델.** 모델에게 검색을 맡기지 않고 코드가 검색한 뒤 그 결과만 모델에 준다. 그래야 모델이 낸 사실을 검색 결과와 대조할 수 있다.
- **모델의 답을 그대로 믿지 않는다.** 모든 추출은 JSON 스키마로 받고, 근거 문장이 원문(공고문, 검색 결과, 웹 원문)에 있는지 코드가 확인한다. 금액은 숫자·단위·통화까지 통째로 원문에 있어야 통과한다.
- **분석을 단락으로 나눠 기다림을 줄였다.** 단락마다 따로 상한을 두고 병렬로 돌려, 오래 걸리는 단락(`facts`) 하나가 다른 단락을 막지 않는다.
- **비싼 호출은 누를 때만.** 논문 동향(학술 검색 최대 12회)과 경쟁사 깊이 비교(경쟁사 5곳이면 최대 34회)는 기본 분석에 넣지 않았다.

### 모델을 비교해 골랐다

공고 3건에 모델 4종을 같은 지시로 돌렸다(`docs/notice-analysis-results.md`).

| 모델 | 근거 확인(3건 합계) | 지연 | 관찰 |
|---|---|---|---|
| `openai/gpt-6.2-sol` | 48/48 | 7~16초 | 세부 자금별 업력 구분까지 추출. **추출에 채택** |
| `liner-mark` | 48/48 | 16~19초 | 위와 비슷한 수준, 비용은 더 낮음(계산값) |
| `anthropic/claude-opus-5.5` | 47/48 | 20~22초 | 자격 조건 중심. **대조에 채택** |
| `anthropic/claude-haiku-5.5` | 53/53 | 7~9초 | 47쪽 공고에서 업력·업종 조건을 빠뜨림 |

이 과제에서는 Liner 자체 모델(`liner-mark`)이 프런티어 모델에 뒤지지 않았다. 공고 3건, 한 가지 과제의 결과라 일반화할 수는 없다. 지금 코드로 다시 비교했을 때 품질은 비슷했고 `liner-mark`가 5~14초 느려, 사용자가 기다리는 화면이라 `openai/gpt-6.2-sol`을 유지했다(2026-11-23 최종 결정).

### 기존 엔진과 팀원 작업의 재사용

- 원문 확인 사실과 기존 투자자(`facts`)는 해커톤 이전에 만든 기업분석 엔진(검색 계획 → 원문 확인 → 추출 → 출처 신뢰도)을 그대로 쓴다. 엔진의 동작은 바꾸지 않았다.
- 재무·고용, 뉴스, 특허, 논문, 투자 이력, 나라장터 수집은 팀원이 해커톤 기간에 만든 통합 분석 프로토타입(커밋 `98d8c6c`)을 성장노트 서버(`growth/`)로 옮겨 고쳤다. 프로토타입 화면과 모듈은 옮긴 뒤 제출 저장소에서 지웠다.

- 여섯 화면(회사 확정, 회사 분석, 경쟁사 분석, 자금·판로(판로 갈래 포함), 심사 준비, 노트)과 회사 없이 자금 둘러보기가 실제 공공 API와 실제 Liner 호출로 동작한다. 가상 데이터가 들어 있던 펀딩노트의 사례 화면은 지웠다.

### 안전장치

- API 키는 서버의 `.env`에만 두고 화면·로그·결과 파일에 남기지 않는다. 분석 결과 저장 전에 키를 지우고 남았는지 검사한다.
- 유료 호출에 세 겹 상한을 둔다: 단락별 상한, API별 하루 상한(서버를 다시 시작해도 이어 셈), 동시 요청 상한. 같은 회사 새로 분석은 하루 3회, 접속 주소별 요청은 분당 6회까지.
- 웹 원문·특허 원문·공고문을 받는 모듈은 내부망 주소로 가는 요청을 막는다(리다이렉트마다 다시 검사). 두 서버는 이 컴퓨터(`127.0.0.1`)에만 열고, 팀에게는 화면 서버만 Tailscale Serve로 tailnet 안에 연다(초대받은 사람만 접속). Serve는 접속자가 보낸 `x-forwarded-for`를 버리고 실제 기기 주소로 바꿔 넘겨, 요청 제한을 머리글로 속일 수 없다(실제 요청으로 확인).
- 사용자가 고친 값, 담은 항목, 노트는 브라우저에만 저장한다. 서버로 가는 회사 값은 공고문 대조·운용사 요약 요청뿐이다.
- 외부 문서(공고문, 검색 결과, 웹 원문) 안의 지시문은 따르지 않도록 모델 지시에 적었다.

## 7. 확장성·임팩트

- **자료가 공공 API라 유지 비용이 낮다.** 공고·운용사 스냅샷은 수집 스크립트로 다시 받는다.
- **비용이 사용자 수보다 회사 수에 따른다.** 회사 분석은 서버에 저장해 여러 사용자가 다시 쓰고, 공고문 추출은 공고당 한 번이다. 사용자마다 드는 것은 공고문 대조와 운용사 요약이다.
- **같은 구조를 다른 지원 분야로 넓힐 수 있다.** 기업마당에는 금융 외에 기술 222건, 수출 138건, 인력 155건 등이 있고, 공고문에서 조건을 뽑아 대조하는 방식은 그대로 쓴다. 판로 지원사업은 이미 같은 대조로 이어진다.
- **쓸 수 있는 주체**: 자금을 찾는 기업, 여러 회사를 돕는 지원기관·액셀러레이터, 여신·투자 담당자의 사전 검토. 회사 이름만 바꿔 같은 흐름을 쓴다.
- **다음 단계**: 세부 자금이 여러 개인 공고에서 회사에 맞는 자금을 먼저 고르는 2단계 추출, 표가 많은 공고문의 표 구조 보존, 운용사 연락 창구 정보, 새 공고 알림, 배포와 사용자 인증.

## 9. 한계

숨기지 않고 적는다.

- **분석은 약 3분 걸리고 실행할 때마다 결과가 달라질 수 있다.** 화면의 예상 안내(2분 30초 안팎)는 기준 기업 실측(약 178초)보다 짧다.
- **같은 이름의 법인 자료를 합치지 않는다.** 기준 기업 지금 법인을 고르면 공식 재무는 "미확보"다(재무는 옛 법인에만 있다).
- **자금·판로 목록은 공공 API의 분류값으로만 거른다.** 세부 자격은 공고문 자격 대조로 확인한다.
- **경쟁사 조건 대조는 공고에 따라 차이가 드러나지 않는다.** 업력·체납·부채비율이 조건인 공고에서는 경쟁사의 매출·직원 수를 넣어도 결과가 같았다.
- **운용사 요약은 검색 결과의 제목과 발췌만 읽는다.** 한국벤처투자 데이터에는 기업당 투자 금액이 없어 금액을 쓰지 않는다. 투자자 이름이 영문인 자료는 운용사와 맞춰 보지 못할 수 있다.
- **표가 많은 공고문은 표 구조가 풀려 근거 문장이 일부만 잡힌다.**
- **특허·논문은 검색으로 확인된 범위다.** 나라장터는 최근 28일, 공고명 낱말 일치만 본다.
- **확인하지 못한 것**: 원문 확인 사실 단계의 모델(Responses) 회당 비용, 무료 API 제공자 하루 한도, 논문 동향·경쟁사 깊이 비교의 실제 시간과 비용, 금융위 API가 개인사업자를 다루는지.
- **실제 사용자 검증은 하지 않았다.**
- 배포하지 않았다. 로컬 실행과 영상으로 제출한다. 로그인이 없어, 비용 보호는 호출 상한과 요청 제한뿐이다.
