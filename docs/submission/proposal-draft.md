## 1. 한 줄 소개

**펀딩노트는 중소·벤처기업이 받을 수 있는 정책자금 공고와 접촉할 벤처캐피탈 운용사를 한곳에서 찾고, 공고문을 대신 읽어 우리 회사 조건과 맞는지 근거 문장과 함께 알려 주는 서비스다.**

## 2. 문제 정의

### 누구의 어떤 일인가
자금이 필요한 중소·벤처기업 대표나 재무 담당자는 다음 일을 직접 한다.

1. 기업마당, 벤처투자 관련 사이트, 기관별 공고 게시판을 오가며 공고와 운용사를 찾는다.
2. 공고마다 첨부된 공고문(PDF·HWP)을 내려받아 우리 회사가 대상인지 읽어 본다.
3. 운용사마다 무엇에 투자하는지 검색해 본다.

시간이 드는 곳은 1번이 아니라 2번과 3번이다. 목록은 이미 공공 사이트에 있지만, **"우리 회사가 되는가"는 목록에 없다.**

### 데이터로 확인한 것
공공 API를 실제로 받아 확인했다(2026-11-21, `docs/public-data-notes.md`).

| 확인한 사실 | 의미 |
|---|---|
| 기업마당에 접수 가능한 공고가 1,303건, 그중 금융 분야가 226건(융자 163, 보증 47 등) | 사람이 하나씩 열어 보기에는 많다 |
| 신청기간의 71%(923건)가 날짜가 아니라 "예산 소진시까지", "상시 접수" 같은 문구 | 목록만으로는 지금 신청할 수 있는지 알 수 없다 |
| 업력·업종·매출·한도·금리 같은 세부 자격은 API에 구조화돼 있지 않고 첨부 공고문에만 있다 | 자격 확인은 결국 공고문을 읽어야 한다 |
| 한국모태펀드 자펀드 1,480개 중 만기 전 761개를 운용사 279곳이 운용. 기업당 투자금액, 투자 단계, 연락처는 없다 | 운용사 이름만으로는 우리 회사와 맞는지 알 수 없다 |
| 중소기업 정책자금 융자계획 공고문은 47쪽(41,165자) | 한 건을 읽는 데도 시간이 든다 |

### 확인하지 못한 것
- **실제 경영자를 대상으로 한 검증은 하지 않았다.** 위 문제 정의는 데이터와 팀의 판단에 근거한다. 사람이 공고 한 건의 자격을 직접 확인하는 데 걸리는 시간도 재지 않았으므로, "시간이 얼마나 줄어드는가"는 이 문서에서 주장하지 않는다.
- 줄어드는 시간을 수치로 주장하지 않는다. 측정한 것은 서비스 쪽 소요 시간뿐이다(5절).

## 3. 해결 방법

| 기능 | 사용자가 얻는 것 |
|---|---|
| **자금 찾기** | 지역·기업 유형·지원 종류를 고르면 공고와 운용사가 함께 나온다. 빠진 공고는 왜 빠졌는지(다른 지역, 대상 아님 등), 남은 공고는 무엇을 확인해야 하는지 보여 준다. 마감까지 남은 날, 저장, 주소 공유 |
| **공고문 자격 대조** | 공고문(PDF·HWPX)을 읽어 자격 조건을 뽑고, 우리 회사 정보와 견줘 조건마다 충족·미충족·확인 필요로 답한다. 조건마다 공고문의 근거 문장을 붙이고, 담당 기관에 물어볼 질문을 만든다 |
| **회사명으로 채우기** | 회사명만 넣으면 공개자료에서 설립일·사업·매출·기존 투자자·경쟁사를 찾아 출처와 함께 보여 주고 빈칸을 채운다. 기존 투자자는 운용사 목록에서 신규 후보와 따로 표시한다 |
| **운용사 요약** | 운용사를 대신 검색해, 확인되는 사실(투자 분야·단계 등)과 우리 회사와 맞닿는 점, 운용사에 물어볼 것을 한 줄씩 정리한다 |
| **경쟁사 조건이라면?** | 같은 공고를 경쟁사 조건으로 다시 대조해, 지금은 안 되지만 갖추면 열리는 요건을 보여 준다 |

### 지키는 원칙
자금 정보는 틀리면 사용자가 시간을 잃는다. 그래서 **모르는 것을 아는 것처럼 보이지 않게 하는 것**을 제품의 중심에 뒀다.

- **근거 문장이 원문에 글자 그대로 있을 때만 사실로 보여 준다.** 모델이 만든 근거는 코드가 원문과 대조해 버린다.
- **점수와 선정 확률을 만들지 않는다.** 대신 충족·미충족·확인 필요와 그 이유를 준다.
- **회사 정보에 없는 것은 추측하지 않고 "확인 필요"로 남긴다.**
- **출처가 엇갈리거나 추정인 값은 자동으로 채우지 않는다.** 화면에는 보여 주되 "추정", "출처 간 불일치"로 표시한다.
- **기존 투자자를 신규 후보로 권하지 않는다.**

## 4. 사용 흐름

서울의 AI 스타트업 대표가 운전자금을 찾는 경우(영상의 흐름과 같다).

1. 지역 "서울", 기업 유형 "벤처", 필요한 지원 "융자·보증"을 고른다. 공고와 운용사 목록이 바로 나온다.
2. "우리 회사 정보"에 회사명을 넣고 "공개자료로 채우기"를 누른다. 설립일·사업·매출이 출처와 함께 채워진다. (조회 결과를 파일로 저장해 두면 "예시 회사로 체험" 단추로 바로 불러올 수 있다. 시연은 이 방법으로 한다. 실제 기업의 조회 결과라 그 파일은 저장소에 넣지 않았다.)
3. 관심 있는 공고에서 "공고문으로 자격 대조하기"를 누른다. 조건별 판정과 근거 문장, 기관에 물어볼 질문이 나온다.
4. 운용사 목록에서 기존 투자자를 제외한 후보를 보고 "대신 검색해 요약하기"를 누른다.
5. 관심 항목을 저장하고 목록을 복사해 팀에 공유한다.

## 5. Liner API 활용

### 어디에 무엇을 쓰는가
| 기능 | Liner Search API | Liner 모델 호출(게이트웨이) | 실측 |
|---|---|---|---|
| 공고문 자격 대조 | 쓰지 않음(공고문은 기업마당이 준 주소에서 직접 받는다) | 조건 추출 1회(`openai/gpt-6.2-sol`), 회사 대조 1회(`anthropic/claude-opus-5.5`) | 추출 7~16초·$0.02~0.09, 대조 22~25초·약 $0.05 (`docs/notice-analysis-results.md`) |
| 회사명으로 채우기 | 주제별 검색 최대 4회 + 경쟁사별 검색 최대 6회 | 주제별 추출 최대 4회 + 경쟁사 조사 1회 | 뤼튼 133초(경쟁사 규모 조사를 넣기 전). 경쟁사 조사는 18~33초·약 $0.03 추가 |
| 운용사 요약 | 운용사 검색 1회 | 요약·대조 1회 | 약 7초 |

- 추출은 공고당 한 번만 하고 저장한다. 조건은 회사와 무관하므로 모든 사용자가 같은 결과를 쓰고, 비용이 공고 수에만 비례한다.
- 서버 실행당 유료 호출 횟수에 상한을 두고(기본 60회), 재시도까지 감안해 미리 예약한다.

### 왜 이렇게 나눴는가
- **검색은 Liner Search, 판단은 모델.** 모델에게 검색을 맡기지 않고 코드가 검색을 실행한 뒤 그 결과만 모델에 준다. 그래야 모델이 낸 사실을 검색 결과와 대조할 수 있다.
- **모델의 답을 그대로 믿지 않는다.** 모든 추출은 JSON 스키마로 받고, 근거 문장이 원문(공고문 또는 검색 결과)에 있는지 코드가 확인한다. 금액은 숫자·단위·통화까지 통째로 원문에 있어야 통과한다.
- **단계를 나눠 호출 한 번을 짧게 유지한다.** 가장 느린 호출도 25초였다.

### 모델을 비교해 골랐다
공고 3건에 모델 4종을 같은 지시로 돌렸다(`docs/notice-analysis-results.md`).

| 모델 | 근거 확인(3건 합계) | 지연 | 관찰 |
|---|---|---|---|
| `openai/gpt-6.2-sol` | 48/48 | 7~16초 | 세부 자금별 업력 구분까지 추출. **추출에 채택** |
| `liner-mark` | 48/48 | 16~19초 | 위와 비슷한 수준, 비용은 더 낮음(계산값) |
| `anthropic/claude-opus-5.5` | 47/48 | 20~22초 | 자격 조건 중심. **대조에 채택** |
| `anthropic/claude-haiku-5.5` | 53/53 | 7~9초 | 47쪽 공고에서 업력·업종 조건을 빠뜨림 |

이 과제에서는 Liner 자체 모델(`liner-mark`)이 프런티어 모델에 뒤지지 않았다. 공고 3건, 한 가지 과제의 결과라 일반화할 수는 없다.

**추출 모델은 `openai/gpt-6.2-sol`을 쓴다.** 지금 코드로 공고 3건을 `liner-mark`로 다시 뽑아 비교했다(2026-11-21, `docs/notice-analysis-results.md`의 "다시 비교").

| | `openai/gpt-6.2-sol` | `liner-mark`(응답 모델 `liner-mark-1.3`) |
|---|---|---|
| 걸린 시간 | 6.6 / 15.7 / 15.8초 | 20.9 / 19.3 / 20.5초 |
| 근거가 확인된 조건 | 15 / 16 / 16 | 13 / 16 / 16 |
| 근거가 원문에 없어 버린 조건 | 1 / 0 / 0 | 3 / 0 / 0 |
| 비용 | $0.028 / $0.014 / $0.088(응답 값) | 응답에 비용이 없다 |

품질은 비슷했고 고른 조건이 달랐다. 47쪽 공고에서 `liner-mark`는 예외 조항과 세부 자금별 업력을 더 담았고, 소상공인·우량기업·부채비율 제외 조건은 뺐다. 사용자가 기다리는 화면이라 더 빠른 쪽을 골랐다. `[확인 필요: liner-mark 전환 여부 최종 결정. 바꾸면 Liner 자체 모델을 핵심 경로에 쓰게 되지만 공고 첫 분석이 5~14초 길어진다]`

### 기존 Liner API 엔진의 재사용
회사명으로 채우기는 해커톤 이전에 만든 기업분석 엔진(검색 계획 → 원문 확인 → 추출 → 출처 신뢰도 판정)에서 필요한 주제만 골라 실행한다. 엔진 코드는 고치지 않았다(`docs/streamlit-intent-and-integration.md`).

## 6. 완성도

### 동작하는 범위
- 다섯 기능이 모두 실제 데이터와 실제 Liner 호출로 동작한다. 별도의 "라이너 사례" 체험 화면에는 가상 펀드가 들어 있고, 화면에 "(가상)"으로 표시돼 있다.
- 공공 데이터는 수집 스크립트로 스냅샷을 만들어 저장소에 넣었다. 분석 서버 없이도 자금 찾기는 동작한다.
- 실행: `scripts/run_local.sh` 한 번으로 화면과 분석 서버가 뜬다.

### 검증
| 항목 | 내용 |
|---|---|
| 자동 테스트 | Python 148개, JavaScript 41개. 실제 API를 호출하지 않는다 |
| 실제 호출 확인 | 공고 3건 × 모델 4종 비교, 뤼튼·라이너·업스테이지 회사 조회, 운용사 요약 |
| 브라우저 측정 | 경영자 시나리오 4개를 실제 브라우저로 재현. 첫 결과 카드 위치(데스크톱 749px → 514px), 모바일에서 누르는 요소 높이(46개 중 33개 미달 → 0개), 12px 미만 글자(70곳 → 0곳) 등 (`docs/ux-checklist.md`) |
| 독립 코드 리뷰 | 변경마다 별도 모델의 리뷰를 거쳤다. 지적은 주로 "불확실한 값을 사실처럼 보이게 하는 경로"였고 모두 반영했다 |

### 안전장치
- API 키는 `.env`에만 두고 화면·로그·결과 파일에 남기지 않는다. 결과 저장 전 마스킹과 누출 검사를 거친다.
- 회사 정보는 사용자의 브라우저에만 저장되고, 조회나 대조를 실행할 때만 분석 서버로 간다.
- 외부 문서(공고문, 검색 결과) 안의 지시문은 따르지 않도록 모델 지시에 명시했다.
- 공고문은 기업마당 주소에서만 받는다(임의 주소 요청 차단).

## 7. 확장성·임팩트

- **데이터가 공공 API라 유지 비용이 낮다.** 수집 스크립트를 하루 한 번 돌리면 최신 상태가 된다.
- **비용 구조가 사용자 수에 덜 민감하다.** 공고문 추출은 공고당 한 번이고, 사용자마다 드는 것은 대조 한 번(약 $0.05)이다.
- **같은 구조를 다른 지원 분야로 넓힐 수 있다.** 기업마당에는 금융 외에 기술 222건, 수출 138건, 인력 155건 등이 있고, 공고문에서 조건을 뽑아 대조하는 방식은 그대로 쓸 수 있다.
- **쓸 수 있는 주체**: 자금을 찾는 기업, 기업을 상담하는 지원기관·액셀러레이터, 여신·투자 담당자의 사전 검토.
- 다음 단계: 47쪽짜리 공고처럼 세부 자금이 여러 개인 경우 회사에 맞는 자금을 먼저 고르는 2단계 추출, 표가 많은 공고문의 표 구조 보존, 운용사 연락 창구 정보, 새 공고 알림.

|---|---|
| 기존(해커톤 이전) | 회사명으로 기업 정보를 수집·검증하는 Streamlit 프로토타입과 그 엔진(`app.py`, `pipeline.py` 등). 변경 없음 |
| 기존 파일에 추가 | `liner_client.py`에 게이트웨이 JSON 호출, `config.py` 경로 상수, 의존성 3개 |
| 신규 | 펀딩노트 전체: `web/`(화면), `api/`(분석 서버), `funding/`(공고문 추출·대조, 회사 조회, 경쟁사, 운용사 요약), `scripts/`, 테스트, 문서 |

두 화면은 따로 실행해 비교할 수 있다. `scripts/run_local.sh`를 실행하면 펀딩노트는 `http://127.0.0.1:3100`, 기존 프로토타입은 `http://127.0.0.1:8501`에 뜬다.

## 9. 한계

숨기지 않고 적는다.

- **자금 찾기 목록은 공공 API의 분류값으로만 거른다.** 세부 자격은 공고문 자격 대조를 눌러야 확인된다.
- **회사 조회는 2분 넘게 걸리고 실행할 때마다 결과가 달라진다.** 같은 회사도 잡히는 자료에 따라 값이 바뀐다(예: 경쟁사 누적 투자가 440억 원과 940억 원으로 다르게 나왔다. 기준 시점이 다른 자료다).
- **경쟁사 조건 대조는 공고에 따라 차이가 드러나지 않는다.** 업력·체납·부채비율이 조건인 공고에서는 경쟁사의 매출·직원 수를 넣어도 결과가 같았다.
- **운용사 요약은 검색 결과의 제목과 발췌만 읽는다.** 원문 전체를 읽지 않는다.
- **표가 많은 공고문은 표 구조가 풀려 근거 문장이 일부만 잡힌다.**
- **한국벤처투자 데이터에는 기업당 투자금액이 없다.** 약정액의 단위도 확인하지 못해 화면에 금액을 쓰지 않는다.
- **실제 사용자 검증, 접근성(키보드 조작·색 대비) 측정은 하지 않았다.**
- 배포하지 않았다. 로컬 실행과 영상으로 제출한다.
