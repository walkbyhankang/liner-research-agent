# 사용자 경험 체크리스트: 중소·벤처기업 자금 찾기 (옛 펀딩노트 점검 목록)

> **옛 펀딩노트 화면의 점검 기록이다.** 그 화면과 아래 측정 도구는 성장노트로 바꾸며 지웠다. 지금 화면의 완료 기준은 `docs/ux/acceptance.md`, 자동 점검은 `web/scripts/ux-check.mjs`(방법은 `web/README.md`)를 본다.
>
> 2026-11-21. 경영자 시나리오 → 체크리스트 → 브라우저 측정 → 개선 → 재측정 순서로 진행했다.
> 측정 도구(지금은 지움): `web/scripts/ux-audit.mjs`(지표), `web/scripts/ux-scenarios.mjs`(시나리오 재현). 설치된 Chrome을 `puppeteer-core`로 조작했다.

## 1. 경영자가 빨리 알고 싶은 것

자금을 찾는 경영자의 질문은 네 가지로 모인다.

| 질문 | 필요한 정보 |
|---|---|
| 우리 회사가 대상인가 | 지역, 기업 유형, 지원대상, 제외 사유 |
| 무엇을 받는가 | 지원 종류(융자·보증·이차보전), 한도·금리 같은 지원 내용 |
| 언제까지인가 | 마감일과 남은 날, 날짜가 없으면 그 사실 |
| 다음에 무엇을 하나 | 공고 원문, 신청 페이지, 문의처, 팀 공유 |

### 시나리오
| # | 상황 | 찾는 답 | 필요한 조작 | 결과 |
|---|---|---|---|---|
| 1 | 이동 중인 서울 창업기업 대표(모바일) | 곧 마감되는 융자·보증이 있나 | 지역 선택, "마감 임박" 2회 | 1건(D-9) 표시, 자세히·저장까지 4회 |
| 2 | 투자 유치를 준비하는 경기 AI 스타트업(데스크톱) | 어느 운용사에 연락할까 | 지역 선택 1회 | 운용사 목록이 스크롤 없이 보임. 2곳 저장 후 목록 복사 |
| 3 | 경남 제조 중소기업 재무 담당(데스크톱) | 시설자금 융자를 마감 순으로 | 지역, 기업 유형, "시설자금" 3회 | 공고 6건, 운용사 목록은 유지 |
| 4 | 3번의 링크를 받은 동료(모바일) | 같은 화면이 보이나 | 0회 | 지역·낱말·정렬이 그대로 복원 |

## 2. 체크리스트와 개선 전후

판정은 자동 측정(자)과 화면 확인(수)으로 나눴다. 데스크톱 1280×800, 모바일 390×844 기준.

### 가. 첫 화면에서 답이 보이는가
| 항목 | 방법 | 개선 전 | 개선 후 |
|---|---|---|---|
| 첫 결과 카드가 첫 화면 안에서 시작한다 | 자 | 데스크톱 749px, 모바일 898px(화면 밖) | 514px, 618px |
| 첫 화면에 온전히 보이는 결과 카드 | 자 | 0개 / 0개 | 2개 / 1개 |
| 설명 문구보다 결과가 먼저다 | 수 | 큰 제목과 설명 3줄이 먼저 | 제목 1줄, 모바일은 설명 숨김 |
| 결과 표시까지 걸리는 시간 | 자 | 약 0.1~0.15초 | 동일 |

### 나. 조건 입력
| 항목 | 방법 | 개선 전 | 개선 후 |
|---|---|---|---|
| 빈칸 없이 바로 결과가 나온다(기본값) | 수 | 충족 | 충족 |
| 조건을 바꾸면 결과와 제외 건수가 즉시 바뀐다 | 수 | 충족 | 충족 |
| 선택 상자에 이름이 있다(화면 낭독기) | 수 | 없음 | 지역·기업 유형·필요한 지원·관심 분야·정렬에 이름 부여 |
| 자주 찾는 낱말을 입력 없이 고를 수 있다 | 수 | 직접 입력만 | 지원 종류별 낱말 5개(해시태그 빈도 기준) |

### 다. 훑어보기
| 항목 | 방법 | 개선 전 | 개선 후 |
|---|---|---|---|
| 카드 한 장이 짧다 | 자 | 중앙값 293px / 367px | 219px / 223px |
| 접힌 카드에 종류·지역·마감·지원 내용·기관이 있다 | 수 | 대상·내용·이유·확인·링크가 모두 펼쳐짐 | 핵심만 보이고 나머지는 "자세히" |
| 확인할 점이 있으면 접힌 상태에서도 개수가 보인다 | 수 | 해당 없음 | "확인 n" 표시 |

### 라. 마감과 긴급성
| 항목 | 방법 | 개선 전 | 개선 후 |
|---|---|---|---|
| 남은 날이 숫자로 보인다 | 자 | 없음 | D-n 표시, 7일 이내는 색 구분 |
| 곧 마감되는 공고만 볼 수 있다 | 자 | 없음 | "마감 임박(14일 내)" |
| 정렬을 고를 수 있다 | 수 | 고정 | 우리 지역·마감순, 마감 임박순, 최신 등록순 |
| 날짜가 없는 공고를 날짜가 있는 것처럼 보이지 않게 한다 | 수 | 충족 | 충족("예산 소진시까지" 원문 표기 + 확인할 점) |
| 스냅샷 이후 마감된 공고가 남지 않는다 | 수 | 미처리 | 오늘 날짜로 다시 걸러 제외 |

## 3. 아직 충족하지 못한 것

| 항목 | 이유 | 해결 방향 |
|---|---|---|
| 세부 자격(업력·업종·매출)으로 대조 | 공공 API에 구조화된 값이 없음 | 공고문을 읽어 추출(Liner Search + 게이트웨이 모델) |
| "예산 소진시까지" 공고의 실제 접수 여부 | 목록의 71%가 날짜 없음 | 소진·변경 공지 검색 |
| 운용사 연락 경로와 투자 사례 | 한국벤처투자 API에 없음 | 운용사별 검색 보강 |
| 실제 경영자 대상 사용성 검증 | 자동 측정과 내부 확인만 수행 | 팀원·지인 3~5명에게 시나리오 과제를 주고 소요 시간 기록 |
| 키보드만으로 전 과정 수행, 색 대비 수치 | 측정하지 않음 | 접근성 점검 도구로 별도 확인 |
| 모바일 첫 화면에 카드 2장 이상 | 조건 문장과 필터가 3줄을 차지 | 스크롤 시 조건 요약 한 줄로 접기 |

## 4. 체크리스트의 근거

- 항목 대부분은 위 시나리오의 과제와 공공 데이터의 한계(`docs/public-data-notes.md`)에서 도출했다.
- 모바일에서 필터와 결과를 함께 보여주기 어렵다는 점은 닐슨 노먼 그룹의 모바일 패싯 검색 글(nngroup.com/articles/mobile-faceted-search)을 참고했다.
- 정부 지원금 검색 서비스의 선례로 영국 정부의 Find a grant(find-government-grants.service.gov.uk)를 참고했다. 이 서비스의 사용자 조사 결과는 찾지 못했다.
- 누르는 요소 40px, 글자 12px 기준은 이 프로젝트에서 정한 내부 기준이다.
