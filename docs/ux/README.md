# 성장노트 UX 설계

> 2026-11-22. 기준은 `docs/integration-design.md`(아래 "설계 문서")와 `CLAUDE.md`. 시각 디자인(색·글꼴)은 정하지 않았다. 다음 단계는 `frontend-design`(1차) → `impeccable`(2차).
> 2026-11-23 화면 구조 개편: 상단 메뉴는 회사 분석 · 경쟁사 분석 · 자금·판로 · 심사 준비 · 노트다. 판로 화면은 자금·판로의 판로 갈래(`/c/[id]/funding?lane=sales`, 옛 주소 `/c/[id]/sales`는 그리로 보냄)로, 경쟁사 단락은 경쟁사 분석 화면(`/c/[id]/rivals`)으로 옮겼다(`screens.md` 4B절·5.2절).

## 핵심 결정

1. **세 층으로 접는다.** 모든 화면은 1층(한 줄 요약과 핵심 몇 개), 2층(펼치기 줄을 누르면 목록·표), 3층(줄을 누르면 근거·출처)으로 나눈다. 3층보다 깊게 접지 않는다.
2. **처음 보이는 개수를 정했다.** 핵심 값 4칸, 중요 사건 3개, 주요 특허 3건, 최근 라운드 3건, 투자기관 이름 5곳, 경쟁사 후보 최대 5곳, 공고·운용사 카드 갈래마다 5장, 입찰공고 5건, 이어서 보기 3곳, 법인 후보 5곳(`screens.md` 0절 표).
3. **상태·출처는 줄여 보인다.** 값 하나에는 상태 낱말 하나만 보이고 출처는 누르면 열린다. 같은 출처의 표·차트·목록은 아래 출처 줄 하나로 한 번만. 예외 둘: **엇갈림은 접지 않고 두 값을 처음부터 나란히**, **미확보는 사유를 처음부터** 보인다.
4. **단락은 정해진 순서대로 자리를 잡고, 도착하는 대로 그 자리만 채운다.** 자리 높이를 미리 잡아 화면이 밀리지 않게 한다. 전체를 막는 대기 화면은 없다. 자금·판로는 공식 자료(약 10초)가 오면 열린다. 맨 나중에 오는 `facts`(약 3분)가 채울 칸에는 "확인 중" 한 줄을 미리 둔다.
5. **회사 표시줄은 "지금 어느 회사인가"만 알린다.** 이름, 지역, 업력, 기업 유형, 분석 시각, "회사 정보 수정", "새로 분석". 핵심 값 4칸(매출, 국민연금 가입자, 누적 투자, 국내 특허)은 표시줄과 겹치는 값을 싣지 않는다.
6. **저장된 분석은 바로 보여 주고 다시 부르지 않는다.** 분석 시각을 붙이고, 30일이 넘으면 "오래된 분석입니다". 새 분석은 확인 창(3분 안팎, Liner 약 19회)을 거쳐서만 한다. 분석한 적 없는 회사 주소를 직접 열어도 자동으로 분석하지 않는다.
7. **유료 호출은 사용자가 누른 단추로만.** 기본 분석 시작, 새로 분석, 논문 분석, 경쟁사 비교 자료 받기(경쟁사 분석 화면), 공고문 자격 대조, 운용사 요약. 단추 옆에 예상 시간과 호출 수(실측 없는 것은 호출 수만).
8. **자금·판로는 고르는 곳, 심사 준비는 깊이 보는 곳.** 자금·판로는 무료 규칙 대조와 "담기"만 한다. 자격 대조, 경쟁사 조건이라면?, 운용사 요약, 미팅 근거 묶음은 심사 준비에 모은다.
9. **심사 준비 투자 쪽에 예상 질문 19개(6갈래)와 실사 대비 자료 26개(7갈래)를 고정 목록으로 넣는다.** 회사 분석에 관련 값이 있으면 항목마다 붙이고, 엇갈림·미확보 값은 "미팅 전에 정리할 값"으로 모은다. 판정·점수·우선순위·합계 없이 사용자가 누르는 "준비함"만.
10. **iPad 터치 기준.** 누르는 곳 44×44px 이상, 펼치기 줄은 가로 전체가 눌림. 폭 세 가지(좁은 640px 미만, 중간 640~1023px, 넓은 1024px 이상)마다 배치를 정했다. 가로·세로를 돌려도 펼친 상태를 유지한다.

## 판단이 필요한 질문

1. **`profile` 글(사업 설명, 제품, 핵심 기술)의 상태**: "추정"(검색 자료를 모델이 정리)으로 두었다. 회사의 사업 설명에 "추정"이 붙어도 괜찮은가.
2. **기업 유형의 근거**: 금융위 `sme` 칸이 실측에서 비어 있었다. 근거 있는 규칙이 없으면 "미확보"로 두고 사용자가 고르게 했다. 자금·판로 조건의 "창업·벤처기업" 같은 기본값을 무엇으로 채울지.
3. 제안 2·3(운용사 요약 위치, `/funding` 유료 기능 빼기)을 받을지.
4. 제안 9: 사례 화면을 `/`로 보낼지, 코드에서 지울지.
5. "시제품" 낱말 칩: 설계 문서 10.2는 남기기로 했지만 "화면 어디에도 '시제품'을 쓰지 않는다"는 지시와 겹친다. 완료 기준 G-02는 이 칩 하나만 예외로 두었다.
6. 기본 단락 다시 실행(뉴스만 새로, 미확보 단락 다시 분석)을 이번 마감 안에 서버에 넣을지. 넣지 않으면 그 단추를 숨긴다.
7. 논문·경쟁사 깊이 비교·나라장터의 걸리는 시간이 실측되지 않았다. 지금은 호출 수만 쓰게 했다.
8. OpenAlex 논문 값의 상태를 "보도"로 둘지.
