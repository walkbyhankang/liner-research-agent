# 화면별 완료 기준

> 2026-11-22. 디자인·테스트 담당이 그대로 검사 목록으로 쓴다. 기준마다 한 문장이고, 통과/실패를 가를 수 있게 썼다.
> 근거: `screens.md`(화면), `data-needs.md`(데이터), `flows.md`(흐름).

## 0. 검사 방법과 가짜 응답

**확인 방법**

- **자동**: `npm test`(부품·규칙 단위 시험)나 브라우저 자동 점검(지금 `web/scripts/ux-audit.mjs`처럼 설치된 Chrome을 조작)으로 판정한다. 서버는 가짜 응답으로 바꾼다. 실제 유료 호출은 하지 않는다.
- **화면**: 사람이 화면을 보고 판정한다(인쇄 쪽수, 움직임, 읽기 쉬움처럼 자동으로 가르기 어려운 것).
- **폭**: 390×844(휴대폰), 820×1180(iPad 세로), 1180×820(iPad 가로), 1280×800(PC). "모든 폭"은 이 넷이다.
- **요청 세기**: "요청 n회"는 가짜 서버가 받은 해당 주소의 요청 수다.

**가짜 응답(테스트 담당이 만든다, 실제 기업 데이터를 넣지 않는다)**

| 이름 | 내용 |
|---|---|
| `F-FULL` | 기본 단락 7개 모두 `done`. 건수는 실측과 같게: 재무 3행, 국민연금 12개월, 제품 6, 핵심 기술 6, 근거 자료 25, 라운드 10(그중 1건 `other_amounts` 있음), 합친 투자기관 35, 중요 사건 14, 기사 693(분류 10종), 흐름 5, 특허 11(등록 8, `pages_checked` 30 = 한도), 언급 문서 1, 국내 경쟁사 후보 4(그중 1곳은 한글·영문 두 표기), `facts` 경쟁사에 해외 기업 2곳("해외갑", "해외을"), 기술 낱말에 "가짜낱말", 긴 뉴스 요약에 "긴요약표지" |
