# UX 설계 결정 (오케스트레이터)

> 2026-11-22. UX 설계 문서의 "판단이 필요한 질문"과 제안에 대한 결정이다. **이 문서가 `docs/ux/`의 다른 문서와 다르면 이 문서를 따른다.** 사용자 지시에 따라 사용자 결정이 꼭 필요한 것이 아니면 오케스트레이터가 권고대로 정했다.

## 1. 질문에 대한 결정

| # | 질문 | 결정 | 이유 |
|---|---|---|---|
| 1 | `profile` 글(사업 설명, 제품, 핵심 기술)의 상태 | **상태 낱말을 붙이지 않는다.** 대신 "공개 자료 {n}건을 정리한 요약"이라는 고정 표시를 두고, 누르면 근거 자료 목록이 펼쳐진다 | 상태 6종은 값(설립일, 매출 같은 사실)에 붙이는 것이다. 여러 자료를 모델이 정리한 서술에 "추정"을 붙이면 모든 회사의 첫 설명이 믿을 수 없는 글처럼 읽히고, "원문 확인"을 붙이면 규칙에 어긋난다. 요약이라는 사실과 근거 수를 그대로 알리는 것이 정확하다 |
| 2 | 기업 유형(`bizType`) | **자동으로 채우지 않는다.** 근거 있는 출처가 없으면 `unavailable`. 회사 표시줄과 자금·판로 맨 위에 "기업 유형을 골라 주세요" 고르기(창업·벤처기업 / 중소기업 / 소상공인)를 둔다. 업력과 투자 유치 기록이 있으면 고르기 옆에 "창업·벤처기업으로 보입니다(추정)"를 보이되 적용은 사용자가 누를 때만 한다. 고르기 전에는 자금·판로 목록 대신 고르기를 먼저 보인다(한 번 누르면 바로 목록) | 추정 값은 자동으로 채우지 않는다는 펀딩노트 원칙. 한 번 누르는 비용은 작다 |
| 3 | 제안 2·3(운용사 요약은 심사 준비에서만, `/funding`에서 유료 기능 빼기) | **받는다** | 둘러보다가 유료 호출이 나가지 않고, 같은 기능이 한 곳에만 있다 |
| 4 | 사례 화면 | **코드에서 지운다**(`web/app/cases`, `web/app/s/[id]`, `web/components/Workspace.tsx`의 사례 부분, `web/lib/data.ts`의 시나리오). 옛 주소 `/cases`, `/s/*`는 `/`로 보낸다. 상담 메모 부품은 노트 화면에 필요한 부분만 새로 만든다 | 가상 데이터를 저장소에 남길 이유가 없다 |
| 5 | "시제품" 낱말 칩 | **예외로 남긴다**(완료 기준 G-02 그대로) | 지원사업을 찾는 낱말이지 서비스 상태를 알리는 문구가 아니다 |
| 6 | 기본 단락 다시 실행(뉴스만 새로, 미확보 단락 다시 분석) | **넣는다(우선순위 P1).** `POST /api/analysis/{jobId}/sections/{key}`를 기본 단락에도 쓴다. 시간이 모자라면 단추를 숨긴다(`retryable: false`) | 같은 엔드포인트로 구현 비용이 작다 |
| 7 | 실측하지 않은 단락의 시간 | 호출 수만 쓴다. 테스트·검증 단계에서 크레딧이 남으면 재고 `estimates`에 반영한다 | 크레딧 $1.20 |
| 8 | OpenAlex 논문 값의 상태 | **"보도"** | 공공기관 원자료가 아닌 학술 DB 기록이다. PDL 회사 카드와 같은 취급 |

## 2. 제안에 대한 결정

- `docs/ux/README.md`의 "설계 문서와 다르게 제안한 것" 14개는 **모두 받는다.**
- `data-needs.md` 7절의 서버 확장 11개는 받되 우선순위를 나눈다(3절).
- API 경계에서 한글 키를 영문 키로 바꾼다(`data-needs.md` 8절 이름 그대로). 화면 코드는 영문 키만 쓴다.
- 실사 대비 자료 목록과 투자 미팅 예상 질문은 `anthropics/financial-services`(Apache-2.0)의 `dd-checklist`, `dd-meeting-prep`를 한국어로 다시 쓴 것이다. 코드에 넣을 때 파일 머리에 원본 경로와 "변경함"을 적고, 저장소 루트 `THIRD_PARTY_NOTICES.md`에 원본·라이선스를 적는다.
- `data-needs.md` 9절의 확인 질문 4~7(운용사 요약 `facts[].kind`, 뉴스 사건 `source` 순번, Premium 카드 `match` 값, `employees_fsc` 뜻)은 서버 담당이 코드로 확인해 계약 문서에 적는다.
- 흐름 1의 7단계(`flows.md`)는 위 결정 2에 맞게 "기업 유형 고르기 한 번"으로 고친다.

## 3. 우선순위 (마감 2026-11-25)

| 등급 | 범위 |
|---|---|
| **P0** (반드시) | 시작, 회사 확정, 회사 분석 6단락(개요, 재무·고용, 투자, 최근 동향, 기술=특허, 경쟁사 후보), 단락 봉투·`merged`·`error.code`·`analyzedAt`, 저장된 분석 찾기와 예시 회사, 기사 나눠 받기, 자금·판로(조건 미리 채우기, 이미 투자함 묶음, 회사 사업과 관련), 심사 준비(공고문 대조, 부족한 요건, 운용사 요약, 미팅 근거 묶음, 예상 질문·실사 자료), 노트와 인쇄, 브라우저 저장(IndexedDB), 새로 분석 확인 창, 호출 상한, 보안, 시제품 문구·사례 화면 제거, 이름 변경 |
| **P1** (가능하면) | 판로(나라장터 + 판로 지원사업), 경쟁사 깊이 비교와 "경쟁사에 투자" 표시, 논문, 뉴스만 새로·미확보 단락 다시 분석, `estimates`, 노트 파일 내보내기·불러오기, 진행 중 작업 이어 받기 |
| **P2** (다음) | 그 밖의 모든 것 |

P1을 못 하면 그 기능의 단추와 메뉴를 숨긴다. 화면에 "준비 중" 같은 문구를 두지 않는다.
