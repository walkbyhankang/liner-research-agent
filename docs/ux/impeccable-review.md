# 성장노트 화면 impeccable 검토 (디자인 2단계)

> 2026-11-23. 기준 커밋 `0253b28`(서버·화면을 합친 커밋), 브랜치 `growth-polish`.
> 1단계(`frontend-design`)로 만든 `web/` 화면을 `impeccable` 스킬(v4.10.0, 엔진 0.1.27)로만 검토하고 다듬었다. 순서: critique → audit → 고치기 → polish.
> 이 문서의 점수는 **화면 품질 검토용**이다. 서비스 화면에는 점수·확률을 넣지 않는다는 규칙(`CLAUDE.md`)은 그대로다.

## 0. 진행 방식과 바꾼 것

- **제품 맥락**: 저장소에 `PRODUCT.md`·`DESIGN.md`가 없다(`impeccable context`가 알림). 새로 만들지 않고 `docs/ux/decisions.md`, `design-brief.md`, `visual-plan.md`, `acceptance.md`, `screens.md`와 제품 책임자 지시(압축 먼저·누르면 펼침, 흰 바탕 전문 정보 사이트, iPad 터치 44px와 휴대폰)를 그 자리에 썼다. 화면 성격(mode)은 Operate(작업 도구).
- **critique**: `Method: dual-agent (A: 디자인 검토 하위 담당 · B: 검출기·브라우저 하위 담당)`. 두 담당은 서로의 결과를 보지 않고 따로 돌았다. 진행 담당(나)은 A가 끝나기 전에 B 결과를 먼저 받았지만, A에게는 전달하지 않았다.
- **사람이 보는 겹쳐 보기(overlay)**: 이 환경에는 사람이 보는 브라우저 탭이 없어 만들지 않았다. 대신 `impeccable detect --json <주소> --viewport <폭>`으로 주소를 검사했다.
- **질문 생략**: `Questions skipped: delegated run`(하위 담당으로 돌아 사용자에게 물을 수 없음). 범위와 우선순위는 오케스트레이터 지시를 따랐다.
- **기록 저장 생략**: `critique-storage`/`audit-storage`는 저장소 `.impeccable/`에 쓰는데, 맡은 파일 범위(`web/`, `docs/ux/visual-plan.md`, 이 문서) 밖이라 쓰지 않았다. 이 문서가 그 기록이다.
- **실제 데이터**: 분석 서버 `127.0.0.1:8000`의 예시 회사(기준 기업, `1234567890123`)로 화면을 띄워(포트 3300) 봤다. 유료 단추(공고문 자격 대조, 운용사 요약, 새로 분석, 깊이 비교, 논문 분석)는 누르지 않았다. "담기"·기업 유형 고르기·펼치기처럼 브라우저에만 쓰는 동작만 했다.

- 한계: 새 브라우저로 열어 자금 조달은 기업 유형 고르기 관문만, 심사 준비·노트는 빈 상태만 검사됐다. 0건을 "깨끗함"으로 읽지 않는다.

### 1.4 페르소나 붉은 신호 (요약)

- 숙련 사용자: 검색·정렬이 목록 맨 아래, 칩 상자에 Esc가 없음.
- 보조 기술 사용자: 목차 `aria-current`가 맨 위에서 틀림, 판로 검색어 상자가 누를 수 있어 보임.

- 대표·재무 담당: 공급사 이름, "6/8개 채움"이 점수처럼 읽힘, 유료 단추에 호출 수 없음.
