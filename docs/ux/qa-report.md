# 성장노트 UX QA 리포트

- 점검일: 2026-11-23
- 목적: 해커톤 시연을 위한 UI, 가독성, 불필요한 요소, 화면 간 일관성 개선
- 범위: 리포트 작성만. 제품 코드 수정 없음. 데스크톱 중심.
- 진행: 화면별 계획 승인 → 실제 화면 점검 → 결과 기록 → 다음 화면 승인
- 우선순위: 높음(핵심 행동·이해 방해), 중간(가독성·일관성 개선), 낮음(시각적 다듬기)
- 시작 화면의 홈페이지 주소 입력 제거는 확정했다. 나머지는 검토 중인 제안이다.

## 1. 시작 화면 `/`

### 점검 범위와 근거

실행 중인 `http://localhost:3100/`을 인앱 브라우저에서 확인했다. 기본 상태, 빈 회사명·한 글자 회사명 제출, 오류 후 회사명 수정, 홈페이지 선택 입력란 펼침, 자료 설명 펼침을 점검했다. 회사 분석과 외부 유료 호출은 실행하지 않았다. 점검 후 기본 화면으로 복원했다.

현재 인앱 브라우저의 약 900px 폭 화면에서 관찰했다. 넓은 데스크톱(1440·1920px), 브라우저 확대, 모바일, 스크린리더는 이번 단계에서 검증하지 않았다. 아래 시각 판단은 현재 화면에 한정한다. 최근 회사가 없는 상태였으므로 ‘이어서 보기’는 미점검이다.

기본 화면: [스크린샷](qa-evidence/01-home-default.jpg)

홈페이지·자료 설명을 펼치고 회사명을 수정한 뒤 오류 문구가 남은 상태: [스크린샷](qa-evidence/01-home-expanded-validation.jpg)

### 종합 판단

분석 시작 버튼의 색과 입력창 배치는 핵심 행동을 잘 드러낸다. 장식이 적고 본문 대비도 육안으로 읽기 편하다. 대대적인 재설계보다 서비스 가치의 표현, 입력 오류 피드백, 선택 입력의 동작을 먼저 다듬는 것이 적절하다. 현재 구분선은 헤더·자료 설명·푸터의 역할을 구분하며, 선이 과도한 화면으로 보이지 않는다. 무조건 선을 없애기보다 역할이 중복되는지 화면별로 판단해야 한다.

### 유지할 요소

- 회사명 입력란에 보이는 레이블을 사용한다.
- 분석 시작만 채운 색 버튼으로 강조한 기본 위계.
- 빈 입력 제출 시 입력창으로 포커스를 옮기는 동작과 구체적인 최소 길이 안내.
- 예시 진입과 회사 없이 탐색할 수 있는 대체 경로.
- 출처 설명을 접어 두고, 확인 상태·출처 원칙을 안내하는 구성.
- 여백으로 구역을 나눈 단순한 화면. 빈 공간을 채우기 위한 카드·장식·구분선 추가는 권하지 않는다.

### 권장 수정 순서

1. HOME-02: 수정된 입력에 남는 오류를 해제한다.
2. HOME-03·04. 홈페이지 주소 입력과 펼침 버튼을 제거해 시작 화면을 간결하게 만든다.
3. HOME-01: 제목에는 우리 회사와 경쟁사 분석을 담고, 소개에서 자금·판로 탐색과 심사 준비로 이어지는 흐름을 설명한다.
4. HOME-05: 자료 설명을 정보 종류 중심으로 압축한다.
5. HOME-06·07: 보조 행동의 위계와 시간 안내를 다듬는다.

### 화면 간 공통 항목으로 추적할 것

아래는 시작 화면만 보고 확정한 전역 문제는 아니다. 다음 화면에서 같은 원칙이 유지되는지 확인한다.

- 버튼: 주요 행동은 채운 색, 보조 행동은 테두리, 부가 행동은 텍스트로 구별하는가.
- 선택 정보: 접기·펼치기 조작과 상태 표시가 일관적인가.
- 오류: 문제 위치를 안내하고, 사용자가 고치면 유효한 상태로 돌아오는가.
- 출처 설명: 사용자에게 의미 있는 정보와 구현 용어를 구분하는가.
- 선·테두리: 정보 구분에 필요한 것만 남기고 여백과 중복되지 않는가.

### 사용자 주석을 반영한 시연용 제안

첨부된 데스크톱 화면의 주석 다섯 곳에 대한 개선안이다.

| 주석 | 권장안 | 이유 |
|---|---|---|
| 1. 하단 문구 | **분석 결과에서 자료의 출처와 확인 여부를 볼 수 있습니다.** 이 문장을 자료 안내 안으로 옮긴다. | 사용자가 확인할 수 있는 내용을 먼저 말한다. 점수·선정 확률에 관한 정책 설명도 필요하다면 펼친 영역에 둔다. |
| 2. 자료 안내 위 구분선 | 제목을 **분석에 쓰는 자료**로 바꾸고, 상단선을 없애고 여백으로 앞 버튼과 구분한다. 기존 펼침 아이콘, 행 전체 클릭, 키보드 포커스 표시는 유지한다. | 여러 항목이 이어지는 아코디언에서는 구분선이 행을 나누는 데 도움이 된다. 이 화면에는 펼칠 항목이 하나라 여백과 아이콘으로 충분히 구별할 수 있다. |
| 3. 분석 시간 | **분석은 약 3분 걸립니다. 준비된 자료부터 차례로 보여드립니다.** | 예상 대기 시간과 중간에 무엇을 볼 수 있는지 전달한다. 개별 요청에 대한 ‘10초 안’ 보장으로 읽힐 여지를 줄인다. |
| 4. 제목과 소개 | 제목 **우리 회사를 분석하고 경쟁사와 비교하세요.** 소개 **회사 이름을 입력하면 공공 자료와 공개 보도를 바탕으로 우리 회사의 현황을 분석하고 경쟁사와 비교할 수 있습니다. 분석 결과를 바탕으로 자금과 판로를 찾고, 지원사업 심사와 투자 미팅을 준비할 수 있습니다.** | 우리 회사와 경쟁사 분석을 첫 화면의 핵심으로 제시한다. 자금·판로 탐색과 심사 준비는 분석 결과를 활용하는 다음 단계로 설명한다. |
| 5. 홈페이지 주소 | **제거 확정.** 시작 화면에 회사 이름 입력과 분석 시작 버튼을 둔다. 회사 확정 화면에도 홈페이지 주소 입력을 추가하지 않는다. | 현재 법인 검색은 회사 이름을 사용한다. 입력란을 제거해도 회사 이름 검색과 기존 법인 후보 선택 흐름은 유지된다. |

시연에서는 회사명만 받는 대신, 사용자가 분석에 쓸 도메인을 직접 보완할 수 없다는 제약을 감수한다. **사실 조사**는 법인 정보 조회와 동시에 시작한다. 조회가 끝나기 전에 검색을 시작하면 법인 정보에 홈페이지가 있어도 그 주소를 검색에 쓰지 못할 수 있다. **투자 이력 검색**은 법인 정보 조회 이후에 실행되므로 확보한 홈페이지를 쓸 수 있다. 법인 정보 없이 분석하거나 홈페이지를 확보하지 못하면 도메인으로만 식별되는 투자 기록이 누락될 수 있다.

## 2. 회사 확정 `/?name=…`

1280×720 인앱 브라우저에서 `기준 기업`과 빈 결과용 가상 이름을 확인했다. 두 검색 모두 URL에 회사명을 인코딩해 직접 진입했다. 기준 기업의 동명 후보 2곳, 기본 미선택 상태, 저장된 분석이 있는 후보 선택, ‘목록에 없음’ 선택을 확인했다. 가상 이름으로는 조회 중 문구와 빈 결과를 확인했다. 분석 버튼은 누르지 않았다. 서버 오류는 코드로만 확인했다.

진입 방법: 시작 화면 폼을 제출하지 않고 `http://localhost:3100/?name=<URL 인코딩한 회사명>`을 직접 연다. 이 경로는 법인 검색만 수행하며, 후보가 한 곳이어도 자동 분석하지 않는다. 시작 폼은 정확히 일치하는 후보가 한 곳이고 저장된 분석이 없으면 유료 분석을 자동 시작할 수 있으므로 사용하지 않는다. 회사 확정 화면에서는 후보 선택과 표시 확인까지만 진행하며 ‘분석 시작’·‘공개 자료만으로 분석’ 등 분석을 실행하는 버튼은 누르지 않는다.

기준 기업 후보 선택 캡처는 실제 사업자번호가 포함되어 저장소 밖에 보관했다. [빈 결과 캡처](qa-evidence/02-company-no-results.jpg)

| ID | 우선순위 | 관찰과 영향 | 개선 제안 |
|---|---|---|---|
| CONFIRM-01 | 중간 | 두 후보의 이름과 대표가 같고, 두 행에 ‘이름이 같음’이 반복된다. 실제 구별 정보인 설립일·사업자번호·이전 이름은 그 아래에 섞여 있다. | 상단에 ‘이름이 같은 법인 2곳을 찾았어요. 사업자번호나 설립일을 확인해 주세요.’를 한 번 표시한다. 후보별 사업자번호·설립일을 같은 위치에 두고 이전 이름을 눈에 띄게 표시한다. 저장 결과가 있는 후보 행에는 작은 ‘저장된 분석 있음’ 표시를 유지한다. 해당 후보를 선택하면 버튼은 ‘저장된 분석 보기’로 표시한다(수용 기준 K-06). |
| CONFIRM-02 | 중간 | ‘목록에 없음’ 선택 후 버튼은 ‘이 회사로 분석’이다. 빈 결과 화면의 같은 동작은 ‘공개 자료만으로 분석’이다. | 두 상태의 버튼을 ‘공개 자료만으로 분석’으로 통일한다. 보조 설명은 ‘법인 정보 없이 분석합니다. 공식 재무·고용 자료는 포함되지 않습니다.’처럼 결과를 중심으로 정리한다. |
| CONFIRM-03 | 중간 | 가상 이름 조회 중에는 ‘법인 찾는 중’만 보이고, 빈 결과에서는 제목과 입력명이 표시된다. 코드상 조회 오류는 후보 선택과 같은 ‘어느 회사인가요?’ 제목 아래 오류 메시지와 ‘이름 다시 넣기’만 표시한다. | 조회 중에도 입력한 회사명을 표시한다. 오류 화면에서는 조회 실패를 제목으로 명시하고 재시도와 이름 수정의 목적을 구별한다. |
| CONFIRM-04 | 낮음 | 후보 사이 구분선은 같은 이름의 행 경계를 보여 준다. 목록 위아래 선까지 있어 첫 행과 마지막 행에도 선이 붙는다. | 후보 사이 선은 유지한다. 목록 외곽선은 간격으로 대체하고 ‘목록에 없음’은 같은 선택 그룹 안에서 보조 경로임이 드러나도록 배치한다. |

동명 후보를 미리 선택하지 않고, 선택 전 진행 버튼을 비활성화하는 동작을 유지한다. 저장된 결과가 있는 후보를 고르면 ‘저장된 분석 보기’로 바뀌는 동작도 유지한다.

### 공통 적용 순서

1. 회사 분석의 핵심 지표와 제목 위계, 회사 분석 → 경쟁사 분석 → 자금·판로 → 심사 준비 버튼을 먼저 정리한다.
2. 펼친 항목의 왼쪽 강조선, 출처 표시 위 장식선, 구역 사이 구분선 규칙을 맞춘다. 표·비교 목록처럼 행 경계가 필요한 곳에는 얇은 선을 쓴다.
3. 자금·판로 도움말과 노트를 정리하고, 화면 전체에서 용어와 상태 표기를 확인한다.

## 4. 공통 디자인 기준과 추가 QA 제안

회사 분석과 경쟁사 분석을 서비스의 중심으로 두고, 자금·판로와 심사 준비는 분석 결과를 활용하는 흐름으로 연결한다. 아래 기준과 추가 발견 사항은 브라우저 주석, 앞서 확인한 화면 상태, 관련 화면 코드를 대조해 작성한 구현 제안이다.

| 요소 | 적용 기준 |
|---|---|
| 제목과 주요 수치 | 페이지 제목, 구역 제목, 항목 제목은 크기뿐 아니라 위치와 여백으로 구별한다. 구역 제목 아래의 주요 지표는 옅은 배경에 이름·값·기간 순으로 배치한다. 진한 배경은 현재 단계나 주요 행동처럼 강조할 역할이 분명한 곳에 집중한다. |
| 줄 간격과 여백 | 본문은 줄 높이 1.55~1.65, 출처·기준일은 1.4~1.5를 출발점으로 한다. 제목과 요약은 8px, 같은 구역 안 묶음은 16~24px, 큰 구역 사이는 32~40px 간격부터 검토한다. 폭 1280px과 1580px에서 긴 한국어 제목과 주소가 자연스럽게 줄바꿈되는지 확인한다. |
| 경계와 펼침 | 큰 구역은 주로 여백으로 나눈다. 표와 비교 목록에는 행을 따라 읽을 수 있도록 얇은 선을 사용한다. 펼친 항목은 옅은 배경과 블록 전체를 잇는 왼쪽 선을 공통으로 적용한다. 근거 인용의 선은 더 가볍게 표시한다. 출처 위 짧은 장식선은 정리한다. |
| 상태와 근거 | 상태를 설명하는 텍스트를 유지한다. 색만으로 구별하지 않는다. 상태는 값 가까이, 출처와 기준일은 해당 값이나 조건 바로 아래에 둔다. 펼치기 전에는 숫자의 해석을 바꾸는 정보만 노출하고, 상세에는 원문 링크와 자료의 한계를 둔다. |
| 행동 | 같은 역할의 버튼은 같은 크기·색·문장 구조를 쓴다. 본문 끝의 주요 이동은 ‘경쟁사 분석 보기’, ‘자금·판로 보기’, ‘심사 준비로 가기’처럼 도착 화면을 밝힌다. 상단 메뉴로도 이동할 수 있으므로 본문 중간에 같은 목적의 큰 배너를 반복하지 않는다. |
| 문구 | 제목은 짧은 명사구, 버튼은 대상을 포함한 동작, 안내는 사용자가 알아야 할 결과를 먼저 쓴다. ‘이 회사 값으로’는 ‘회사 분석 결과로’, ‘대조에 쓴 회사 값’은 ‘판단에 사용한 회사 정보’로 다듬는다. 뜻이 같은 용어만 통일하고 ‘미확보’, ‘미충족’, ‘확인 필요’의 차이는 유지한다. |

### 주석 외에 추가로 다듬을 부분

| 화면 | 관찰과 개선안 |
|---|---|
| 시작·회사 확정 | 시작 화면의 간결한 입력 구조를 살리고, 회사 확정은 검색한 이름과 후보 수, 구별에 필요한 정보, 버튼 순으로 읽히게 한다. 로딩이나 빈 결과에서도 같은 위치에 검색명을 두면 어떤 검색의 결과인지 놓치지 않는다. |
| 회사 분석 | ‘지금 확인할 것’은 ‘확인이 필요한 정보’처럼 제목만 읽어도 목적이 드러나게 한다. 예시 분석의 재무·고용에서 ‘금융위원회 재무 자료 없음’이 구역 경고와 매출 항목에 반복된다. 매출·영업이익 영역에 한 번만 설명한 뒤 공식 재무 자료와 웹 보도 수치를 나란히 구분한다. 국민연금 요약은 큰 현재값, 측정월, 12개월 변화 순으로 나누어 긴 문장보다 빨리 읽게 한다. |
| 경쟁사 분석 | 넓은 표의 ‘우리 회사’ 열에는 옅은 배경을 사용해 기준점이 보이게 한다. 지표 행의 값·단위·기준일 위치를 맞추고, 출처 링크와 자료가 없는 상태는 숫자와 분리한다. 상대 순위나 우열을 뜻하는 색 강조는 피한다. |
| 자금·판로 | 기업 유형 선택을 결과 보기 전에 해야 할 일로 표시한다. 목록에서는 제목·마감·지원 유형·담기 순서를 맞추고, 매칭에 쓴 조건과 용어 설명은 공통 도움말로 모은다. |
| 심사 준비 | 공고별 판정 요약과 조건별 상세를 분리한다. 미충족·확인 필요 건수를 상단에 먼저 보여 주고, 조건을 펼치면 ‘조건 → 근거 → 판단 이유’ 순서로 읽히게 한다. |
| 노트 | 각 공고에서 판단 결과와 다음에 확인할 내용을 먼저 읽게 한다. 출처나 근거 상세는 그 아래에 두고, 화면과 인쇄에서 제목과 해당 내용이 서로 떨어지지 않는지 확인한다. |

구현 검토는 회사 분석에서 시작한다. 대표·본사 펼침, 재무·고용, 투자 라운드, 경쟁사 분석으로 가는 버튼에 먼저 공통 기준을 적용해 비교한다. 이후 다른 화면에도 같은 규칙을 쓰고, 긴 목록·자료 미확보·모두 펼친 상태·키보드 포커스·인쇄에서 핵심 정보가 유지되는지 확인한다.
