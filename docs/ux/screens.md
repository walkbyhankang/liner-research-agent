# 화면 설계

> 2026-11-22. 기준: `docs/integration-design.md`(아래 "설계 문서"). 흐름과 주소는 `flows.md`, 받는 데이터는 `data-needs.md`, 완료 기준은 `acceptance.md`.
> 색 값·글꼴은 정하지 않는다(`design-brief.md`). 이 문서는 구조, 정보 위계, 상호작용, 문구, 상태를 정한다.
> **2026-11-23 화면 구조 개편**: 상단 메뉴를 회사 분석 · 경쟁사 분석 · 자금 조달 · 심사 준비 · 노트로 바꿨다. 회사 분석의 경쟁사 단락은 새 화면 **경쟁사 분석(4B절)**으로, 판로 화면은 **자금 조달의 셋째 갈래(5.2절)**로 옮겼다. 다른 문서와 코드가 절 번호를 가리키므로 번호는 바꾸지 않고, 옛 4.6절·7절에는 옮긴 곳만 적었다. 시각 계획은 `visual-plan.md` 6절.

## 0. 읽는 법

- **큰따옴표 안은 화면에 그대로 쓰는 문구**다. `{중괄호}`는 데이터로 채운다. 문구를 바꾸려면 이 문서를 먼저 고친다.
- **층**: 모든 화면은 세 층으로 접는다.
  - 1층: 처음 보이는 것. 한 줄 요약과 핵심 몇 개.
  - 2층: 펼치기 줄을 누르면 열리는 것. 목록 전체, 표, 차트의 숫자.
  - 3층: 목록의 줄 하나를 누르면 그 줄 아래 열리는 자세히. 근거 문장, 출처, 원문 링크.
  - 3층보다 깊게 접지 않는다. 여는 동작은 두 번까지만 겹친다: 펼치기 줄이나 카드의 "자세히"로 한 번 열고, 그 안의 줄 하나를 한 번 더 연다. 그 안에 또 여는 것을 두지 않는다(2층 안의 "더 보기"는 같은 층의 이어 보기라 겹침으로 세지 않는다).
  - 카드: 목록 안의 카드는 접힌 모양이 그 층이고, 카드의 "자세히"가 한 층 아래다. 자금 조달 카드(목록이 1층)의 자세히는 3층이라 그 안에 더 여는 것이 없다. 심사 준비 카드(카드가 1층)의 자세히는 2층이고, 그 안의 줄을 누르면 3층이다.
- **폭**: 좁은 화면(640px 미만, 휴대폰), 중간 화면(640~1023px, iPad 세로·iPad 화면 나누기), 넓은 화면(1024px 이상, iPad 가로·PC). 검사 폭은 390, 820, 1180, 1280px.
- **터치**: 누르는 곳은 가로·세로 44px 이상, 이웃한 누르는 곳 사이는 8px 이상. 마우스를 올려야만 보이는 정보는 두지 않는다(iPad에는 올리기가 없다).
- **용어**: 단계(회사 분석·경쟁사 분석·자금 조달·심사 준비·노트), 단락(회사 분석 안의 5덩어리), 갈래(자금 조달 안의 빌리는 돈·투자받는 돈·판로), 회사 값(분석으로 얻었거나 사용자가 고친 값으로, 자금 조달과 대조에 쓰는 값), 담기(심사 준비와 노트로 모으기).

### 처음 보이는 개수 (모든 화면 한눈에)

| 화면 | 1층에 보이는 것 | 개수 |
|---|---|---|
| 시작 | 이어서 보기 | 최대 3곳 |
| 회사 확정 | 법인 후보 | 최대 5곳 + "목록에 없음" |
| 회사 분석 | 핵심 값 | 4개(매출, 국민연금 가입자, 누적 투자, 국내 특허) |
| 개요 | 사업 설명 / 기업 사실 / 제품 이름 / 핵심 기술 | 2줄 / 4줄 / 3개 / 4개 |
| 재무·고용 | 차트 | 2개(재무 막대, 국민연금 선) |
| 투자 | 최근 라운드 / 투자기관 이름 | 3건 / 5곳 |
| 최근 동향 | 중요 사건 | 3개 |
| 기술 | 특허 연도 선 / 주요 특허 | 1개 / 3건 |
| 경쟁사 분석 | 국내 경쟁사 후보 / 비교 표 항목 / 경쟁사별 사업과 최근 변화 | 최대 5곳 / 7줄 / 모두(접힌 채) |
| 자금 조달 | 갈래마다 카드 | 5장 |
| 자금 조달 판로 갈래 | 입찰공고 / 판로 지원사업 카드 | 5건 / 5장 |
| 심사 준비 | 담은 공고·운용사 카드 | 모두(접힌 채) |
| 노트 | 목록마다 | 5개 |

## 1. 공통 요소

### 1.1 머리줄과 단계 메뉴

**목적**: 어느 회사의 어느 단계에 있는지 알리고, 단계 사이를 한 번에 옮긴다.

- 머리줄 왼쪽: "성장노트"(누르면 시작 화면).
- 회사가 정해진 화면(`/c/[id]/…`)에서는 단계 메뉴 5개: "회사 분석", "경쟁사 분석", "자금 조달", "심사 준비", "노트"(2026-11-23 화면 구조 개편. 판로는 자금 조달의 갈래로 옮겼다, 5.2절). 이 순서는 바꾸지 않는다. 번호는 붙이지 않는다.
- **좁은 화면(640px 미만)의 짧은 이름**: "회사", "경쟁사", "자금", "심사", "노트". 다섯 단계와 개수가 390 폭 한 줄에 들게 하려는 것이다("경쟁사 분석"을 그대로 쓰면 약 430px로 넘쳐 "노트"가 화면 밖에 숨는다). 화면 읽기 이름은 언제나 전체 이름이고(개수가 있으면 아래 표의 이름), 보이는 짧은 이름이 그 안에 들어 있다. 각 화면의 제목(h1)은 전체 이름을 쓴다.
- 지금 단계는 표시하고 `aria-current="page"`를 준다.
- **단계 옆 개수**(2026-11-23 가독성 조정에서 넓힘, 같은 날 화면 구조 개편에서 고침): 이 브라우저에서 고르거나 담은 것을 단계 이름 옆에 작게 붙인다. 0이면 붙이지 않는다. 개수는 사실을 센 것이고 진행률·완료율이 아니다.

  | 단계 | 세는 것 | 화면 읽기 이름 |
  |---|---|---|
  | 경쟁사 분석 | 고른 경쟁사: "맞음"인 후보와 "맞음"인 직접 넣은 회사(4B.1절 "처음 고르기" 포함) | "경쟁사 분석, 고른 경쟁사 {n}곳" |
  | 자금 조달 | 자금 조달에서 담은 것 전체: 공고(빌리는 돈·판로 갈래에서 담은 같은 공고는 하나로), 운용사, 노트에 담은 입찰공고(`program`·`salesProgram` 합쳐 공고 id로 하나 + `gp` + `bid`) | "자금 조달, 담은 자금·판로 후보 {n}개" |
  | 심사 준비 | 담은 항목 전체: 공고·운용사·판로 지원사업(같은 공고는 하나로, 노트에만 담는 입찰공고 제외). 지금까지와 같다 | "심사 준비, 담은 항목 {n}개" |
  | 회사 분석, 노트 | 붙이지 않는다(노트는 모든 담은 항목이 모이는 곳이라 다른 단계 숫자와 겹친다) | |

  - 자금 조달과 심사 준비 숫자는 입찰공고를 담지 않았으면 같다. "여기서 고른 수"와 "준비할 곳에 모인 수"를 각각 보이는 것이라 둘 다 둔다.
  - "자금 조달"이 "준비 중"(누를 수 없음)일 때는 숫자를 붙이지 않는다.
- "경쟁사 분석"은 언제나 누를 수 있다. 경쟁사 후보(`profile`)를 받기 전에 열면 그 화면에 "확인 중"이 보인다(4B.1절).
- "자금 조달"은 공식 자료(지역·업력)를 받기 전에는 누를 수 없다. 그 자리에 작은 글 "준비 중"을 쓰고, 화면 읽기 프로그램용 설명은 "공식 자료를 받으면 열립니다". 공식 자료가 미확보로 끝나면 바로 열린다(조건을 직접 고른다).
- 회사 분석이 진행 중이면 "회사 분석" 옆에 작은 진행 표시를 붙인다(움직임 줄이기 설정이면 멈춘 표시).
- 회사가 없는 화면(`/`, `/funding`): 단계 메뉴 없음. `/funding` 오른쪽에 "회사 분석 시작" 링크.
- **배치**
  - 넓은·중간: 한 줄에 "성장노트"와 단계 메뉴. 이 줄이 화면 위에 붙는다.
  - 좁은: "성장노트" 줄은 스크롤하면 사라지고, 단계 메뉴 줄만 위에 붙는다. 5개를 같은 폭으로 나눠 한 줄에 둔다(짧은 이름). 글자가 넘치는 기기에서는 가로로 밀어 볼 수 있다.
- 위에 붙는 줄은 화면마다 최대 2개다: 단계 메뉴, 그리고 화면에 따라 하나(회사 분석의 단락 목차 줄, 자금 조달의 갈래 탭, 심사 준비의 갈래 고르기). 넓은 화면에서는 단계 메뉴 하나만 붙는다(목차는 왼쪽 단에 붙는다).

### 1.2 회사 표시줄

**목적**: 지금 보는 회사와 분석 시각을 알리고, 회사 정보 수정과 새로 분석으로 가는 입구가 된다.

- 위치: 회사가 정해진 모든 화면의 머리줄 바로 아래. 위에 붙지 않는다(스크롤하면 사라진다).
- 내용(왼쪽부터)
  1. 회사 이름. 회사 분석 화면에서는 이것이 그 화면의 제목(h1)이다. 다른 단계 화면에서는 일반 글이고 제목은 단계 이름이다.
  2. 사실 칩 3개: 지역(예: "서울"), 업력(예: "업력 4년"), 기업 유형(예: "창업·벤처기업"). 칩을 누르면 그 아래 작은 상자가 열려 값, 상태 낱말, 출처 줄을 보여 준다(1.3절). 사용자가 고친 값이면 칩에 "직접 입력"을 붙인다.
  3. 분석 시각: "{YYYY-MM-DD HH:mm} 분석". 진행 중이면 "분석 중 ({경과})". 30일이 넘었으면 "{YYYY-MM-DD} 분석, 오래된 분석입니다".
  4. 단추: "회사 정보 수정", "새로 분석". (2026-11-23 "값 고치기"에서 바꿈: 무엇을 고치는지 한 번에 알 수 있게. 값 옆 "직접 입력"·"분석 값으로 되돌리기"는 그대로 둔다)
- 업력: 설립일부터 오늘까지 만 연수. 1년 미만은 "업력 1년 미만". 설립일이 엇갈림이면 공공 API 값으로 계산하고 칩에 "엇갈림"을 붙인다(설계 문서 4.1).
- 값이 없으면 칩에 "지역 미확보"처럼 쓰고, 누르면 회사 정보 수정 창이 열린다.
- 기업 유형은 서버가 근거와 함께 주는 값만 쓴다(`data-needs.md` 3절). 없으면 "기업 유형 미확보"로 두고 사용자가 고른다.
- **예시 회사**일 때: 회사 이름 옆에 "예시 회사", "새로 분석" 단추는 숨긴다. 표시줄 아래 한 줄: "저장해 둔 예시 분석입니다. 우리 회사를 보려면 회사 이름을 넣으세요." + 링크 "회사 이름 넣기"(시작 화면).
- **오래된 분석**(30일 초과): 분석 시각 줄에 "오래된 분석입니다"를 쓰고, 표시줄 아래 한 줄: "{n}일 전 분석입니다. 최근 자료를 보려면 새로 분석하세요." 자동으로 다시 분석하지 않는다.
- **배치**
  - 넓은: 한 줄(이름, 칩 3개, 분석 시각, 단추 2개 오른쪽 끝).
  - 중간: 두 줄(1줄: 이름과 단추 2개, 2줄: 칩 3개와 분석 시각).
  - 좁은: 세 줄(1줄: 이름, 두 줄까지 줄바꿈, 2줄: 칩 3개, 3줄: 분석 시각과 단추 2개).

### 1.3 상태와 출처 표시

**목적**: 값이 얼마나 확인됐는지(상태)와 어디서 왔는지(출처)를 따로 알리되, 화면을 상태 표시로 덮지 않는다.

**상태 낱말 6종과 직접 입력** (서버 값 → 화면 낱말)

| 서버 값 | 화면 낱말 | 뜻(상태 안내와 3층에 쓰는 문장) |
|---|---|---|
| `confirmed` | "원문 확인" | "원문 본문이나 공공 기관 원자료에서 값을 확인했습니다." |
| `reported` | "보도" | "기사, 자료, 투자 DB에 적혀 있지만 원문 본문으로 확인하지는 않았습니다." |
| `inferred` | "추정" | "모델이 판단했거나 간접 근거로 짐작한 값입니다." |
| `conflicting` | "엇갈림" | "자료마다 값이 다릅니다. 어느 한쪽을 고르지 않고 함께 보여 줍니다." |
| `unavailable` | "미확보" | "자료를 얻지 못했습니다. 사유를 함께 적습니다." |
| `reference` | "참고" | "같은 값이 아니라 대신 볼 수 있는 값입니다. 예: 국민연금 가입자 수는 직원 수와 다릅니다." |
| (브라우저) | "직접 입력" | "이 브라우저에서 고친 값입니다. 새로 분석해도 바뀌지 않습니다." |

"직접 입력"은 확인 정도가 아니라 값의 주인이 바뀌었다는 표시라 6종과 따로 센다.

**규칙**

1. **낱개 값**(핵심 값, 개요의 기업 사실, 회사 표시줄 칩): 값 바로 뒤에 상태 낱말 하나만 보인다. 출처는 그 줄을 누르면 3층으로 열린다.
2. **묶음 값**(표, 차트, 같은 출처의 목록): 줄마다 상태 낱말을 붙이지 않는다. 묶음 바로 아래 **묶음 출처 줄** 하나에 "{상태 낱말}" + 출처를 쓴다. 묶음 안에서 상태가 다른 값만 그 값 옆에 상태 낱말을 붙인다.
3. **엇갈림은 접지 않는다.** 1층에서 두 값을 위아래로 나란히 보인다. 첫 줄: 값과 짧은 출처(예: "(금융위원회)"), 둘째 줄: "다른 자료:" + 값과 짧은 출처. 상태 낱말 "엇갈림"은 항목 이름 옆에 한 번. 어느 쪽이 맞다고 쓰지 않는다. 계산(업력)과 자격 대조에 어느 값을 쓰는지는 3층에 쓴다: "업력 계산과 자격 대조에는 공공 API 값을 씁니다."
4. **미확보는 사유를 처음부터** 보인다. 값 자리에 "미확보" + 짧은 사유(20자 안팎). 예: "미확보: 공식 재무 자료 없음". 빈칸, "0", "-"만 쓰지 않는다.
5. **참고 값은 이름에서 뜻이 드러나게** 쓴다. "직원 수"가 아니라 "국민연금 가입자". 3층에 이유를 쓴다.
6. **추정**은 3층에 근거를 쓴다. 예: "Liner 웹 검색 자료 25건을 모델이 정리했습니다."
7. **직접 입력**은 3층에 원래 분석 값과 그 상태·출처를 쓰고 "분석 값으로 되돌리기" 단추를 둔다.
8. **출처 줄**: 화면에는 두 부분으로 쓴다. 앞: "{기관·자료 이름} ({자료 종류})", 뒤(작게): "{기준일}"과 연결·별도 같은 기준. 복사·인쇄·화면 읽기 프로그램에는 설계 문서의 형식 그대로 한 줄로 낸다: "{기관·자료 이름} ({자료 종류}) · {기준일}". 원문 주소가 있으면 출처 줄 끝에 링크 "원문 열기"(새 창).
   - 예(가짜 기준일): "금융위원회 요약재무제표 (공공 API)" / "2022 사업연도, 별도"
9. **근거 문장**은 원문 그대로 따옴표 안에 쓰고 3층에만 둔다. 3줄을 넘으면 3줄까지 보이고 "전체 보기"로 나머지를 연다(같은 3층 안의 이어 보기).
10. **상태 안내**: 회사 분석 화면의 핵심 값 아래 펼치기 줄 "상태 표시 안내". 펼치면 위 표의 7줄. 3층으로 열린 출처 상자에도 그 값의 상태 뜻 한 줄을 쓴다.
11. 상태는 색만으로 구분하지 않는다. 언제나 낱말이 보인다.

**3층 출처 상자 내용(순서)**: 상태 낱말과 뜻 한 줄 → 출처 줄 → (있으면) 근거 문장 → (있으면) 메모(예: 국민연금 설명) → (엇갈림이면) 다른 값과 그 출처 → (직접 입력이면) 원래 분석 값과 "분석 값으로 되돌리기".

### 1.4 펼치기 부품

세 가지 모양만 쓴다.

| 부품 | 쓰는 곳 | 닫힌 문구 | 열린 문구 |
|---|---|---|---|
| 펼치기 줄 | 2층 열기 | "{무엇} {n}건 보기", "{무엇} 보기" | "{무엇} 접기" |
| 더 보기 단추 | 2층 안에서 이어 보기 | "{k}건 더 보기 ({남은 수}건 남음)" | (마지막이면 사라짐) |
| 줄 자세히 | 3층 열기 | 줄 전체가 단추. 문구 없음 | 같은 줄을 다시 누르면 닫힘 |

- 펼치기 줄은 가로 전체를 누를 수 있고 높이 44px 이상, 오른쪽에 여닫음 표시(돌아가는 꺾쇠 등)를 둔다. 문구 끝에 "→" 같은 기호를 붙이지 않는다.
- `aria-expanded`(열림 여부)와 `aria-controls`(여는 영역)를 단다. Enter·Space로 연다. 열고 닫아도 초점은 그 줄에 남는다.
- 더 보기를 누르면 새로 나온 첫 항목으로 초점을 옮긴다.
- 펼친 내용은 접어도 화면에서 숨기기만 한다(지우지 않는다). 진행 중인 유료 작업과 받은 결과를 지키기 위해서다(지금 펀딩노트 코드와 같음).
- 펼칠 때 위쪽 내용의 화면 위치는 그대로 두고 아래로 연다.
- 같은 방문 안에서 다른 단계에 다녀와도 펼친 상태를 유지한다. 새로고침하면 처음 상태다. 화면을 가로·세로로 돌려도 유지한다.
- 움직임은 0.2초 안으로 짧게. 움직임 줄이기 설정이면 움직이지 않는다.
- 0건이면 펼치기 줄을 만들지 않는다(빈 문구나 미확보를 쓴다). 항목 수가 1층 개수 이하이면 펼치기 줄 없이 1층에 다 보인다.
- 단락 전체를 접는 부품은 두지 않는다. 단락은 늘 1층이 보인다.

### 1.5 단락 틀 (회사 분석의 5단락 공통)

```
┌ 단락 머리 ───────────────────────────────────────────┐
│ 단락 이름(h2)  [상태]                [단락 메뉴(있으면)] │
│ 한 줄 요약 (완료되면) / 진행 문구 (확인 중이면)           │
├ 1층 ────────────────────────────────────────────────┤
│ 핵심 몇 개                                            │
│ 펼치기 줄 …                                           │
├ 단락 바닥 ───────────────────────────────────────────┤
│ 묶음 출처 줄                                          │
│ 이어지는 곳 한 줄 (정한 단락만)                          │
└─────────────────────────────────────────────────────┘
```

**단락 상태와 문구**

| 서버 상태 | 머리 표시 | 몸 |
|---|---|---|
| `waiting`, `running` | "확인 중 ({경과}초)" + 같은 줄 뒤에 작은 글 "보통 {예상} 안에 끝납니다"(한 줄 요약과 같은 높이) | 1층과 같은 높이의 자리 표시(회색 줄). 글자는 넣지 않는다 |
| (경과가 예상의 2배 초과) | 위에 더해 "평소보다 오래 걸립니다. 다른 단락을 먼저 보셔도 됩니다." | 같음 |
| `done` | 한 줄 요약 | 1층 |
| `partial` | 한 줄 요약 + "일부 자료를 얻지 못했습니다: {사유}" | 받은 것만 1층. 못 받은 부분은 그 자리에 "미확보: {사유}" |
| `unavailable` | "미확보" | 사유 문장 한 줄 + (있으면) 행동 단추 |
| `idle`(열 때 실행, 아직 안 함) | (단락 안의 열 때 실행 블록, 1.6절) | |

- 단락 순서는 언제나 개요, 재무·고용, 투자, 최근 동향, 기술이다(경쟁사는 2026-11-23부터 경쟁사 분석 화면, 4B절). 도착 순서로 바꾸지 않는다.
- 자리 표시의 높이는 1층이 채워졌을 때의 높이와 비슷하게 잡는다(차트 자리는 차트 높이 그대로). 위 단락이 채워져도 지금 보고 있는 글이 밀리지 않게 한다(브라우저의 스크롤 고정을 끄지 않는다).
- 단락 하나가 끝날 때마다 화면 읽기 프로그램에 한 번 알린다(`aria-live="polite"`, 화면에 하나): "{단락 이름} 단락이 준비됐습니다." / "{단락 이름} 단락은 미확보로 끝났습니다." 모두 끝나면 "회사 분석이 끝났습니다."
- 확인 중인 단락에는 `aria-busy="true"`.

**미확보 사유 문구** (서버 오류 코드 → 문장)

| 코드 | 문장 | 행동 |
|---|---|---|
| `daily_limit` | "오늘 호출 상한에 닿아 이 단락을 확인하지 못했습니다. 내일 0시 이후에 다시 분석할 수 있습니다." | "이 단락 다시 분석" 비활성 + "내일 다시 시도할 수 있습니다" |
| `section_limit` | "이 단락에 정한 호출 수 안에서 자료를 다 확인하지 못했습니다." | 없음(대개 `partial`과 함께) |
| `no_corp` | "법인이 확인되지 않아 공식 재무·고용 자료가 없습니다." | "법인 다시 고르기"(회사 확정으로) |
| `no_data` | 단락별 문장(각 단락 절) | 없음 |
| `upstream_error` | "{자료 이름}에서 응답을 받지 못했습니다." | "이 단락 다시 분석" |
| `timeout` | "정한 시간 안에 응답이 오지 않았습니다." | "이 단락 다시 분석" |
| `interrupted` | "분석이 중간에 멈췄습니다." | "이 단락 다시 분석" |
| `missing_config` | "이 자료를 쓰는 설정이 되어 있지 않습니다." | 없음 |

- "이 단락 다시 분석"은 서버가 기본 단락 다시 실행을 지원할 때만 보인다(`data-needs.md` 7절). 누르면 1.7절의 단락 확인 창.
- 오류 문장에 내부 경로, 예외 내용, 키 이름을 넣지 않는다.

### 1.6 열 때 실행 블록 (논문, 경쟁사 비교 자료)

- 실행 전: 제목, 설명 한 줄, 단추 "{동사}하기", 비용 줄 "보통 {n}초, Liner {m}회". 예상 시간을 서버가 주지 않으면 "Liner 약 {m}회"만 쓴다(실측 전 값을 추측해 쓰지 않는다).
- 조건이 안 됐으면 단추 비활성 + 이유 한 줄(각 단락 절).
- 실행 중: 블록 자리에 "확인 중 ({경과}초)". 다른 화면으로 가도 계속된다.
- 끝나면 블록이 결과 1층으로 바뀌고 머리 오른쪽에 "{MM-DD HH:mm} 실행". 결과 바닥에 "다시 실행"(1.7절 확인 창을 거친다).
- 유료 호출은 단추를 누를 때만 한다. 화면을 열거나 펼치기만으로는 부르지 않는다.

### 1.7 새로 분석 확인 창

**회사 전체**

- 제목: "새로 분석할까요?"
- 본문(목록)
  - "{회사 이름} 분석을 처음부터 다시 합니다."
  - "걸리는 시간: 3분 안팎 (공식 자료는 10초 안에 먼저 보입니다)"
  - "Liner 호출: 약 19회 (검색, 모델 같은 유료 호출)"
  - "지금 분석({분석 시각})은 지우지 않고 남깁니다."
  - "고친 값, 담은 항목, 노트는 그대로 둡니다."
  - (서버가 하루 남은 횟수를 주면) "이 회사는 오늘 {n}번 더 새로 분석할 수 있습니다."
- 단추: "새로 분석"(주), "취소". 창이 열리면 초점은 "취소"에 둔다. Esc는 취소.
- 하루 횟수를 다 썼으면: 본문 첫 줄을 "이 회사는 오늘 새로 분석할 수 있는 횟수를 다 썼습니다. 내일 다시 시도하세요."로 바꾸고 "새로 분석"을 비활성, "취소" 대신 "닫기".
- 시간·호출 수는 서버가 주는 예상값(`estimates`)을 쓰고, 없을 때만 위 값을 쓴다.

**새로 분석이 진행되는 동안**: 지금 결과를 지우지 않는다. 단락 머리에 "새로 확인 중 ({경과}초)"를 붙이고, 새 결과가 오면 그 단락만 바꾼다. 새 결과가 미확보로 끝나면 이전 결과를 그대로 두고 단락 바닥에 "이 단락은 {이전 분석 시각} 분석 결과입니다. 새 분석에서는 {사유}"를 쓴다.

**단락만 새로**(뉴스, 그리고 미확보로 끝난 단락)

- 제목: "{단락 이름}만 새로 받을까요?" (뉴스는 "뉴스만 새로 받을까요?")
- 본문: "걸리는 시간: {n}초 안팎", "Liner 호출: 약 {m}회", "다른 단락은 그대로 둡니다."
- 단추: "{단락 이름} 새로 받기"(뉴스는 "뉴스 새로 받기"), "취소".
- 다시 받은 단락은 단락 바닥에 자기 분석 시각을 쓴다: "{MM-DD HH:mm}에 새로 받음".

**열 때 실행 다시 실행**: 제목 "{블록 이름} 다시 실행"(예: "경쟁사 비교 자료 다시 실행"), 본문 "Liner 약 {m}회를 다시 씁니다. 지금 결과는 새 결과로 바뀝니다.", 단추 "다시 실행", "취소".

- 문구에 회사 이름이나 블록 이름 뒤 조사(을/를, 이/가)를 붙이지 않는다. 받침에 따라 틀리기 쉬워서다.

### 1.8 회사 정보 수정 창

**목적**: 분석 값을 사용자가 고치고, 공개 자료에 없는 내부 정보(필요한 자금, 인증, 체납 등)를 넣는다.

- 넓은·중간: 오른쪽에서 열리는 패널. 좁은: 화면 전체를 덮는 창.
- 제목: "회사 정보 수정"
- 제목 아래 한 줄: "자격 대조와 운용사 요약에 쓰는 정보입니다. 필요한 자금이나 인증처럼 공개 자료에 없는 정보도 넣을 수 있습니다."
- 안내: "고친 값은 이 브라우저에만 저장됩니다. 공고문 자격 대조나 운용사 요약을 실행할 때만 분석 서버로 보냅니다."
- 칸(순서)

| 칸 이름 | 입력 | 예시 문구(placeholder) | 분석 값 |
|---|---|---|---|
| "지역" | 고르기(시·도 17) | — | 있음 |
| "기업 유형" | 고르기: "창업·벤처기업", "중소기업", "소상공인" | — | 있으면 |
| "설립 연월" | 연월 | — | 있음 |
| "업종" | 글 | "예: 소프트웨어 개발 및 공급업" | 있음 |
| "직원 수" | 글 | "예: 12명" | 있으면(보도) |
| "최근 연매출" | 글 | "예: 8억 원" | 있음 |
| "필요한 자금" | 글 | "예: 운전자금 3억 원(인건비)" | 없음 |
| "그 밖의 사항" | 여러 줄 | "예: 벤처기업 확인, 기존 대출 없음, 세금 체납 없음" | 없음 |

- 칸마다 아래 작은 글: "분석 값: {값} ({상태 낱말}, {출처 짧게})" 또는 "분석 값 없음". 엇갈림이면 두 값을 모두 쓴다.
- "직원 수" 아래 한 줄 더: "국민연금 가입자 수({n}명)는 상시근로자 수와 다릅니다."
- 고친 칸에는 "직접 입력"과 "분석 값으로 되돌리기"가 붙는다.
- 창 아래 안내: "비워 둔 칸은 자격 대조에서 '확인 필요'로 나옵니다. 확인된 특허 수와 국민연금 가입자 수는 대조할 때 함께 보냅니다."
- 단추: "저장"(주), "취소". 맨 아래 작은 단추 "고친 값 모두 되돌리기" → 그 자리에서 묻기: "고친 값 {n}개를 분석 값으로 되돌릴까요?" + "되돌리기", "취소".
- 저장하면 창이 닫히고 알림 "회사 정보를 저장했습니다." 이미 끝난 자격 대조가 있으면 알림 둘째 줄: "자격 대조 {n}건은 이전 회사 값으로 한 결과입니다. 심사 준비에서 다시 대조할 수 있습니다." 이전 대조 결과는 지우지 않는다(6.1절).
- 저장하지 않고 닫으려 하면: "고친 내용을 저장하지 않고 닫을까요?" + "닫기", "계속 고치기".
- 접근성: 창이 열리면 첫 칸으로 초점, 닫히면 창을 연 "회사 정보 수정" 단추로 초점을 돌린다. 창 밖으로 초점이 나가지 않는다.

### 1.9 담기와 담은 항목 막대

- 공고·운용사·판로 지원사업 카드의 단추: "담기". 담으면 "담음"으로 바뀌고 다시 누르면 뺀다(`aria-pressed`). 화면 읽기 프로그램용 이름: "심사 준비로 담기: {제목}".
- 입찰공고(나라장터)는 심사 준비 대상이 아니라 "노트에 담기" / "노트에 담음".
- 담은 항목 막대: 자금 조달 화면(판로 갈래 포함) 아래에 붙는다. 1개 이상 담으면 나타난다. 문구: "담은 항목 {n}개" + 단추 "심사 준비로 가기". 막대가 마지막 카드를 가리지 않게 화면 아래 여백을 둔다.
- 담을 때 알림 창을 띄우지 않는다. 단추 모양과 막대 숫자가 바뀌고, 화면 읽기 프로그램에 "담았습니다. 담은 항목 {n}개"를 알린다.

### 1.10 공통 알림 문구

| 상황 | 위치 | 문구 | 행동 |
|---|---|---|---|
| 진행 상황 묻기가 연속 5번 실패 | 화면 위 띠 | "분석 서버와 연결이 끊겼습니다. 다시 연결되면 이어서 받습니다." | "다시 연결" |
| 분석 서버가 꺼짐(시작 화면) | 입력 아래 | "지금은 분석 서버에 연결할 수 없습니다. 잠시 뒤 다시 시도하세요. 자금 둘러보기는 그대로 쓸 수 있습니다." | — |
| 서버가 다시 시작돼 작업이 사라짐 | 화면 위 띠 | "분석이 중간에 멈췄습니다. 받은 단락은 그대로 두었습니다." | "멈춘 단락 다시 분석" |
| 접속 주소별 요청 제한 | 누른 단추 아래 | "요청이 잠시 많았습니다. 1분 뒤 다시 눌러 주세요." | — |
| 브라우저 저장소를 쓸 수 없음(시크릿 창 등) | 화면 위 띠, 방문마다 한 번 | "이 브라우저에서는 고친 값과 담은 항목을 저장할 수 없습니다. 창을 닫으면 사라집니다." | "닫기" |
| 브라우저 저장 공간 부족 | 화면 위 띠 | "브라우저 저장 공간이 부족해 이 회사 사본을 저장하지 못했습니다. 분석 결과는 서버에서 다시 받을 수 있습니다." | "닫기" |

- 오류 문장은 사과하지 않고, 무슨 일이 있었고 무엇을 하면 되는지 쓴다.

### 1.11 바닥글

- 모든 화면: "점수나 선정 확률은 만들지 않습니다. 값마다 확인 상태와 출처를 붙입니다."
- 이 문장 말고는 화면 어디에도 "점수", "확률"이라는 낱말을 쓰지 않는다.

### 1.12 목록 줄 (2026-11-23 가독성 조정)

**목적**: 공고·운용사·입찰공고 목록을 위에서 아래로 훑을 때 기한과 상태를 같은 자리에서 읽게 한다.

- 쓰는 곳: 자금 조달 공고 카드·운용사 카드(5절), 자금 조달 판로 갈래의 입찰공고 줄과 판로 지원사업 카드(5.2절), 심사 준비 담은 공고 카드(6.1절), `/funding` 카드.
- 왼쪽: 분류 꼬리표 줄(종류·지역·"회사 사업과 관련" 같은 표시), 이름(제목), 부가 정보(지원 내용, 기관, 대표 펀드, 수요기관·금액).
- 오른쪽 끝 칸: 기한이나 상태. 카드마다 같은 오른쪽 위치에 맞춘다.
  - 접수 중 공고·진행 중 입찰공고: 큰 줄 "D-{n}"(또는 "오늘 마감"), 그 아래 작은 줄 "{M.D} 마감". 7일 안이면 더 굵게(색은 바꾸지 않는다). 화면 읽기와 복사에는 지금처럼 "D-{n}, {M.D} 마감" 한 덩어리로 읽힌다.
  - 접수 예정: 큰 줄 "{M.D}", 작은 줄 "접수 시작". 남은 날이 없는 글("상시 접수", "신청기간 미기재", "입찰 예정 {M.D}", "입찰 마감")은 보통 크기 한 줄.
  - 운용사: 표시("이미 투자함", "경쟁사에 투자")를 위에, "최근 결성 {YYYY}년"을 아래에.
- 문구는 바꾸지 않는다. 기존 "D-{n}, {M.D} 마감"을 쉼표에서 두 줄로 나눠 보일 뿐이다.
- **좁은 화면(640px 미만)**: 오른쪽 끝 칸을 분류 꼬리표 줄 끝으로 올려 한 줄("D-12  12.31 마감")로 둔다. 제목이 카드 전체 폭을 쓴다. 넘치면 꼬리표 줄 안에서 줄을 바꾼다(가로 넘침 없음).

## 2. 시작 (`/`)

**목적**: 회사 이름 하나로 분석을 시작하게 한다.

### 1층

- 제목(h1): "우리 회사를 객관적으로 분석합니다"
- 설명 한 줄: "회사 이름 하나로 공공 자료와 공개 보도를 모아 분석하고, 받을 수 있는 자금, 심사 준비, 판로까지 잇습니다."
- 입력: 보이는 이름표 "회사 이름", 예시 문구 "예: 주식회사 가나다". 단추 "분석 시작".
- 입력 아래 작은 단추 "홈페이지 주소도 넣기 (선택)" → 누르면 그 자리에 입력 "홈페이지 (선택)", 예시 문구 "예: https://example.co.kr", 안내 "같은 이름의 다른 회사와 구별하는 데 씁니다."
- 시간 안내 한 줄: "공식 자료는 10초 안에 보이고, 나머지는 준비되는 대로 채웁니다. 전체는 3분 안팎입니다."
- 이어서 보기(이 브라우저에 본 회사가 있을 때만): 제목 "이어서 보기", 최근 연 순서로 최대 3줄. 한 줄 = 회사 이름, "{YYYY-MM-DD HH:mm} 분석"(30일 초과면 "오래된 분석"), 담은 항목이 있으면 "담은 항목 {n}개". 줄 전체를 누르면 그 회사 분석으로 간다.
- 두 링크: "예시 회사로 보기"(서버에 예시 분석이 있을 때만), "회사 없이 자금만 둘러보기".

### 2층

- "이어서 보기" 4곳 이상이면 펼치기 줄 "모두 보기 ({n})" → 최대 20줄. 이때만 줄마다 "지우기" 단추가 보인다. 누르면 그 자리에서 묻기: "이 회사의 고친 값, 담은 항목, 노트를 이 브라우저에서 지울까요? 서버에 있는 분석은 남습니다." + "지우기", "취소".
- 펼치기 줄 "어떤 자료로 분석하나요?" → 목록
  - "금융위원회 기업기본정보, 요약재무제표 (공공 API)"
  - "국민연금공단 사업장 가입자 (공공 API)"
  - "기업마당 지원사업 (공공 API)"
  - "한국벤처투자 모태펀드 현황 (공공 API)"
  - "조달청 나라장터 입찰공고 (공공 API)"
  - "특허 공개 원문 (Google Patents)"
  - "뉴스 (NAVER 뉴스 검색)"
  - "Liner 검색과 모델"
  - 아래 한 줄: "근거가 없는 값은 만들지 않고 '미확보'로 둡니다."

### 동작과 결과

| 동작 | 결과 |
|---|---|
| 이름 2글자 미만으로 "분석 시작" 또는 Enter | 입력 아래 "회사 이름을 2글자 이상 넣어 주세요." 초점은 입력에 |
| 이름 넣고 "분석 시작" | 단추가 "법인 찾는 중"으로 바뀌고 비활성(1~2초). 결과에 따라 회사 확정(3절)으로 가거나 바로 회사 분석으로 |
| 이어서 보기 줄 | `/c/[id]`. 브라우저 사본을 바로 보여 준다 |
| "예시 회사로 보기" | `/c/[예시 id]`. 서버에 저장된 분석을 연다. 새 분석은 하지 않는다 |
| "회사 없이 자금만 둘러보기" | `/funding` |

### 상태

- 분석 서버 꺼짐: 입력은 쓸 수 있고 "분석 시작"은 비활성. 입력 아래 1.10절 문구. "예시 회사로 보기"는 숨기고 "회사 없이 자금만 둘러보기"는 둔다.
- 법인 검색 실패(금융위 연결 오류): 입력 아래 "금융위원회 자료에 연결하지 못했습니다. 다시 시도하거나, 법인 확인 없이 공개 자료만으로 분석할 수 있습니다." + "다시 시도", "공개 자료만으로 분석".
- 이어서 보기가 없으면 그 제목도 만들지 않는다.

### 배치

- 좁은: 위에서 아래로 한 줄씩. 입력과 단추는 세로로 쌓고 단추는 가로 전체.
- 중간·넓은: 입력과 단추를 한 줄에. 글 줄 길이는 한글 40자 안팎(약 640px)을 넘지 않게. 왼쪽 정렬.

### 접근성

- 입력에 보이는 이름표를 연결한다(예시 문구만으로 이름을 대신하지 않는다). 오류 문장은 `aria-describedby`로 입력에 묶고 `role="alert"`.
- "법인 찾는 중"은 `aria-live="polite"`로 알린다.

## 3. 회사 확정 (`/?name={이름}`)

**목적**: 같은 이름의 법인 중 분석할 회사를 골라, 뒤의 모든 조회가 같은 회사를 보게 한다.

### 1층

- 제목(h1): "어느 회사인가요?"
- 설명: "금융위원회 기업기본정보에서 찾은 법인 {n}곳입니다. 분석할 회사를 고르세요."
- 후보 목록(하나만 고르는 목록), 최대 5곳. 한 줄 =
  - 법인 이름(굵게). 넣은 이름과 같으면 "이름이 같음".
  - 이름표와 값 3쌍: "대표" {이름}, "설립" {YYYY-MM-DD}, "본사" {시·도 시·군·구}.
  - 서버에 저장된 분석이 있으면 "저장된 분석 있음 ({YYYY-MM-DD})".
- **이름이 같은 후보가 여럿일 때**(법인 표기 "주식회사"·"(주)"·띄어쓰기를 뺀 이름이 같은 후보가 2곳 이상, 계약 2.1절): 그 후보들에만 구분 정보를 더 보인다. 다른 후보는 위처럼 간결하게 둔다.
  - "대표", "설립" 다음에 "사업자번호" {000-00-00000}(시·군·구 "본사" 대신).
  - 다음 줄 "본사" {건물까지 나온 주소 전체}. 긴 주소는 줄을 바꾼다.
  - 이전 이름이 있으면 다음 줄 "이전 이름" {옛 이름} · {YYYY-MM} 변경(바뀐 날을 모르면 이름만, 여럿이면 최근 것부터 쉼표로). 이력이 없거나 확인하지 못했으면 이 줄을 두지 않는다.
  - 예: 합병 때 존속법인이 옛 이름이었고 이름만 바꾼 법인은 대표·시군구가 같아도 "이전 이름 주식회사 라마바코리아 · 2024-12 변경"으로 가른다.
- 마지막 선택지: "목록에 없음" + 설명 "법인 등록 전이거나 이름이 다른 경우입니다. 공식 재무·고용 자료 없이 공개 자료로만 분석합니다."
- 단추: "이 회사로 분석"(고르기 전 비활성). 고른 회사에 저장된 분석이 있으면 단추 문구가 "저장된 분석 보기". 옆에 "이름 다시 넣기"(시작 화면, 이름이 채워진 채로).

### 2층

- 후보가 5곳을 넘으면 펼치기 줄 "후보 {n}곳 더 보기".

### 미리 고르기와 건너뛰기

- 이름이 정확히 같은 후보가 1곳이면 그 후보를 미리 고른다. 2곳 이상이면 미리 고르지 않는다.
- 후보가 1곳이고 이름이 정확히 같으면 이 화면을 건너뛰고 회사 분석으로 간다(설계 문서 3.2).

### 상태

- 후보 0곳: 제목 "법인을 찾지 못했습니다", 설명 "'{이름}' 이름의 법인이 금융위원회 기업기본정보에 없습니다. 이름이 다르면(주식회사 포함, 영문 이름 등) 다시 넣어 보세요." 단추 "공개 자료만으로 분석", "이름 다시 넣기".
- "이 회사로 분석"을 누르면 단추가 "분석을 시작하는 중"으로 바뀌고, 작업이 시작되면 `/c/[id]`로 간다. 시작 요청이 실패하면 단추 아래 오류 문장(1.10절 또는 서버가 준 사용자용 문장).

### 배치

- 좁은: 목록은 가로 전체. "이 회사로 분석" 단추는 화면 아래에 붙는다.
- 중간·넓은: 폭 약 640px, 단추는 목록 바로 아래.

### 접근성

- 목록은 `role="radiogroup"`, 화살표 키로 옮기고 Space로 고른다. 한 줄 전체가 고르는 영역이고 높이 56px 이상.
- 각 선택지의 화면 읽기 이름에 법인 이름, 대표, 설립, 본사를 모두 넣는다. 이름이 같은 후보는 사업자번호, 본사 전체 주소, 이전 이름(있을 때)도 넣는다.

## 4. 회사 분석 (`/c/[id]`)

**목적**: 회사를 객관적으로 보여 주는 중심 화면. 결정에 필요한 숫자를 먼저 보이고, 단락은 준비되는 대로 채운다.

### 4.0 화면 틀

**위에서 아래로**: 머리줄·단계 메뉴 → 회사 표시줄 → (진행 중이면) 진행 줄 → 핵심 값 4개 → (셀 것이 있으면) "지금 확인할 것"(4.0.3) → 자금 후보 줄 → "상태 표시 안내"(펼치기 줄) → 단락 5개 → 경쟁사 분석 줄.

**단락 목차**

- 넓은: 왼쪽에 붙는 목차 5줄(개요, 재무·고용, 투자, 최근 동향, 기술). 줄마다 상태 글: "확인 중", "준비됨", "일부 미확보", "미확보". 누르면 그 단락으로 스크롤하고 초점을 단락 제목으로 옮긴다.
- 중간·좁은: 단계 메뉴 바로 아래에 붙는 가로 한 줄(칩 5개, 넘치면 가로로 밀기). 상태는 칩 안의 작은 표시와 화면 읽기 이름("투자, 확인 중")으로.
- 지금 화면에 보이는 단락을 목차에 표시한다.
- 단락 주소 조각: `#overview`, `#finance`, `#investment`, `#news`, `#tech`. 주소에 조각이 있으면 그 단락으로 바로 간다. 옛 조각 `#rivals`(옛 경쟁사 단락)로 열면 경쟁사 분석(`/c/[id]/rivals`)으로 보낸다(기록에 쌓지 않는다).

**경쟁사 분석 줄**(2026-11-23 화면 구조 개편): 기술 단락 아래, 단락과 같은 잉크 1px 윗줄 아래 한 줄. 경쟁사 단락은 경쟁사 분석 화면(4B절)으로 옮겼고 여기에는 그 입구만 둔다.

- 후보를 받았으면: "국내 경쟁사 후보 {n}곳, 고른 곳 {k}곳" + 링크 "경쟁사 분석에서 보기". 고른 곳이 0이면 ", 고른 곳 0곳"을 빼지 않는다(무엇을 할 차례인지 알리게).
- `profile` 확인 중: "국내 경쟁사 후보 확인 중" + 같은 링크. 글이 한 줄이라 후보가 와도 높이가 바뀌지 않는다.
- `profile` 미확보: "국내 경쟁사 후보 미확보" + 같은 링크(직접 넣기는 경쟁사 분석에서 한다).

**진행 줄**(분석 진행 중에만)

- "분석 중 ({경과}). 다른 화면으로 가도 분석은 계속됩니다."
- 둘째 줄: "아직 확인 중: {단락과 부분 이름들}". 예: "아직 확인 중: 투자(원문 확인 투자자), 개요(직원 수), 경쟁사 분석(후보 추가)". 단락은 회사 분석의 5단락이고, `facts`가 경쟁사 후보를 더 찾는 동안은 "경쟁사 분석(후보 추가)"를 붙인다(화면은 따로지만 이 분석 작업의 일부다). **한 줄로 자르고 넘치면 말줄임**(목록 길이에 따라 줄 수가 바뀌어 아래가 밀리지 않게. 같은 내용이 단락마다 "확인 중"으로 있다).
- 진행 줄은 높이가 정해진 자리다(넓은 화면 두 줄, 좁은 화면 세 줄). 화면 읽기 알림 영역이 아니다(경과 초를 매초 읽지 않게, 단락 준비·분석 끝은 알림 영역이 한 번씩 알린다).
- 모두 끝나면 진행 줄이 같은 자리·같은 높이의 "분석이 끝났습니다."와 "닫기"로 바뀌고(이 화면에서 진행을 본 경우), 회사 표시줄에 분석 시각이 나온다. 사라지며 아래가 올라붙지 않게 한다(실제 서버 검증, 2026-11-23).
- 끝났을 때 미확보 단락이 있으면 그 자리에 "분석이 끝났습니다. 미확보 단락 {n}개"를 남긴다. 이 줄을 누르면 첫 미확보 단락으로 가고, "닫기"로 닫을 수 있다.

**저장된 분석을 열 때**: 진행 줄 없음. 모든 단락이 곧바로 채워진다. 회사 표시줄에 분석 시각.

**분석한 적 없는 회사 주소를 직접 열 때**(브라우저 사본도, 서버 분석도, 진행 중 작업도 없음): 자동으로 분석하지 않는다. 회사 표시줄 아래 상자: "아직 분석하지 않은 회사입니다." + 단추 "분석 시작" + 작은 글 "보통 3분, Liner 약 19회".

### 4.0.1 단락이 도착하는 순서 (기준 기업 실측, 설계 문서 6.5)

| 시점 | 도착하는 서버 단락 | 화면에서 바뀌는 곳 |
|---|---|---|
| 0초 | `identity`(회사 확정에서 이미 받음) | 회사 이름. 모든 단락 자리 표시와 "확인 중" |
| 약 10초 | `official` | 표시줄의 지역·업력 칩, 핵심 값 매출·국민연금 가입자, 개요의 대표·설립·본사, 재무·고용 단락 전체, 단계 메뉴 "자금 조달" 열림 |
| 약 22초 | `profile` | 개요의 사업 설명·제품·핵심 기술, 경쟁사 분석 줄과 경쟁사 분석 화면의 후보, 판로 검색어 |
| 약 27초 | `funding_history` | 투자 단락, 핵심 값 누적 투자 |
| 약 31초 | `patents` | 기술 단락(특허), 핵심 값 국내 특허 |
| 약 40초 | `news` | 최근 동향 단락 |
| 약 144초 | `facts` | 개요의 직원 수와 설립 엇갈림, 재무·고용의 웹 조사 매출, 투자의 원문 확인 투자자, 경쟁사 분석 화면의 후보 추가 |

**한 단락이 여러 서버 단락으로 채워질 때**: 단락의 "준비됨"은 주된 서버 단락이 끝났을 때 붙인다. 주된 서버 단락: 개요=`profile`, 재무·고용=`official`, 투자=`funding_history`, 최근 동향=`news`, 기술=`patents`(경쟁사 분석 화면의 후보도 `profile`). `facts`가 채울 부분은 그 자리에 "확인 중" 한 줄을 미리 두고, 도착하면 그 줄만 바뀐다. 이미 보이는 목록에 항목이 더해지면 목록 끝에 붙이고 "추가됨"을 이번 방문 동안 붙인다. 사용자가 펼쳐 둔 영역은 닫지 않는다. 자금 조달 조건처럼 사용자가 이미 본 조건은 자동으로 바꾸지 않는다(5절).

### 4.0.2 핵심 값 4개

회사 표시줄에 있는 값(지역, 업력, 기업 유형)은 싣지 않는다. 같은 내용을 두 번 보이지 않기 위해서다.

| 칸 | 큰 값 | 작은 글 | 상태 | 없을 때 |
|---|---|---|---|---|
| 매출 | "{n}억원" | "{YYYY} 사업연도, {연결/별도}" | 원문 확인 | 공식 값 없고 웹 조사 값 있으면 그 값과 "보도". 둘 다 없으면 "미확보: 공식 재무 자료 없음" |
| 국민연금 가입자 | "{n}명" | "{YYYY-MM}, 12개월 전보다 {+n/−n}명" | 참고 | "미확보: 국민연금 사업장을 찾지 못함" |
| 누적 투자 | "{통화 금액}"(통화별로 따로) | "라운드 {n}건, 최근 {YYYY-MM} {단계}" | 보도 | 누적액 없고 라운드만 있으면 큰 값 "라운드 {n}건". 둘 다 없으면 "미확보: 투자 라운드 자료 없음" |
| 국내 특허 | "{n}건" | "출원인 확인, 등록 {r}건" | 원문 확인 | "미확보: 출원인이 확인된 특허를 찾지 못함" |

- 매출 칸에 웹 조사 값(보도)도 있으면 작은 글 아래 한 줄 "웹 조사: {값} 보도"를 더한다(설계 문서 6.5, 두 값을 나란히).
- 칸 전체가 그 단락으로 가는 링크다. 칸 안의 상태 낱말은 누를 수 없는 글이다(링크 안에 단추를 겹치지 않는다). 출처는 단락의 묶음 출처 줄에 있다.
- 확인 중이면 칸에 자리 표시와 "확인 중".
- 누적 투자가 여러 통화면 "$124.0M"과 "300억원"처럼 따로 쓰고 더하지 않는다(예시는 가짜 값).

**자금 후보 줄**: "이 회사 값으로 받을 수 있는 자금 후보를 찾습니다." + 단추 "자금 후보 보기"(→ `/c/[id]/funding`). 공식 자료 전에는 단추 비활성 + "공식 자료를 받으면 열립니다".

**배치**: 넓은 4칸 한 줄, 중간 2칸×2줄, 좁은 2칸×2줄(칸 안 글은 두 줄까지).

### 4.0.3 지금 확인할 것 (2026-11-23 가독성 조정)

**목적**: 첫 화면에서 "이 회사에서 내가 먼저 손볼 것"을 사실의 개수로 모아 보이고, 누르면 그 자리로 보낸다. 점수·확률·준비도가 아니다.

- 위치: 핵심 값 4칸 바로 아래, 자금 후보 줄 위. 옅은 회색 바탕의 한 덩어리.
- 제목: "지금 확인할 것"(작은 굵은 글). 그 아래 항목 단추가 한 줄로 이어지고 넘치면 줄을 바꾼다.

| 항목 | 화면 글 | 세는 것 | 누르면 |
|---|---|---|---|
| 엇갈린 값 | 상태 낱말 "엇갈림" + "값 {n}개" | 합친 회사 값(`merged`) 가운데 상태가 `conflicting`인 값. 대상은 지역, 본사, 대표, 설립, 업종(금융위·웹 조사), 직원 수, 매출(공식·웹 조사), 국민연금 가입자, 국내 특허 — 미팅 근거 묶음 "미팅 전에 정리할 값"(6.2절)과 같은 셈 | 바로 아래에 목록이 펼쳐진다: 값 이름, 두 값과 짧은 출처(1.3절 규칙 3), 링크 "{단락 이름} 단락에서 보기" |
| 미확보 값 | 상태 낱말 "미확보" + "값 {n}개" | 같은 대상 가운데 상태가 `unavailable`인 값 | 같은 목록 모양: 값 이름, "미확보: {사유}", 단락 링크 |
| 마감 임박 담은 공고 | "마감 임박 담은 공고 {n}건" + 가장 가까운 "D-{d}"(0이면 "오늘 마감") | 이 브라우저에 담은 공고(판로 지원사업 포함) 가운데 마감일이 오늘부터 14일 안. 날 수(14일)는 자금 조달 빠른 거르기 "마감 임박(14일 내)"과 같지만, **아직 접수 전인 담은 공고도 센다**(자금 조달 거르기는 지금 접수 중인 공고 목록을 줄이는 것이라 접수 중만 본다. 여기는 이미 담은 공고를 놓치지 않게 하는 것이라, 접수가 곧 열리고 곧 닫히는 짧은 공고일수록 먼저 보여야 한다). 담을 때 저장한 마감일로 센다 | 심사 준비 정책자금·지원사업 갈래(`/c/[id]/review?tab=grants`) |
| 미충족 요건 | 판정 표시 "미충족" + "요건 {n}개" | 공고문 자격 대조를 끝낸 담은 공고의 "미충족" 줄 수(심사 준비 "부족한 요건"의 미충족과 같은 셈). 대조한 공고가 없으면 항목이 없다 | 심사 준비 정책자금·지원사업 갈래 |

- **0인 항목은 숨긴다. 끝난 분석을 열었을 때 네 항목이 모두 0이면 덩어리 전체를 그리지 않는다**(빈 덩어리나 "없음" 줄을 두지 않는다. 상태 낱말은 핵심 값과 단락에 그대로 있다).
- **화면이 밀리지 않게**(2026-11-23 Codex 리뷰 반영): 이 방문에서 분석(새로 분석 포함)이 진행 중이면 덩어리 틀을 먼저 두고 항목 줄에 "엇갈린 값·미확보 값은 분석이 끝나면 셉니다"를 쓴다. 끝나면 같은 자리에 항목이 들어오고, 셀 것이 없으면 "지금 확인할 것이 없습니다"로 둔다(이 방문 동안만. 다시 열면 위 규칙대로 그리지 않는다). 항목은 늘 한 줄이고 넘치면 옆으로 밀어 본다. 그래서 분석이 끝나는 순간 덩어리가 생기거나 사라지거나 두 줄로 늘어 아래 자금 후보 줄·단락이 밀리지 않는다.
- 회사 분석이 진행 중이면 엇갈린 값·미확보 값은 세지 않는다(값이 도착하며 수가 바뀌어 첫 화면이 흔들리지 않게). **새로 분석 중도 같다**: 화면은 저장된 분석 위에 새 결과를 얹어 보이므로, 진행 중인 새 작업이 있으면 세지 않는다. 담은 공고 두 항목은 진행 중에도 보인다.
- 같은 공고(수출·내수 공고는 자금 조달과 판로에 모두 나온다)를 두 화면에서 담았으면 한 건으로 센다. 심사 준비의 공고 목록·개수, 단계 메뉴의 심사 준비 개수도 같은 셈이다.
- 사용자가 "직접 입력"으로 고친 값도 원래 분석 값의 상태로 센다(미팅 근거 묶음과 같음). 고친 값은 그 줄에 "직접 입력"이 따로 보인다.
- 예시 회사에서도 같다(값은 저장된 분석, 담은 공고는 이 브라우저).
- 펼친 목록은 같은 방문 안에서 다른 단계에 다녀와도 열린 채로 둔다(1.4절과 같음, 새로고침하면 닫힘). 한 번에 한 항목의 목록만 열린다(다른 항목을 누르면 바뀐다). 분석(새로 분석 포함)이 진행되면 목록을 닫는다: 진행 중에는 값을 세지 않아 목록이 비고, 끝나는 순간 다시 펼쳐지면 아래가 밀리기 때문이다.
- 접근성: 값 항목은 단추(`aria-expanded`, `aria-controls`), 공고 항목은 링크. 제목은 h2. 인쇄에서는 빠진다.

### 4.1 개요 (`#overview`)

**목적**: 이 회사가 무엇을 하는 회사인지 한눈에.

**머리 요약**: 웹 조사 업종 한 줄(예: "AI 반도체 설계"). 없으면 금융위 업종, 둘 다 없으면 요약 줄 없음.

**1층**

1. 사업 설명: 처음 2줄만(넘치면 자름) + "더 읽기"(같은 자리에서 전체로). 문단 끝에 상태 낱말 "추정".
2. 기업 사실 4줄(이름표와 값): "대표", "본사"(시·도 시·군·구), "설립", "직원 수". 법인 확인으로 바로 정해지는 대표·본사를 위에, `facts`가 오며 바뀌는 설립(엇갈리면 두 값)·직원 수를 아래에 둔다(늦게 길어지는 줄이 위 줄을 밀지 않게). 줄마다 상태 낱말. 줄을 누르면 3층 출처 상자. 넓은 화면에서 개요 본문은 진행 중·끝난 뒤 모두 같은 최소 높이를 잡고, "기업 정보 더 보기"는 펼치기 줄 맨 앞에 둔다.
   - 대표·설립·본사는 `official`(원문 확인)로 10초 안에 채운다. 직원 수는 `facts`(보도)가 올 때까지 "확인 중".
   - 설립이 엇갈림이면 1.3절 규칙 3대로 두 줄.
3. 제품·서비스: 이름표 "제품·서비스 {n}개" + 이름 최대 3개(짧은 목록, 줄바꿈 허용).
4. 핵심 기술: 이름표 "핵심 기술" + 낱말 최대 4개.

**2층**

- "제품·서비스 {n}개 모두 보기": 이름과 설명 한 줄씩(3개 이하면 이 줄 없음).
- "핵심 기술 {n}개 모두 보기"(4개 이하면 없음).
- "기업 정보 더 보기": 법인 이름(전체), 영문 이름, 법인등록번호, 사업자등록번호, 홈페이지(링크), 상장 구분, 업종(금융위, 비어 있으면 "미확보: 공공 자료에 업종 없음"), 업종(웹 조사, 보도) — 업종은 둘 다 쓴다(설계 문서 4.1), 주소 전체, 금융위 자료 갱신일. 마지막에 "같은 이름의 다른 법인 {n}곳"과 단추 "다른 법인으로 바꾸기"(회사 확정으로).
- "회사 현황 메모 {n}개 보기": 모델이 정리한 현황 문장들(추정).
- "근거 자료 {n}건 보기": 제목, 날짜, "원문 열기".

**싣지 않는 것**: 기술 키워드(판로 검색어와 자금 조달 "회사 사업과 관련" 표시에서만 보인다), 기업 단계 추정, 관심 투자 분야 추정(자금 조달 조건 칩에서만 보인다), 별칭.

**묶음 출처 줄**: "추정. Liner 웹 검색 자료 {n}건을 모델이 정리" (사업 설명·제품·핵심 기술·현황 메모에 해당). 기업 사실은 줄마다 출처를 따로 연다.

**상태**: `profile` 미확보 → 사업 설명 자리에 "미확보: 사업 설명 자료를 찾지 못했습니다." 기업 사실은 따로 채운다. 법인 없음 → 대표·설립·본사는 `facts` 값(보도)이 있으면 그 값, 없으면 미확보. "기업 정보 더 보기"에 "법인 확인 안 함".

**배치**: 넓은·중간에서는 사업 설명(왼쪽 넓게)과 기업 사실(오른쪽 좁게) 두 칸. 좁은은 위아래.

### 4.2 재무·고용 (`#finance`)

**목적**: 매출과 이익, 고용의 흐름을 한눈에.

**머리 요약**(빈 값이 있으면 그 부분만 뺀다): "매출 {YYYY} 사업연도 {n}억원({구분}), 국민연금 가입자 {YYYY-MM} {n}명(12개월 {+n}명)".

**1층**

1. 재무 막대: 최근 3개 사업연도 매출과 영업이익. 아래 묶음 출처 줄 "원문 확인. 금융위원회 요약재무제표 (공공 API)" / "{YYYY}~{YYYY} 사업연도, {연결/별도}".
2. 국민연금 선: 최근 12개월 가입자 수. 차트 제목 "국민연금 가입자 수 (직원 수와 다릅니다)". 아래 묶음 출처 줄 "참고. 국민연금공단 사업장 가입자 (공공 API)" / "{YYYY-MM}~{YYYY-MM}".
3. (웹 조사 매출이 있으면) 한 줄 "웹 조사 매출: {값} 보도". 누르면 3층 출처 상자.

**2층**

- "재무 표 보기": 열은 사업연도 3개, 줄은 매출액, 영업이익, 당기순이익, 자산총계, 부채총계, 자본총계, 부채비율. 금액은 억원, 소수 첫째 자리. 열 머리에 연결·별도. 증가율·이익률은 서버가 준 값만 쓰고 없으면 "—"(화면에서 계산하지 않는다).
- "월별 가입자 표 보기": 12줄. 열은 월, 가입자 수, 신규 취득, 상실, 전월 대비.
- "어느 사업장 자료인가요?": 맞춘 사업장 이름과 사업자번호(가린 값), 서버 설명 문장, 그리고 "국민연금 가입자 수는 상시근로자 수와 다릅니다."
- "전체 연도 재무 {n}행 보기": 서버의 전체 연도 표가 3행보다 많을 때만.

**이어지는 곳**: 없음(핵심 값 아래 "자금 후보 보기"가 같은 역할).

**상태**

- 법인 없음: "미확보" + `no_corp` 문장 + "법인 다시 고르기". 웹 조사 매출이 있으면 그 줄은 보인다.
- 재무만 없음(`partial`): 재무 막대 자리에 "미확보: 금융위원회 재무 자료 없음". 국민연금은 보인다.
- 국민연금만 없음: 선 자리에 "미확보: 국민연금 사업장을 찾지 못함".

**배치**: 넓은·중간은 차트 두 개 나란히, 좁은은 위아래. 차트 높이는 확인 중일 때의 자리 표시와 같다.

**접근성**: 차트마다 요약 문장을 화면 읽기 이름으로 단다(예: "매출 2020 사업연도 1.2억원, 2021 3.4억원, 2022 5.6억원" — 가짜 값). 같은 숫자는 2층 표에 있다.

### 4.3 투자 (`#investment`)

**목적**: 누가 언제 얼마를 투자했는지.

**머리 요약**: "투자 라운드 {n}건, 최근 {YYYY-MM} {단계}". 누적액이 있으면 뒤에 "누적 {통화 금액} ({기준 이름})".

**1층**

1. 최근 라운드 3건(최근 날짜순). 한 줄 = 날짜("YYYY-MM-DD", 날짜가 없고 보도일만 있으면 "보도 {YYYY-MM-DD}"), 단계, 금액(통화 그대로, 없으면 "미공개"), "투자기관 {k}곳".
   - 다른 자료의 금액이 있으면 그 줄 아래 "다른 자료 금액: {금액}"과 "엇갈림"을 1층에 그대로 보인다.
   - 줄을 누르면 3층: 투자기관 이름 모두, 리드·주요 투자자 표기, 투자 대상 법인(이 회사 이름과 다르면 "투자 대상: {법인 이름} (이름이 다름)"), 출처 줄, 자료의 원래 표기.
   - 단계 이름은 원래 표기를 우리말로 바꿔 쓴다: Seed → "시드", Series A~E → "시리즈 A~E", Corporate round → "기업 투자", Undisclosed series → "단계 미공개". 표에 없는 표기는 원래대로. 원래 표기는 3층에 남긴다.
2. 투자기관: "투자기관 {n}곳" + 이름 5곳(리드 표기가 있는 곳 먼저, 다음은 참여 라운드가 많은 순, 같으면 최근 참여순).
3. (`facts`가 오기 전) 한 줄 "원문에서 투자자를 더 확인하고 있습니다 (보통 3분 안에 끝남)". 도착하면 이 줄은 사라지고 투자기관 목록의 상태가 바뀌거나 항목이 더해진다.

**2층**

- "라운드 {n}건 모두 보기": 1층과 같은 줄 모양.
- "투자기관 {n}곳 모두 보기": 한 줄 = 이름, 참여 라운드 수, 최근 참여, 상태 낱말(원문 확인 또는 보도). 투자기관 목록은 서버가 합친 한 목록만 쓴다(Premium 회사 카드, 회사 조회 엔진, 웹 보완을 따로 늘어놓지 않는다).
- "이름이 비슷한 다른 법인 자료 {n}건": 법인 이름과 "기존 투자자 판정에 쓰지 않습니다."(설계 문서 4.1).
- "투자 관련 기사 {n}건 보기"(있을 때만).
- "이 자료의 한계"
  - "투자 DB와 기사에 실린 라운드만 보입니다. 결과가 적다고 투자 이력이 없다는 뜻은 아닙니다."
  - "금액은 통화를 바꾸지 않고 자료에 적힌 그대로 보여 줍니다."
  - "투자기관 이름이 영문이면 자금 조달의 모태펀드 운용사(한글 이름)와 맞춰 보지 못할 수 있습니다."

**누적 투자**: 통화마다 따로. 기준 이름을 함께 쓴다: "People Data Labs 누적액" 또는 "라운드 금액 합계 (금액이 있는 라운드 {k}건만 더함)".

**싣지 않는 것**: 투자기관 유형(이름으로 짐작한 VC·전략적·공공 구분). 이름만 보고 짐작한 값이라 뺀다.

**묶음 출처 줄**: "보도. People Data Labs 회사 카드 (Liner Premium)" / "{조회일}". `facts`가 왔으면 둘째 줄 "원문 확인 {k}곳. 기사·공식 자료 원문 (Liner 검색)".

**이어지는 곳**: "투자기관은 자금 조달의 운용사 목록에서 '이미 투자한 곳'으로 따로 표시합니다." + 링크 "운용사 목록 보기"(→ `/c/[id]/funding?lane=invest`).

**상태**: 라운드 0건 → "미확보" + "투자 라운드 자료를 찾지 못했습니다. 투자 이력이 없다는 뜻은 아닙니다."

### 4.4 최근 동향 (`#news`)

**목적**: 최근 12개월 무슨 일이 있었는지 중요한 것만.

**머리 요약**: "최근 12개월 중요 사건 {n}개, 기사 {m}건". 머리 오른쪽 단락 메뉴: 작은 단추 "뉴스만 새로 받기".

**1층**

1. 중요 사건 3개(최신순). 한 줄 = 날짜("YYYY-MM-DD", 월까지만 있으면 "YYYY-MM"), 분류, 제목(두 줄까지). 줄을 누르면 3층: 짧은 설명, 근거 기사 "{매체}, {YYYY-MM-DD}" + "기사 열기", 상태 "보도".
2. 펼치기 줄 "중요 사건 {n−3}개 더 보기".
3. 펼치기 줄 "기사 {m}건 보기".

**2층**

- 중요 사건 나머지: 1층과 같은 줄 모양.
- 기사 목록
  - 맨 위 분류 고르기: 칩 "전체 {m}"과 분류별 "{분류} {건수}"(여러 개 고르기, 건수 많은 순). 좁은 화면에서는 가로로 밀기.
  - 목록: 최신순 20건. 한 줄 = 날짜, 제목(두 줄까지), 매체, 묶인 기사가 있으면 "비슷한 기사 {k}건". 줄을 누르면 3층: 발췌(3줄까지), 분류, "기사 열기".
  - "20건 더 보기 ({남은 수}건 남음)".
  - 처음 열 때 서버에서 받는다(브라우저 사본에는 최근 20건만 있다). 받는 동안 목록 자리 표시와 "기사 목록을 받는 중입니다".
- "흐름 요약 보기": 짧은 흐름 문장 최대 5줄.

**싣지 않는 것**: 500자 안팎의 긴 뉴스 요약 문단. 중요 사건과 흐름 5줄이 같은 내용을 더 짧게 전한다.

**묶음 출처 줄**: "보도. NAVER 뉴스 검색, Liner 검색" / "{기간}, 중복 정리 후 {m}건 (수집 {raw}건)". 그 아래 "중요 사건은 기사 제목과 발췌를 모델이 골라 정리했습니다. 내용은 기사 원문에서 확인하세요."

**이어지는 곳**: "중요 사건은 심사 준비의 미팅 근거 묶음에 '최근 성과'로 들어갑니다." + 링크 "미팅 근거 묶음 보기"(→ `/c/[id]/review?tab=invest#evidence`).

**상태**: 기사 0건 → "미확보" + "최근 12개월 기사를 찾지 못했습니다." 뉴스만 새로 받는 중 → 머리 "새로 확인 중 ({경과}초)", 1층은 이전 결과 유지.

**제3자 글 규칙**: 기사는 제목, 짧은 발췌, 링크만 보인다. 기사 글은 HTML로 해석하지 않고 글로만 보인다.

### 4.5 기술 (`#tech`)

**목적**: 특허로 기술을 보이고, 논문은 원할 때만.

**머리 요약**: "출원인이 확인된 국내 특허 {n}건 (등록 {r}건)".

**1층 (특허)**

1. 특허 연도 선: 최근 5년, 출원연도 기준. 최근 2년 구간에 표시 "공개 전 기간이라 적게 보일 수 있습니다".
2. 주요 특허 3건(최근 출원순). 한 줄 = 발명의 명칭(두 줄까지), 출원일, "등록" 또는 "공개". 줄을 누르면 3층: 요약 전체, 출원번호, 공개번호, 등록번호, 기술 분류 최대 3개, "특허 원문 열기".
3. 원문 확인 한도에 닿았을 때만 한 줄: "특허 문서 {30}건까지 원문을 확인했습니다. 확인하지 못한 후보 {71}건이 있어 실제보다 적을 수 있습니다."

**2층**

- "특허 {n}건 모두 보기"(3건 이하면 없음).
- "회사 이름이 나오지만 출원인이 다른 문서 {k}건": "건수에 넣지 않았습니다."
- "이 숫자의 한계": "검색으로 찾은 공개 특허만 셉니다. 출원 뒤 약 18개월은 공개되지 않아 최근 연도는 적게 보입니다. 같은 출원의 공개·등록 문서는 한 건으로 셉니다."

**묶음 출처 줄**: "원문 확인. 특허 공개 원문 (Google Patents)" / "{조회일}, 출원인이 이 회사인 국내 특허만".

**1층 맨 아래: 논문 (열 때 실행 블록)**

- 실행 전: 제목 "논문 동향", 설명 "회사 기술 분야 {k}개의 논문 발표 추이와 회사가 직접 참여한 논문을 찾습니다.", 단추 "논문 분석하기", 비용 줄 "Liner 학술 검색 {k}회, 모델 1회"(예상 시간은 서버가 주면 앞에 붙인다).
- 조건이 안 됨(`profile` 전): 단추 비활성 + "회사 기술 분야를 받으면 실행할 수 있습니다."
- 실행 중: "논문을 찾고 있습니다 ({경과}초)".
- 완료 1층: 요약 "회사가 직접 참여한 논문 {n}건 (저자 소속 확인)" + 직접 참여 논문 3건(제목, 연도, 학술지·학회). 줄을 누르면 3층: 저자, 소속, 피인용 수, "논문 열기".
- 완료 2층: "직접 참여 논문 {n}건 모두 보기", "분야별 발표 추이와 주요 논문 보기"(특허·논문 연도 선, 분야마다 연구 흐름 2줄, 주요 연구기관 3곳, 주요 논문 3건).
- 완료 묶음 출처 줄: "보도. OpenAlex 논문 DB (공개 API)" / "{조회일}. 회사 이름이 언급만 된 논문은 직접 참여에 넣지 않습니다."
- 0건: "회사가 저자 소속으로 확인되는 논문을 찾지 못했습니다."

## 4B. 경쟁사 분석 (`/c/[id]/rivals`)

> 2026-11-23 화면 구조 개편. 팀원 제안("회사 분석 다음은 경쟁사 분석", VC 심사역 관점)을 사용자가 받아들였다. **새 서버 수집은 없다.** 회사 분석이 이미 받은 경쟁사 후보(`merged.rivals`, 계약 7.9)와 누를 때만 받는 경쟁사 비교 자료(`rivals_deep`, 계약 8.9)를 다시 짠다. 서버 계약(단락 키 `rivals_deep`, 요청 본문, `rivalSet`)은 바꾸지 않았다. 시각 계획은 `visual-plan.md` 6절.

**목적**: 같은 시장의 국내 경쟁사와 우리 회사를 같은 항목·같은 기준으로 나란히 본다. 누가 낫다고 판정하지 않는다(점수·순위·합계·종합 판정 없음, CLAUDE.md 데이터 규칙).

### 4B.0 화면 틀

- 배치 둘(2026-11-23 오케스트레이터 검토: 실제 예시 자료에서 1280 첫 화면이 고르기로 다 차고 "나란히 비교"가 밀렸다. 390은 쪽 길이 약 7,500px).
  - **비교 먼저**(고른 경쟁사가 1곳 이상이고 비교 자료가 있을 때): 제목 → 나란히 비교(머리 바로 아래 고르기 한 줄, 4B.1) → 경쟁사별 사업과 최근 변화 → 경쟁사에 투자한 곳 → 이어지는 곳. 심사역이 볼 것(표)이 첫 화면에 온다.
  - **고르기 먼저**(고른 경쟁사가 없거나 비교 자료가 없을 때): 제목 → 경쟁사 고르기(펼친 채) → 나란히 비교(비교 자료 받기 + 우리 회사 열) → 이어지는 곳. 고르는 것이 할 일이라서다.
  - 배치는 화면을 열 때(회사 분석과 이 브라우저 고르기를 받은 뒤) 한 번 정하고 그 방문 동안 바꾸지 않는다. 고르기를 바꾸거나 비교 자료가 도착하는 순간 덩어리 순서가 바뀌면 보던 자리가 밀리기 때문이다. 다음 방문부터 새 조건으로 정한다.
- 위에서 아래로(공통): 머리줄·단계 메뉴 → 회사 표시줄(한 줄, 1.2절) → 제목 → 위 배치.
- 제목(h1): "경쟁사 분석"
- 설명 한 줄: "회사 분석에서 찾은 국내 경쟁사 후보를 고르고, 고른 곳의 재무·고용·투자·특허를 우리 회사와 같은 항목으로 나란히 봅니다."
- 덩어리마다 제목(h2)과 잉크 1px 윗줄(회사 분석 단락 경계와 같은 모양). 목차는 없다. 위에 붙는 줄은 단계 메뉴 하나.
- 모든 폭에서 한 단. 고르기·글·펼치기 줄은 폭 760px, 비교 표만 화면 폭(최대 1152px)을 쓴다.
- 회사 분석이 없으면(분석한 적 없는 주소): "아직 분석하지 않은 회사입니다." + 링크 "회사 분석으로 가기". 불러오는 중에는 제목만.

### 4B.1 경쟁사 고르기

- **비교 먼저 배치에서는 접힌 한 줄**: "나란히 비교" 제목 바로 아래 펼치기 줄 "고른 경쟁사 {k}곳: {이름들}"(고른 곳이 없으면 "고른 경쟁사 없음"), 오른쪽 "고르기 바꾸기"와 꺾쇠. 펼치면 아래 후보 줄·맞음/아님·직접 넣기가 그대로 나온다. 이 줄 안에서는 더 여는 것을 두지 않는다(0절 깊이 규칙): 후보를 모두 보이고(5곳 넘어도 이어서), "아님으로 고른 후보 {n}곳"은 작은 제목과 목록, "경쟁사 직접 넣기"는 작은 제목과 입력으로 바로 둔다. 후보 줄 자세히가 마지막 층이다.
- 고르기 먼저 배치에서는 덩어리: 제목(h2) "경쟁사 고르기", 머리 요약 "국내 경쟁사 후보 {n}곳, 고른 곳 {k}곳".
- 안내 한 줄: "맞는 경쟁사를 고르면 비교와 심사 준비의 '경쟁사 조건이라면?'에 씁니다. 국내 기업만 후보로 보여 줍니다."
- 후보 최대 5곳(두 자료가 모두 낸 후보 먼저, 그다음 `profile` 순서). 한 줄 =
  - 왼쪽(누르면 3층): 이름(영문 이름이 있으면 작게), 관계(짧은 낱말), 이유 한 줄(넘치면 자름), 상태 낱말(대개 "추정" 또는 "보도").
  - 오른쪽: 두 단추 묶음 "맞음", "아님"(`aria-pressed`). 처음에는 둘 다 눌리지 않은 상태(아래 "처음 고르기"는 예외).
  - 3층: 이유 전체, 제품, 출처 줄.
- (`facts` 전) 한 줄 "후보를 더 찾고 있습니다 (보통 3분 안에 끝남)".
- 2층: "후보 {n}곳 더 보기"(5곳 넘을 때), "아님으로 고른 후보 {n}곳"("아님"을 누른 후보는 1층에서 빠져 여기로 간다. 다시 "맞음"으로 바꿀 수 있다), "경쟁사 직접 넣기"(입력 "회사 이름" + "넣기". 넣은 회사는 "직접 입력"이고 "맞음"이 눌린 채로 목록 끝에 붙는다).
- `profile` 확인 중: 목록 자리에 자리 표시 4줄과 "회사 분석에서 경쟁사 후보를 찾고 있습니다 ({경과})". `profile` 미확보: "미확보: 경쟁사 후보를 찾지 못했습니다." 직접 넣기는 그대로 쓸 수 있다.
- **처음 고르기**: 이 브라우저에서 아직 아무것도 고르지 않았고(맞음·아님·직접 넣기 모두 없음) 받아 둔 비교 자료가 있으면, 그 자료가 비교한 경쟁사(`rivalSet` 전부)를 "맞음"으로 보인다. 후보 목록에 없는 열쇠(그 자료를 받은 사람이 직접 넣은 회사 `user:…` 등)는 비교 자료의 이름으로 직접 넣은 회사에 둔다. 예시 회사나 같은 분석을 처음 연 팀원의 고른 목록·단계 메뉴 개수·비교 표가 저장된 비교 자료와 같게 하려는 것이다. 사용자가 하나라도 바꾸면 그때 보이던 고르기를 이 브라우저에 저장하고 그 위에 바꾼다. 단계 메뉴 개수(1.1절), 심사 준비 "경쟁사 조건이라면?"(6.1절), 미팅 예상 질문의 "고른 경쟁사 {k}곳"도 같은 고르기를 쓴다.
- 규칙: 해외 기업은 후보에 넣지 않는다(서버가 거르고 화면도 한 번 더 거른다). 해외 기업 이름이나 개수도 쓰지 않는다. 맞음/아님과 직접 넣은 회사는 브라우저에만 저장한다.
- 배치: "맞음/아님"은 넓은·중간에서 줄 오른쪽(세로선으로 줄 자세히와 뗀다), 좁은에서 줄 아래 가로 전체(두 단추 반씩).

### 4B.2 나란히 비교

- 제목(h2): "나란히 비교". 비교 자료를 받았으면 제목 줄 오른쪽에 "{MM-DD HH:mm} 실행".

**비교 자료 받기**(1.6절 열 때 실행 블록, 유료)

| 상태 | 보이는 것 |
|---|---|
| 고른 곳 0 | "'맞음'으로 고른 경쟁사가 있으면 재무, 고용, 투자, 특허를 받아 우리 회사와 나란히 봅니다." + 단추 "비교 자료 받기" 비활성 |
| 고른 곳 1~5 | "고른 경쟁사 {k}곳의 법인, 재무, 국민연금, 투자, 특허, 최근 기사를 받아 아래 표에 채웁니다." + 단추 "비교 자료 받기" + 비용 줄 "Liner 약 {m}회 (고른 {k}곳 기준, 한 곳당 약 {p}회)"(m = liner − p × (5 − k), 계약 10절. `perRival`이 없으면 "Liner 약 {liner}회 (경쟁사 5곳 기준)". 예상 시간은 서버가 주지 않아 쓰지 않는다) |
| 고른 곳 6곳 이상 | 위에 더해 "고른 순서로 앞의 5곳만 받습니다." |
| 받는 중 | "비교 자료를 받고 있습니다 ({경과})". 다른 화면으로 가도 계속된다 |
| 받은 뒤 | 표 위(비교 먼저 배치에서는 접힌 고르기 줄 바로 아래) 단추 "비교 자료 다시 받기" + 비용 줄(지금 고른 곳 수 기준). 누르면 1.7절 확인 창(제목 "경쟁사 비교 자료 다시 실행")을 거쳐 지금 고른 경쟁사로 다시 받는다. 표는 다시 받을 때까지 저장된 비교 자료의 회사 그대로다. **고르기가 저장된 비교 자료와 달라도 "바뀌었다" 안내는 띄우지 않는다**(사용자 결정 2026-11-23: 공개·제출 전이라 이런 안내는 필요 없다) |
| 받지 못함(`unavailable`) | "비교 자료를 받지 못했습니다: {사유}" + (다시 할 수 있으면) "비교 자료 받기" |
| 다시 받기 실패(`rerun.status` = `failed`) | 지금 표(이전 결과)를 그대로 두고 한 줄 "이 표는 {YYYY-MM-DD HH:mm}에 받은 것입니다. 다시 받기에서는 {사유}" |
| 예시 회사 | 단추 대신 "예시 회사는 비교 자료를 새로 받을 수 없습니다. 우리 회사 이름을 넣으면 받을 수 있습니다." + 링크 "회사 이름 넣기". 저장된 비교 자료가 있으면 표와 아래 덩어리가 그대로 보인다(서버가 유료 단락을 409 `example_readonly`로 막는다) |

- 유료 호출은 단추를 누를 때만 한다. 화면을 열거나 고르기만으로는 부르지 않는다.
- 단추를 누른 뒤 서버가 거절하면(상한, 요청 제한 등) 단추 아래에 서버 문장.

**비교 표**

- 받기 전: 우리 회사 열만 있는 같은 표. 표를 받으면 오른쪽에 경쟁사 열이 붙는다(줄과 위 덩어리는 움직이지 않는다).
- 받은 뒤: 열 = 우리 회사(첫 열) + 비교한 경쟁사(`rivalSet` 순서, 고른 순서). 값 크기로 열이나 줄을 다시 정렬하지 않는다.
- 열 머리: 회사 이름(굵게). 우리 회사는 이름 아래 작게 "우리 회사".
- 줄 = 항목 7개. 앞 4줄은 회사 분석 핵심 값 띠와 같은 매출·국민연금 가입자·누적 투자·국내 특허, 뒤 3줄은 최근 라운드·주요 투자자·설립(2026-11-23 검토에서 이 순서로 바꿨다. 좁은 화면에서 앞 4줄만 1층에 두기 위해서다):

| 줄 | 우리 회사 | 경쟁사 | 칸 안 기준(작게) | 상태 | 칸 출처(짧게) |
|---|---|---|---|---|---|
| "매출" | `merged.revenue.official`, 없으면 `.web` | `financials` 가장 최근 사업연도 | "{YYYY} 사업연도, {연결/별도}". 원화가 아니면 통화 그대로 | 원문 확인(웹 조사 값이면 보도) | 금융위원회(웹 조사면 Liner) |
| "국민연금 가입자" | `merged.npsLatest` | `nps` 마지막 달 | "{YYYY-MM}" | 참고 | 국민연금공단 |
| "누적 투자" | `funding_history` 누적액(통화마다 한 줄, 더하지 않음) | `funding.summary.cumulative` | 기준 이름("People Data Labs 누적액", "라운드 금액 합계 (…)"). 누적액이 없고 라운드만 있으면 값 "라운드 {n}건", 기준 "금액 미공개" | 보도 | 투자 라운드 자료 출처 |

- **칸 하나** = 값(16px) → 기준(13px 보조 글) → 상태 낱말 + 짧은 출처(13px). 출처의 기관·자료 이름·종류 전체와 기준 시각은 표 아래 각주 줄에 있다. 상태 낱말은 칸마다 붙인다(같은 줄의 칸도 회사마다 상태가 다르다: 우리 매출은 원문 확인, 경쟁사는 미확보 등).
- 값이 없으면 상태 "미확보" + 사유(서버 사유 또는 "법인이 확인되지 않음", "출원인이 확인된 특허를 찾지 못함" 등). 빈칸, "0", "-"만 쓰지 않는다.
- 우리 회사 칸은 "직접 입력"으로 고친 값(설립 연월, 최근 연매출)이 있으면 그 값과 "직접 입력".
- 회사 분석이 아직 그 값을 확인 중이면 그 칸은 "확인 중".
- 표 아래 기준 줄(늘 보임): "우리 회사 {분석 시각} 분석, 경쟁사 {조회 시각} 조회. 회사마다 기준 연도가 다를 수 있습니다." 그 아래 펼치기 줄 "항목별 출처 5줄 보기"(칸마다 상태 낱말과 짧은 출처가 이미 있으므로 기관·자료 이름 전체는 2층): "매출: 금융위원회 요약재무제표 (공공 API). 우리 회사 매출이 웹 조사 값이면 Liner 웹 검색", "국민연금 가입자: 국민연금공단 사업장 가입자 (공공 API). 직원 수와 다릅니다", "누적 투자·최근 라운드·주요 투자자: People Data Labs (Liner Premium)와 기사", "국내 특허: 특허 공개 원문 (Google Patents)", "설립: 금융위원회 기업기본정보 (공공 API)".
- 2층: 펼치기 줄 "그림으로 보기" → 누적 투자 막대(통화마다 따로, 금액이 없는 회사는 막대 없이 "금액 미확보: {회사 이름들}")와 특허 연도 선(회사마다 선 하나, 우리 회사 잉크).
- 만들지 않는 것: 차이(±)·비율·합계 줄, "우세"·"열세"·순위·별, 값이 가장 큰 칸 강조. 이 화면에서 굵은 2px 잉크 윗줄은 비교 표 한 곳이다.

**배치**

- 640px 이상: 표. 첫 열(항목 이름)은 옆으로 밀어도 왼쪽에 붙는다. 회사 열은 최소 9.5em. 1180 폭에서는 경쟁사 5곳도 한 화면에 들고, 820 폭에서 고른 곳이 3곳을 넘으면 표 상자 안에서만 옆으로 민다(화면 전체는 가로로 넘치지 않는다). 표 상자가 실제로 넘칠 때만 표 아래 한 줄 "표를 옆으로 밀면 나머지 경쟁사가 보입니다."
- 표 최대 폭은 열 수에 맞춘다(항목 열 7.5em + 회사 열 15em씩). 받기 전 우리 회사 열 하나가 덩어리 폭으로 늘어나 휑하지 않게 하고, "나란히 비교" 덩어리 폭도 표 폭(최소 760px)에 맞춰 머리 오른쪽 "실행" 시각이 표 끝에 오게 한다.
- 640px 미만: 표 대신 **항목마다 한 덩어리**. 덩어리 이름(굵게) 아래 회사마다 한 줄(왼쪽 회사 이름, 오른쪽 값·기준·상태와 출처). 우리 회사 줄이 맨 위. 같은 항목끼리 견주는 표의 뜻을 휴대폰에서도 지킨다. 1층은 앞 4항목(핵심 값과 같은 항목)이고, 뒤 3항목은 펼치기 줄 "최근 라운드, 주요 투자자, 설립 보기"로 연다(쪽 길이: 가짜 경쟁사 4곳 6,574px → 4,105px).

### 4B.3 경쟁사별 사업과 최근 변화 (받은 뒤)

- 제목(h2): "경쟁사별 사업과 최근 변화"
- 비교한 경쟁사마다 펼치기 줄 하나, 모두 접힘. 줄 글: 경쟁사 이름(굵게), 관계(있으면 작게), 끝에 "최근 변화 {n}줄"(없으면 생략).
- 펼치면(2층): "사업" 문단, "제품·기술" 한 줄, "최근 변화" 목록(최대 5줄), 묶음 출처 줄 "추정. 경쟁사 기사를 모델이 정리 (NAVER 뉴스 검색, Liner 검색)" / "{조회일} 조회". 그 아래 작은 재무 막대·국민연금 선, 최근 라운드 3건, 미확보 사유. 2층 안에 더 여는 것을 두지 않는다.
- 요약이 없으면 "미확보: 사업 요약을 받지 못했습니다."
- 싣지 않는 것: 경쟁사별 뉴스 기사 목록. 양이 많고 "최근 변화"가 같은 역할을 한다(옛 4.6절과 같음).

### 4B.4 경쟁사에 투자한 곳 (받은 뒤)

- 제목(h2): "경쟁사에 투자한 곳"
- 한 줄: "고른 경쟁사의 투자 라운드 자료에 나온 투자기관입니다. 자금 조달 투자받는 돈에서 이름이 같은 모태펀드 운용사에 '경쟁사에 투자'를 붙입니다." + 링크 "투자받는 돈에서 보기"(→ `/c/[id]/funding?lane=invest`).
- 경쟁사마다 한 덩어리: 이름 + "투자기관 {n}곳", 이름 목록 앞 5곳을 한 줄에 이어서(누르는 것이 아니라 이름이라 44px 줄로 세우지 않는다), 넘으면 "투자기관 {n}곳 모두 보기"(같은 층의 이어 보기). 이름 옆 표시(`.tag`): "모태펀드 운용사"(자금 조달 운용사 목록에 이름이 같은 곳이 있음, `gpKey`로 견줌), "이미 투자함"(우리 회사 투자기관과 이름이 같음).
- 보조 한 줄: "새로 찾아볼 운용사 목록이 아닙니다. 직접 경쟁사에 투자한 곳은 이해충돌로 투자를 피할 수 있습니다."
- 투자기관이 하나도 없으면: "고른 경쟁사의 투자 라운드 자료에서 투자기관을 찾지 못했습니다."
- 묶음 출처 줄: "보도. People Data Labs (Liner Premium) 투자 라운드" / "{조회일} 조회".

### 4B.5 이어지는 곳

"고른 경쟁사는 심사 준비의 '경쟁사 조건이라면?'에도 씁니다." + 링크 "심사 준비 보기".

### 4B.6 접근성

- 표: 화면 읽기용 `caption` "우리 회사와 고른 경쟁사 나란히 비교", 회사 열 머리 `scope="col"`, 항목 이름 `scope="row"`. 옆으로 미는 표 상자는 키보드 초점을 받아(`tabindex="0"`, 이름 "비교 표, 옆으로 밀어 볼 수 있습니다") 화살표로 민다.
- 받는 중 글은 1.6절과 같이 경과 초를 알림 영역 밖에 둔다.
- 맞음/아님은 `aria-pressed`, 묶음 이름 "{경쟁사 이름} 경쟁사 고르기".

## 5. 자금 조달 (`/c/[id]/funding`)

**목적**: 회사 값으로 채운 조건에 맞는 공고와 운용사, 그리고 판로 기회를 고르고 담는다. 여기서는 유료 호출을 하지 않는다(판로 갈래의 나라장터 조회는 무료).

**갈래 셋**(2026-11-23 화면 구조 개편): "빌리는 돈", "투자받는 돈", "판로". 판로를 이 화면에 둔 이유: 판로는 회사 사실이 아니라 회사 값으로 찾는 기회 목록이고, 판로 지원사업은 자금 조달과 같은 기업마당 공고이며(수출 공고는 이미 두 화면에 겹쳤다), 담기 → 심사 준비 자격 대조 흐름이 같다. 판로 갈래는 5.2절.

### 1층

- 제목(h1): "자금 조달"
- 조건 줄: 이름표 "회사 분석 값으로 채운 조건" + 칩 4개(누르면 고르기): 지역 {서울}, 기업 유형 {창업·벤처기업}, 필요한 지원 {융자·보증}, 관심 투자 분야 {AI·딥테크·소프트웨어}. 칩은 가운뎃점으로 잇지 않고 따로 둔다.
- 안내 한 줄: "기업마당 분류값으로 거른 목록입니다. 세부 자격은 담은 뒤 심사 준비에서 공고문으로 대조합니다."
- 빠른 거르기 3개: "전체 {n}", "마감 임박(14일 내) {n}", "{지역} 공고 {n}". 빠른 거르기와 "거르기와 정렬"은 빌리는 돈·투자받는 돈에만 걸린다(판로 갈래는 자기 검색어와 내수·수출 고르기로 거른다).
- 세 갈래
  - "빌리는 돈" — 융자·보증·지원사업. 갈래 머리 한 줄: "{필요한 지원} {전체}건 중 다른 지역 {x}건, 대상 아님 {y}건 제외". 공고 카드 5장.
  - "투자받는 돈" — 모태펀드 운용사. 갈래 머리 한 줄: "'{관심 분야}' 분야 모태 자펀드를 운용 중인 곳". 그 아래 차례로
    1. 이미 투자한 운용사 묶음(접힘): 머리 "이미 투자한 운용사 {k}곳" + 한 줄 "새 후보가 아니라 후속 투자나 소개를 부탁할 곳입니다." + 한 줄 "투자자 이름이 영문인 자료는 운용사와 맞춰 보지 못할 수 있습니다." 0곳이면 머리를 "이미 투자한 운용사로 확인된 곳 없음"으로 바꾸고 둘째 줄만 남긴다.
    2. "새로 찾아볼 운용사 {n}곳": 운용사 카드 5장. 이미 투자한 운용사는 이 목록에 넣지 않는다.
    3. (경쟁사 비교 자료를 안 받았으면) 한 줄 "경쟁사에 투자한 운용사를 보려면 경쟁사 분석에서 비교 자료를 받으세요." + 링크 "경쟁사 분석으로 가기"(→ `/c/[id]/rivals`).
  - "판로" — 나라장터 입찰공고와 판로 지원사업(5.2절).
- 담은 항목 막대(1.9절). 세 갈래 모두 하나의 막대를 쓴다.

**같은 공고가 두 갈래에 나올 때**: 기업마당 "수출"·"내수" 공고는 빌리는 돈('필요한 지원'이 "수출·해외진출 지원"이나 "모든 지원사업"일 때)과 판로 갈래 판로 지원사업에 함께 나올 수 있다.
- 목록에서는 빼지 않는다. 각 갈래는 그 질문("이 조건의 지원사업", "판로 지원사업")에 대한 온전한 목록이고, 한쪽에서 빼면 '필요한 지원'을 바꿀 때마다 판로 개수가 따라 바뀐다.
- 대신 이 화면에서 **같은 공고의 담기 상태는 하나다**: 어느 갈래에서 담아도 두 곳 모두 "담음"이 되고, 어느 쪽에서 빼도 둘 다 빠진다(저장은 담은 갈래의 종류 하나, 빼기는 두 종류 모두). 단계 메뉴·심사 준비·"지금 확인할 것"은 같은 공고를 한 번만 센다(지금 `savedNotices`).

### 공고 카드

- 접힌 카드: 첫 줄 표시들(종류, 지역, 관련 시 "회사 사업과 관련"), 공고 제목(두 줄까지), 지원 내용 한 줄, 기관 한 줄(작게). 마감("D-{n}, {M.D} 마감" / "{M.D} 접수 시작" / "신청기간 미기재")은 카드 오른쪽 끝 칸(1.12절 목록 줄). 바닥: "자세히"(확인할 점이 있으면 "확인 {n}"), "담기", "공고 원문"(새 창).
- 펼친 카드(3층): "대상" 한 줄, "맞는 점" 목록, "확인할 점" 목록, "공고문 파일", "신청 페이지" 링크, "문의 {연락처}", "등록 {YYYY-MM-DD}, 출처 기업마당". 맨 아래 한 줄 "공고문 자격 대조는 담은 뒤 심사 준비에서 합니다."

### 운용사 카드

- 접힌 카드: 운용사 이름, 표시("경쟁사에 투자" — 경쟁사 비교 자료를 받았고 해당할 때만), "펀드 {n}개", "최근 결성 {YYYY}년"(표시와 함께 오른쪽 끝 칸, 1.12절), 대표 펀드 이름 한 줄, "출자 분야 {분야}, 만기 {YYYY-MM-DD}". 경쟁사에 투자했으면 한 줄 "{경쟁사 이름}에 투자한 곳입니다."
- 바닥: "펀드 {n}개 보기"(2개 이상일 때), "담기", "웹에서 찾기"(새 창, 운용사 이름으로 검색).
- 이미 투자한 운용사 묶음 안의 카드에는 표시 "이미 투자함"을 붙인다. "담기"는 그대로 둔다(후속 투자 상담을 준비할 수 있게). 담으면 심사 준비와 노트에서도 "이미 투자함"이 따라간다.

### 2층

- "거르기와 정렬": 자주 찾는 낱말 칩 5개, "결과 안에서 찾기" 입력, 정렬("우리 지역·마감순", "마감 임박순", "최신 등록순"). 접혀 있을 때도 걸린 거르기가 있으면 펼치기 줄 문구 뒤에 요약: "거르기와 정렬 (낱말: 운전자금, 마감 임박순)".
- "조건은 어디서 왔나요?": 4줄. "지역: {출처 짧게}, {상태 낱말}", "기업 유형: {근거}", "필요한 지원: 직접 고름", "관심 투자 분야: 회사 분석의 사업 내용으로 고름, 추정".
- "표시의 뜻": "회사 사업과 관련: 회사 기술 낱말이 공고 제목·요약·태그에 있습니다. 순서에만 쓰고 공고를 빼지 않습니다.", "이미 투자함: 회사의 투자기관 이름과 운용사 이름이 같습니다.", "경쟁사에 투자: 고른 국내 경쟁사에 투자한 기록이 있습니다(경쟁사 분석의 비교 자료). 이 업종을 아는 곳이지만, 직접 경쟁사에 투자한 곳은 이해충돌로 투자를 피할 수 있습니다."
- 갈래마다 "10건 더 보기 ({남은 수}건 남음)".
- 바닥: 데이터 기준일·출처 줄(지금 문구), "용어 풀이", "이 목록이 판단하는 것과 하지 않는 것"(지금 내용에서 "점수나 선정 확률은 계산하지 않습니다" 줄은 바닥글과 겹쳐 뺀다).

### 동작과 결과

| 동작 | 결과 |
|---|---|
| 조건 칩 바꾸기 | 목록이 곧바로 바뀌고 더 보기 개수가 처음으로 돌아간다. 칩 옆에 "직접 고름" |
| "담기" | 1.9절. 심사 준비 메뉴 숫자와 막대가 바뀐다 |

### 상태

- 회사 값이 아직 없음(주소로 바로 연 경우): 조건 칩이 "골라 주세요"이고 그 위에 "회사 값을 받는 중입니다. 조건을 직접 골라도 됩니다."
- 분석 값이 나중에 도착(법인 없이 분석해 `facts`가 본사 지역을 준 경우): 조건 줄 아래 "회사 분석에서 본사 지역({지역}, {상태 낱말})을 찾았습니다. 조건을 바꿀까요?" + "바꾸기", "그대로 두기". 사용자가 이미 본 조건을 자동으로 바꾸지 않는다.
- 공고·펀드 목록을 못 불러옴: "공고와 펀드 목록을 불러오지 못했습니다. 잠시 뒤 다시 열어 주세요." (지금 화면의 개발용 명령 안내는 화면에 쓰지 않는다.)
- 빈 결과: 지금 펀딩노트의 원인별 문구를 그대로 쓴다.

### 배치

- 넓은(1024px 이상): 빌리는 돈·투자받는 돈 두 갈래를 나란히(지금 모양). **판로는 그 아래 화면 폭 전체 단**(갈래 머리 3px 윗선은 판로 색, `visual-plan.md` 6절). 빠른 거르기와 거르기와 정렬은 두 갈래 위에 있다. 그 아래 "조건은 어디서 왔나요?", "표시의 뜻", 기준일·출처.
  - 이렇게 정한 이유: ① 두 갈래 나란히는 사용자가 승인한 모양이라 그대로 둔다. ② 셋째 열로 두면 열 폭이 약 384px로 줄어 판로 안의 두 덩어리(입찰공고 목록·지원사업 카드)와 검색어 고치기가 들어가지 않는다. ③ 넓은 화면까지 탭으로 바꾸면 빌리는 돈과 투자받는 돈을 한눈에 견주는 지금 모양을 잃는다.
  - 넓은 화면에서 `?lane=sales`로 열면(옛 판로 주소 포함) 판로 단으로 한 번 스크롤한다. 판로 단은 공고·펀드 목록을 받은 뒤에 그리므로 스크롤도 그 뒤에 한다(그래야 판로 단이 화면에 들어와 나라장터 조회가 나간다, F-24).
- 중간·좁은: 갈래 탭 3개("빌리는 돈 {n}", "투자받는 돈 {n}", "판로")가 단계 메뉴 아래 붙는다. 빠른 거르기와 거르기와 정렬은 탭 아래에 두고 빌리는 돈·투자받는 돈 탭에서만 보인다(판로 탭으로 바꿔도 탭 위 내용이 바뀌지 않아 화면이 밀리지 않는다). `?lane=invest`이면 투자받는 돈, `?lane=sales`이면 판로 탭으로 연다. 판로 탭에는 개수를 붙이지 않는다(입찰공고와 지원사업 두 목록이라 한 숫자로 말할 수 없다).
- 기업 유형을 고르기 전에도 갈래 탭은 보인다(판로 갈래의 입찰공고는 기업 유형 없이 찾는다).

**옛 주소**: `/c/[id]/sales`는 `/c/[id]/funding?lane=sales`로 보낸다(영구 이동 아님). 옛 링크와 즐겨찾기가 끊기지 않게.

### 5.1 회사 없이 자금 둘러보기 (`/funding`)

- 제목(h1): "자금 둘러보기"
- 조건: 지금 펀딩노트의 문장형 고르기 그대로("{지역}에 있는 {기업 유형}입니다. {필요한 지원}을 찾고, 투자는 {관심 분야} 분야를 봅니다.").
- 위 안내 띠: "회사 이름을 넣으면 조건을 채우고, 공고문 자격 대조까지 이어집니다." + 단추 "회사 분석 시작"(시작 화면).
- 카드 단추는 "담기" 대신 "저장" / "저장함". 저장한 항목 보기와 "목록 복사해서 공유"는 지금 그대로.
- 공고문 자격 대조, 운용사 요약, "우리 회사 정보" 입력은 두지 않는다(README 제안 3).
- 회사 표시줄, 단계 메뉴 없음. 판로 갈래는 없다(판로는 회사 기술 낱말로 찾는다).

### 5.2 판로 갈래 (`/c/[id]/funding?lane=sales`, 옛 7절)

**목적**: 공공 조달 입찰공고와 판로 지원사업을 찾아 노트와 심사 준비로 잇는다. 내용과 문구는 옛 판로 화면(7절) 그대로이고, 화면 제목 대신 갈래 머리를 쓴다.

**1층**

- 갈래 머리: 넓은 화면은 제목(h2) "판로"와 판로 색 3px 윗선, 중간·좁은 화면은 "판로" 탭이 제목을 대신한다. 머리 한 줄: "회사 기술 낱말과 회사 값({지역}, {기업 유형})으로 찾은 판로 기회입니다. 위 빠른 거르기는 걸리지 않습니다."(넓은 화면만 둘째 문장. 좁은 화면은 탭 아래에 빠른 거르기가 없다)
- 덩어리 1 "공공 조달 입찰공고"(h3, 나라장터, 최근 28일)
  - 검색어 줄: 이름표 "검색어" + 회사 기술 낱말 최대 6개 + 펼치기 줄 "검색어 고치기".
  - 요약: "입찰공고 {n}건 (최근 28일, 공고명에 검색어가 들어간 것). 진행 중 {k}건."
  - 목록 5건(입찰 진행 중 먼저, 다음 핵심 낱말 일치, 다음 마감 가까운 순). 한 줄 = 공고명(두 줄까지), 수요기관, 금액(없으면 "공고문 확인"), 마감("D-{n}, {M.D} 마감" / "입찰 예정 {M.D}" / "입찰 마감", 오른쪽 끝 칸 — 1.12절), 핵심 낱말과 맞으면 표시 "핵심 낱말 일치".
  - 줄을 누르면 3층: 구분(물품/용역), 입찰 방식, 기간, 신청 조건("참가자격은 공고문 확인" 또는 "물품분류 제한"), 일치한 검색어, "공고 열기", "노트에 담기".
  - 한 줄: "입찰 참가 자격(지역 제한, 업종 등록 등)은 공고문에서 확인하세요."
  - 묶음 출처 줄: "원문 확인. 조달청 나라장터 입찰공고 (공공 API)" / "{기간} 조회".
- 덩어리 2 "판로 지원사업"(h3, 기업마당)
  - 갈래 고르기(두 칸): "내수 {a}", "수출 {b}".
  - 한 줄: "위 조건({지역}, {기업 유형})으로 거릅니다." 기업 유형을 아직 고르지 않았으면 "기업 유형을 고르면 판로 지원사업이 나옵니다."(고르기는 화면 위 "기업 유형을 골라 주세요" 한 곳에만 둔다)
  - 공고 카드 5장(자금 조달 공고 카드와 같은 부품). "담기" → 심사 준비 정책자금·지원사업. 같은 공고가 빌리는 돈에도 있으면 담기 상태가 하나다(5절).

**2층**

- "검색어 고치기": 칩마다 빼기 단추, 입력 "검색어 더하기" + "더하기", 단추 "다시 찾기"(무료, 최대 6개). 고친 검색어는 브라우저에 저장한다.
- 입찰공고 "10건 더 보기 ({남은 수}건 남음)".
- "이 목록의 한계": "참가 자격은 확인하지 않았습니다.", "공고명에 낱말이 들어간 공고를 찾아 관계없는 공고가 섞일 수 있습니다.", "최근 28일 공고만 찾습니다."
- 판로 지원사업 "10건 더 보기".

**동작과 상태**

- **판로 갈래가 처음 화면에 들어올 때** 나라장터를 한 번 조회한다(무료, 서버가 12시간 저장). 중간·좁은 화면은 판로 탭을 열 때, 넓은 화면은 판로 단이 화면에 보일 때다(자금 조달을 열기만 하고 판로까지 내려가지 않으면 부르지 않는다). 같은 방문에서 같은 검색어로 다시 열면 다시 묻지 않는다. 조회 중: 목록 자리 표시와 "나라장터에서 입찰공고를 찾고 있습니다 ({경과}초)".
- 회사 기술 낱말 전(`profile` 전): "회사 분석에서 기술 낱말을 받으면 찾습니다." 검색어를 직접 넣어 "다시 찾기"를 누를 수 있다.
- 일부 구간 실패(`partial`): 요약 아래 "일부 기간 조회에 실패했습니다 ({k}건). 빠진 공고가 있을 수 있습니다."
- 0건: "최근 28일 동안 검색어가 들어간 입찰공고가 없습니다. 검색어를 바꿔 보세요."
- 상한 도달(나라장터 하루 한도): 덩어리 1에 "미확보" + "오늘 호출 상한에 닿아 입찰공고를 찾지 못했습니다. 내일 0시 이후에 다시 찾을 수 있습니다." 판로 지원사업 덩어리는 그대로 보인다.
- 조회 오류: "나라장터에서 응답을 받지 못했습니다." + "다시 찾기".
- 판로 지원사업은 자금 조달과 같은 기업마당 자료를 화면에서 거른다(추가 조회 없음).

**배치**

- 넓은: 판로 단 안에서 입찰공고(줄 목록, 폭 760px) 위, 판로 지원사업(카드 두 칸) 아래.
- 중간·좁은: 위아래, 카드 한 칸.

## 6. 심사 준비 (`/c/[id]/review`)

**목적**: 담은 공고와 운용사를 깊이 대조하고, 심사·미팅에 가져갈 근거와 준비 목록을 만든다. 판정·점수는 없다.

### 6.0 화면 틀

- 제목(h1): "심사 준비"
- 갈래 고르기(두 칸): "정책자금·지원사업 {n}", "투자 {m}". 주소 `?tab=grants` / `?tab=invest`.
- 처음 갈래: 담은 공고가 있으면 정책자금·지원사업, 없고 담은 운용사가 있으면 투자, 둘 다 없으면 정책자금·지원사업.

### 6.1 정책자금·지원사업

**1층**

1. 요약 줄: "담은 공고 {n}건, 자격 대조 {k}건 완료."
2. 부족한 요건(대조 1건 이상일 때): 머리 "부족한 요건" + 한 줄 "미충족 {a}개, 확인 필요 {b}개 (대조한 공고 {k}건)". 펼치기 줄 "부족한 요건 {a+b}개 보기".
3. 대조에 쓰는 회사 값: 한 줄 "대조에 쓰는 회사 값 {채운 수}/8개 채움" + 단추 "회사 정보 수정". 채운 수가 3개 미만이면 한 줄 더 "회사 값이 비어 있으면 대부분 '확인 필요'로 나옵니다."
4. 담은 공고 카드 모두(접힌 채, 마감 가까운 순). 접힌 카드 =
   - 공고 제목(두 줄까지), 마감 표시(오른쪽 끝 칸, 1.12절).
   - 대조 상태 한 줄
     - 대조 전: 단추 "공고문으로 자격 대조" + 작은 글 "보통 30~50초".
     - 대조 중: "공고문을 읽고 있습니다 ({경과}초)".
     - 대조 완료: 종합 문구(지금 기능의 "신청 검토 가능", "대상 아님", "확인 후 판단") + 세 개수 "충족 {x}", "미충족 {y}", "확인 필요 {z}"(따로 놓인 세 표시, 가운뎃점으로 잇지 않는다).
     - 회사 값이 바뀐 뒤: 위에 더해 "이전 회사 값으로 한 대조입니다" + 단추 "다시 대조".
     - 대조 실패: "대조하지 못했습니다: {서버 문장}" + "다시 대조".

**2층·3층**

- 부족한 요건 목록: 조건 분야(업력, 매출, 지역, 인증 등)로 묶는다. 한 줄 = 판정 낱말(미충족/확인 필요), 요건(두 줄까지), 공고 이름(작게). 같은 분야가 여러 공고에 있으면 한 묶음 아래 공고마다 한 줄. 줄을 누르면 3층: 공고문 근거 문장, 판단 이유, 대조에 쓴 회사 값(상태 낱말·출처).
- 대조에 쓰는 회사 값 목록(펼치기 줄 "회사 값 보기"): 8칸(1.8절)과 함께 보내는 값 2개("확인된 특허 {n}건 (원문 확인)", "국민연금 가입자 {n}명 (참고, 직원 수와 다름)").
- 공고 카드를 펼치면(대조 완료 후, 카드의 "자세히" = 2층). 카드 안에 펼치기 줄을 또 두지 않고, 길어질 수 있는 묶음은 "줄 하나 → 누르면 3층" 모양으로 둔다(0절 깊이 규칙).
  1. 종합 문구와 이유 한 줄.
  2. 판단한 조건 모두. 순서는 미충족, 확인 필요, 충족. 충족 줄은 다른 줄보다 조용하게. 한 줄 = 판정 낱말, 분야, 요건(두 줄까지). 줄을 누르면 3층: 공고문 근거 문장, 판단 이유, 대조에 쓴 회사 값.
  3. "기관에 물어볼 것": 모두(번호 목록).
  4. 줄 "준비 자료 {n}개": 누르면 3층에 목록.
  5. 줄 "신청 방법·제출 서류 등 {n}건"(판단 대상 아님): 누르면 3층에 목록과 근거 문장.
  6. 줄 "경쟁사 조건이라면?": 누르면 3층에
     - 고른 경쟁사 0곳: "경쟁사 분석에서 경쟁사를 '맞음'으로 고르면 쓸 수 있습니다." + 링크 "경쟁사 고르러 가기"(→ `/c/[id]/rivals`).
     - 1곳 이상: 경쟁사 고르기(고른 국내 경쟁사만, 4B.1절 "처음 고르기" 포함) + 단추 "이 경쟁사 조건으로 대조" + 작은 글 "보통 20~30초". 비교 자료를 안 받았으면 한 줄 "경쟁사 분석에서 비교 자료를 받으면 경쟁사 값이 채워져 결과가 구체적이 됩니다." 결과와 안내 문장은 지금 기능 그대로.
  7. 바닥: 근거 안내(지금 문구 "근거 문장이 공고문에 그대로 있는 조건만 표시했습니다…"), "다시 대조", "공고 원문", 작은 단추 "담은 공고에서 빼기".

**빈 상태**: "아직 담은 공고가 없습니다. 자금 조달에서 공고나 판로 지원사업을 담으면 여기서 공고문과 자격을 대조합니다." + 단추 "자금 조달에서 고르기".

**상한 도달**: 대조 요청이 하루 호출 상한에 닿으면 그 카드에만 "오늘 호출 상한에 닿아 대조하지 못했습니다. 내일 0시 이후에 다시 대조할 수 있습니다." 단추 "공고문으로 자격 대조"는 비활성. 다른 카드와 이미 받은 결과는 그대로.

**회사 분석이 진행 중일 때**: 대조할 수 있다. 대조에 쓰는 회사 값 줄에 "회사 분석이 끝나지 않아 일부 값이 비어 있습니다"를 붙인다.

**대조 결과 보관**: 대조 결과는 브라우저에 저장하고, 회사 값이 바뀌어도 지우지 않는다. "이전 회사 값으로 한 대조입니다"를 붙이고 "다시 대조"를 권한다(유료 결과를 말없이 지우지 않는다).

### 6.2 투자

순서: 담은 운용사 → 미팅 근거 묶음 → 투자 미팅 예상 질문 → 실사 대비 자료. 담은 운용사가 없어도 나머지 셋은 보인다(회사 분석 결과만으로 만든다).

#### 담은 운용사

- 0곳: "담은 운용사가 없습니다. 자금 조달에서 운용사를 담으면 여기서 요약을 볼 수 있습니다." + 링크 "운용사 고르기".
- 카드(1층): 운용사 이름, 표시("이미 투자함", "경쟁사에 투자"), "펀드 {n}개, 최근 결성 {YYYY}년".
  - 요약 전: 단추 "운용사 요약" + 작은 글 "보통 10~20초". 옆에 "웹에서 찾기".
  - 요약 중: "{운용사 이름} 자료를 검색하고 있습니다 ({경과}초)".
  - 요약 후 1층: "투자 분야: {한 줄}", "투자 단계: {한 줄}"(찾지 못했으면 "미확보"), "맞닿는 점" 처음 2개, "물어볼 것" 처음 2개.
  - 확인되는 사실이 0개: "검색 결과 {n}건에서 이 운용사에 대해 확인되는 내용을 찾지 못했습니다." + "웹에서 찾기".
  - 상한 도달: "오늘 호출 상한에 닿아 요약하지 못했습니다. 내일 0시 이후에 다시 할 수 있습니다." 단추 비활성.
  - 요약 후 2층: 펼치기 줄 "근거 {n}개와 검색 결과 보기": 확인된 사실 모두(종류, 문장, 근거 문장, 출처 링크), 맞닿는 점·물어볼 것 나머지, 검색 결과 목록.
  - 바닥 안내: "검색 결과의 제목과 발췌에서 그대로 확인되는 내용만 적었습니다. 원문 전체를 읽은 것은 아닙니다." 단추 "다시 요약", "담은 운용사에서 빼기".
- 이미 투자한 운용사를 담았으면 카드 위 한 줄: "이미 투자한 곳입니다. 후속 투자나 소개를 부탁할 때 쓰세요."

#### 미팅 근거 묶음 (`#evidence`)

- 머리: "미팅 근거 묶음" + 한 줄 "투자 미팅에 가져갈 근거를 회사 분석 결과에서 모았습니다. 새로 조회하지 않습니다." + 작은 글 "회사 분석 {분석 시각} 기준"(30일 초과면 뒤에 "오래된 분석") + 단추 "미팅 근거 묶음 인쇄".
- 1층: 다섯 덩어리, 덩어리마다 한 줄(펼치면 2층).

| 덩어리 | 1층 한 줄 | 2층 |
|---|---|---|
| "재무·고용 추이" | "매출 {첫 연도} {값} → {끝 연도} {값} ({구분}). 국민연금 가입자 {12개월 전} {n}명 → {최근} {n}명" | 재무 막대, 국민연금 선, 출처 줄 |
| "투자 이력" | "라운드 {n}건, 최근 {YYYY-MM} {단계} {금액}" | 최근 라운드 5건 표(날짜, 단계, 금액, 투자기관 수), 출처 줄 |
| "특허" | "출원인이 확인된 국내 특허 {n}건 (등록 {r}건)" | 특허 연도 선, 주요 특허 5건(명칭, 출원일), 출처 줄 |
| "최근 성과" | "중요 사건 {n}개 중 최근 5개" | 사건 5개(날짜, 분류, 제목, 근거 기사 매체) |
| "미팅 전에 정리할 값" | "자료끼리 다른 값 {a}개, 비어 있는 값 {b}개" | 엇갈림 값(두 값과 출처)과 미확보 값(사유) 목록. 한 줄 끝에 "투자자가 물을 수 있습니다" |

- "→"는 위 표의 숫자 흐름 표시에만 쓰고, 단추 문구에는 쓰지 않는다. 디자인 담당이 다른 표기를 정해도 된다.
- 값마다 상태 낱말과 출처는 2층과 인쇄에서 보인다.
- 회사 분석이 끝나지 않았으면 그 덩어리 한 줄 자리에 "회사 분석에서 확인 중".
- 값이 없으면 덩어리를 빼지 않고 "미확보: {사유}"를 쓴다.
- 인쇄: A4 한 장. 다섯 덩어리 모두 2층까지 펼친 모양, 출처 줄 포함.

#### 투자 미팅 예상 질문

- 1층: 여섯 갈래 펼치기 줄(모두 접힘): "사업 개요 2", "매출과 성장 4", "경쟁 3", "팀과 운영 3", "재무 3", "앞으로의 계획 4".

- 준비한 개수의 합계나 비율은 쓰지 않는다(평가처럼 읽히지 않게).
- 질문 목록(고정 문구, 모델 호출 없음). 원본은 `anthropics/financial-services`의 `dd-meeting-prep`(Apache-2.0)이고 한국어로 다시 썼다. 저장소에 넣을 때 설계 문서 9.2절의 고지를 남긴다.

### 6.3 배치

- 모든 폭에서 한 단으로, 글 줄 길이는 한글 45자 안팎을 넘지 않게. 넓은 화면에서는 남는 폭을 비워 둔다(두 단으로 나누지 않는다).
- 갈래 고르기는 좁은 화면에서 단계 메뉴 아래 붙는다.

### 6.4 접근성

- 갈래 고르기는 탭 목록(`role="tablist"`), 화살표 키로 옮긴다.
- "준비함"은 `aria-pressed`, 화면 읽기 이름 "준비함: {질문이나 자료 이름}".
- 판정 낱말(충족, 미충족, 확인 필요)은 색과 함께 낱말로 보인다.

## 8. 노트 (`/c/[id]/note`)

**목적**: 상담·미팅 전에 한 장으로 정리하고 인쇄하거나 나눈다.

노트는 내보내는 문서라서, 회사 핵심 값의 출처를 3층에 숨기지 않고 값 옆에 작게 쓴다(1.3절 규칙 1의 예외).

### 1층

- 제목(h1): "노트"
- 단추 줄: "인쇄·PDF 저장"(주), "텍스트 복사", "더 보기"(메뉴: "회사 분석 주소 복사", "파일로 내보내기", "파일에서 불러오기").
- 문서 본문(차례대로)
  1. 머리: "{회사 이름} 성장노트", "{YYYY-MM-DD} 작성, 회사 분석 {분석 시각}".
  2. "회사 핵심 값" 표: 지역, 업력(설립일), 기업 유형, 업종, 매출(사업연도·기준), 국민연금 가입자(월), 직원 수, 누적 투자, 국내 특허. 줄마다 값, 상태 낱말, 출처 줄(작게). 엇갈림은 두 값 모두.
  3. "담은 자금 후보": 공고마다 제목, 마감, 대조 결과(종합 문구와 세 개수, 또는 "대조 전"), 미충족·확인 필요 조건 처음 5개.
  4. "운용사": 운용사마다 이름, 표시("이미 투자함"), 투자 분야, 맞닿는 점 2개(요약 전이면 "요약 전").
  5. "판로 후보": 담은 입찰공고와 판로 지원사업(제목, 기관, 마감).
  6. "다음 할 일": "기관에 물을 질문"(공고별), "운용사에 물을 것", "준비할 자료"(공고 준비 자료와 "미팅 전에 정리할 값"). 목록마다 처음 5개.
  7. "메모": 여러 줄 입력. 입력을 멈추면 1초 뒤 브라우저에 저장하고 "저장됨"을 작게 보인다.
  8. 바닥: "회사 분석에 쓴 Liner 호출 {n}회", 상태 낱말 뜻 한 줄("원문 확인: 원문이나 공공 원자료에서 확인 / 보도: … / …").

### 2층

- 목록마다 5개를 넘으면 "{n}개 더 보기".

### 동작과 결과

| 동작 | 결과 |
|---|---|
| "인쇄·PDF 저장" | 인쇄 창. 9절 인쇄 모양 |
| "텍스트 복사" | 노트 전체를 글로 복사. 알림 "노트를 복사했습니다." 출처는 설계 문서 형식 한 줄로 |
| "회사 분석 주소 복사" | 알림 "주소를 복사했습니다. 담은 항목과 메모는 주소에 들어가지 않습니다." |
| "파일로 내보내기" | `성장노트-{회사 이름}-{YYYYMMDD}.json` 내려받기. 안내 "이 브라우저에 저장된 고친 값, 담은 항목, 대조 결과, 노트를 파일로 저장합니다." |
| "파일에서 불러오기" | 파일 고르기 → 묻기 "파일의 내용으로 이 회사의 고친 값, 담은 항목, 노트를 바꿀까요? 지금 브라우저에 있는 내용은 바뀝니다." + "불러오기", "취소". 다른 회사 파일이면 "다른 회사({회사 이름})의 파일입니다. 이 회사 노트로 불러올 수 없습니다." |

### 상태

- 담은 항목 없음: 3~5번 자리에 한 문장 "담은 항목이 없습니다. 자금 조달에서 공고, 운용사, 판로 기회를 담으면 노트에 모입니다." + 링크 "자금 조달로 가기". 회사 핵심 값과 메모는 그대로 보인다.
- 회사 분석 진행 중: 회사 핵심 값의 빈 칸은 "확인 중".
- 오래된 분석(30일 초과): 머리의 "회사 분석 {분석 시각}" 뒤에 "오래된 분석"을 붙이고 인쇄에도 남긴다.
- 미확보 값: 빼지 않고 "미확보: {사유}"로 남긴다(인쇄에도).
- 브라우저 저장소를 못 씀: 메모 아래 "이 브라우저에서는 메모를 저장할 수 없습니다. 텍스트 복사나 파일로 내보내기로 남겨 두세요."

### 배치

- 모든 폭에서 문서 한 단. 화면 폭이 넓어도 종이 비율에 가깝게 폭을 제한한다.
- 좁은 화면에서는 단추 줄이 "인쇄·PDF 저장"과 "더 보기" 둘이 되고 "텍스트 복사"는 "더 보기" 안으로.

## 9. 인쇄

- 대상: 노트(A4 세로, 1~2쪽 목표), 미팅 근거 묶음(A4 세로 1쪽).
- 인쇄에서 숨김: 머리줄, 단계 메뉴, 회사 표시줄 단추, 펼치기 줄, 더 보기, 담은 항목 막대, 메뉴.
- 인쇄에서 펼침: 노트와 묶음의 목록은 "{n}개 더 보기"를 무시하고 모두 인쇄(목록마다 최대 10개, 넘으면 "외 {n}개").
- 차트는 화면과 같은 그림을 쓰고, 흑백으로 찍어도 구분되게 한다(직접 이름 붙이기, 선 모양).
- 쪽마다 아래: "{회사 이름} 성장노트, {YYYY-MM-DD} 인쇄, {쪽}/{전체 쪽}". 첫 쪽 아래에 상태 낱말 뜻 한 줄과 바닥글 문장.
- 링크는 인쇄할 때 주소 대신 출처 이름으로만 남긴다(긴 주소로 줄이 깨지지 않게).
