# 성장노트 시각 계획 (디자인 1단계, `frontend-design`)

> 2026-11-22. 바탕: `design-brief.md`(브리프), `screens.md`(구조·문구), 사용자 지시(흰 바탕, 전문 정보 사이트, 압축 후 펼치기, iPad 터치). 2단계(`impeccable`)는 이 계획과 구현 결과를 함께 본다.
> 순서: 1절 첫 계획 → 2절 브리프와 대조해 고친 것 → 3절 고친 뒤 최종 토큰(구현은 3절을 따른다) → 4절 2단계 보완 → 5절 가독성 조정(2026-11-23, 3절 표에 반영).

## 0. 주제 정하기

- **무엇**: 회사 이름 하나로 공공 자료·공개 보도를 모아 회사를 보여 주고, 자금·심사 준비·판로로 잇는 서비스.
- **누구**: 중소·벤처기업 대표와 재무 담당, 지원기관 담당자, 심사역. iPad 가로·세로, PC, 휴대폰.
- **화면의 주된 일**: 숫자와 그 기준(사업연도, 연결·별도, 월, 통화)을 믿을 수 있게 보이고, 확인하지 못한 것은 못 했다고 쓰는 것.
- **이 세계의 말과 물건**: 감사보고서·재무제표(굵은 윗줄과 가는 아랫줄의 표, 숫자 오른쪽 정렬, "(단위: 억원)"), 통계 자료집(표·그림 아래 출처 한 줄), 회계 장부 용지(녹색 괘선), 공문서 서명에 쓰는 청흑 잉크, 각주 구분선.

## 1. 첫 계획

**색**

| 이름 | hex | 역할 |
|---|---|---|
| 바탕 | `#FFFFFF` | 모든 바탕 |
| 글 | `#1A1F29` | 본문·숫자 |
| 보조 글 | `#667085` | 꼬리표·출처 |
| 선 | `#E4E7EC` | 구분선 |
| 강조 | `#2563EB` | 링크·주 단추 |
| 주의 | `#D97706` | 엇갈림·미확보 |

**글꼴**: Pretendard 하나(본문·제목). 숫자는 `tabular-nums`.

**배치**: 위 머리줄 → 회사 표시줄 → 핵심 값 네 칸(둥근 카드 넷, 큰 숫자와 작은 이름표) → 단락마다 둥근 카드 하나. 넓은 화면은 왼쪽 목차.

**원칙**: 깔끔하게, 카드로 나누기, 상태는 색깔 알약.

## 2. 브리프와 대조해 고친 것

첫 계획을 "비슷한 서비스라면 누구에게나 냈을 안"인지 하나씩 따졌다. 대부분 그랬다.

| # | 첫 계획 | 무엇이 기본값인가 | 고친 것과 이유 |
|---|---|---|---|
| 1 | 글 `#1A1F29` | 검정 대신 쓰는 옅게 물든 거의 검정(브리프 8절) | **청흑 잉크 `#1E2A3F`**. 공문서 서명·재무 서류에 쓰는 파란빛 검정 잉크에서 왔다. 검정을 흉내 낸 회색이 아니라 분명히 남색 쪽이고, 흰 바탕 대비 14:1 |
| 2 | 강조 `#2563EB` | 어느 화면에나 쓰는 파란 단추 | **장부 녹색 `#0C6B58`**. 회계 장부 용지의 녹색 괘선에서 왔다. 누르는 것(주 단추, 펼치기 꺾쇠, 초점, 고른 탭)에만 쓴다. 숫자·상태에는 쓰지 않는다 |
| 3 | 주의 `#D97706` 하나로 엇갈림·미확보 | 신호등의 노랑. 미확보와 엇갈림이 같은 모양 | **엇갈림만 호박색 칠**(`#FCEFD7` 바탕, `#7A4B00` 글). **미확보는 회색 칠 + 점선 테두리**("비어 있음"을 모양으로). 빨강은 팔레트에 두지 않는다(신호등·실패 느낌 없음) |
| 4 | Pretendard | 한국어 화면에서 가장 먼저 손이 가는 기본 글꼴 | **IBM Plex Sans KR + IBM Plex Sans(라틴·숫자)**. 한 가족이라 섞여도 어색하지 않고, 기술·분석 문서 성격이 있다. 숫자는 Plex Sans의 고정폭 숫자(tnum)로 맞춘다 |
| 5 | 핵심 값을 둥근 카드 넷(큰 숫자 + 작은 이름표) | 브리프 7절이 피하라고 한 바로 그 모양(SaaS 카드, KPI 타일) | **재무제표식 숫자 띠**: 굵은 윗줄(2px 잉크)과 가는 아랫줄 사이 네 칸, 칸 사이 세로 실선. 칸 안은 이름표 → 숫자(단위 붙임) → 기준(사업연도, 연결·별도, 월)이 숫자 바로 밑에 붙고 상태 낱말이 이름표 줄 끝에. 숫자와 기준이 한 덩어리로 읽힌다. **화면에서 힘을 주는 곳은 여기 한 곳** |
| 6 | 단락마다 둥근 카드 | 모든 것을 같은 카드로 자르기 | 단락은 **카드 없이 여백과 윗선 하나**로 나눈다. 카드는 정말 한 덩어리인 것(공고·운용사 카드)에만, 그림자 없이 |
| 7 | 단락 제목(큰 글) 아래 요약(작은 글) | 제목이 가장 크고 요약은 회색 | 브리프 3절 "한 줄 요약이 단락보다 약하지 않게"에 맞춰 **뒤집는다**: 단락 이름은 16px 굵게(이정표), **한 줄 요약은 21px**(첫인상) |
| 8 | 상태는 색깔 알약 | 색만으로 구분, 모두 같은 크기로 시끄러움 | 상태 낱말 7개를 **모양으로** 나눈다(3.4절). 원문 확인은 테두리 없는 작은 회색 글(가장 조용), 엇갈림·미확보만 칠 |
| 9 | 출처 줄을 "출처: A · B · C" | 가운뎃점 나열 | **각주 구분선 + 두 부분**(screens 1.3 규칙 8): 짧은 선 하나 아래 "{자료 이름} ({종류})"와 작게 "{기준일}, {기준}". 책·보고서의 각주 모양이다 |
| 10 | 차트 막대 색 두 가지 | 흑백 인쇄에서 구분 안 됨 | 매출은 잉크 칠, 영업이익은 빗금, 음수는 기준선 아래 빗금. 이름은 막대 옆에 직접 쓴다 |

## 3. 최종 계획 (구현 기준)

### 3.1 색 (기본 6개 + 쓰임이 정해진 옅은 색)

| 이름 | hex | 역할 |
|---|---|---|
| `paper` 바탕 | `#FFFFFF` | 모든 화면 바탕(인쇄도 같음) |
| `ink` 청흑 잉크 | `#1E2A3F` | 본문, 숫자, 제목, 차트의 우리 회사 |
| `sub` 보조 | `#515C70`(5절에서 `#586377`보다 한 단계 진하게) | 이름표, 기준일, 출처, 꼬리표, 한계 안내 한 줄, 진행·대기 글(대비 6.7:1, 13px 이상만). **값과 문장에는 쓰지 않는다**(5.3절) |
| `rule` 선 | `#C9D0DA`(5절에서 `#DDE2E9`보다 진하게, 1.5:1) | 목록 줄 사이, 표 안 가는 선, 펼치기 줄 윗선 |
| `edge` 경계 | `#8A95A5`(5절에서 새로, 3.0:1) | 영역을 가르는 경계: 카드·입력·단추·칩 테두리 |
| `ledger` 장부 녹색 | `#0C6B58` | 누르는 것: 주 단추, 펼치기 꺾쇠와 열린 줄의 선, 초점 테두리, 고른 탭 밑줄, 담은 항목 막대 |
| `amber` 엇갈림 | `#7A4B00` / 칠 `#FCEFD7` | 엇갈림 낱말과 칠, 판정 "확인 필요" 표시 |

옅은 색(새 색이 아니라 위 색의 쓰임): `wash #F3F5F8`(줄 자세히가 열린 줄, 미확보 칠, 자리 표시, 5절부터 펼친 내용(2층)·표 머리줄·"지금 확인할 것" 바탕), `ledger-soft #E5F1ED`(고른 칩, 담은 항목 막대 바탕). 갈래 표시선(이 두 곳에만): 빌리는 돈 `#8B6534`, 투자받는 돈 `#3A52A0`, 판로 `#6B4E8A`(6절, 2026-11-23) — 갈래 머리의 3px 윗선(넓은 화면만)과 갈래 탭 밑줄(중간·좁은 화면)에만 쓰고 카드·글에는 퍼뜨리지 않는다.

코드에 흩어져 있던 값을 토큰으로 올린 것(2단계, 새 색 아님): `ledger-deep #0A5A4A`(주 단추 올리기), `rule-strong #B9C1CC`(상태 낱말 "보도" 테두리), `rule-dot #8A95A5`("참고" 점 테두리). 입력 예시 글(placeholder)은 `sub`, 글 고르기 바탕은 `ledger-soft`, 입력 커서는 `ledger`.

### 3.2 글꼴과 크기

- **IBM Plex Sans KR**(한글) + **IBM Plex Sans**(라틴·숫자). 굵기 400·500·600·700. 글꼴을 못 받으면 Apple SD Gothic Neo / Noto Sans KR.
- 숫자는 어디서나 `tabular-nums lining-nums`. 단위(억원, 명, 건)는 숫자에 붙여 한 단계 작게.
- 크기 단계(2026-11-23 5절에서 고침. 처음 값은 Bringhurst 전통 단계 12/14/16/18/21/28/36):

| 크기 | 토큰 | 쓰임 | 전 |
|---|---|---|---|
| **13** | `text-xs` | 출처 줄, 기준일, 꼬리표(`.meta`), 상태 낱말, 눈여겨볼 표시(`.tag`), 목록 줄 오른쪽 작은 줄. 이보다 작게 쓰지 않는다(차트 그림 안 글은 차트 규칙) | 12 |
| **15** | `text-sm` | 보조 글: 이름표, 묶음 이름(굵게), 빽빽한 목록의 보조 줄, 표, 칩·단추, 단계 메뉴·단락 목차, 2층·3층 안의 글 | 14 |
| **16** | `text-base` | 본문 문장, 1층 값, 목록 줄 제목, 펼치기 줄 | 16 |
| **18** | `text-lg` | 단락 이름(굵게), 카드 제목, 목록 줄 오른쪽 큰 줄(D-12), 하위 화면 회사 이름 | 18(단락 이름은 16) |
| **21** | `text-xl` | 단락 한 줄 요약, 덩어리 제목 | 21 |
| **28** | `text-2xl` | 화면 제목, 좁은 화면 회사 이름 | 28 |
| **32 / 36** | `text-[32px]` / `text-3xl` | 핵심 값 숫자(좁은·중간 32, 넓은 36, 가장 굵게), 넓은 화면 회사 이름 36 | 28 / 32 |
- 본문 줄 간격 1.7(한글은 영문보다 넉넉히), 제목 1.3. `word-break: keep-all`. 한 줄은 한글 40~45자(약 680px)를 넘기지 않는다.
- 대문자 머리말, 고정폭 글꼴, 제목 속 낱말 하나 강조는 쓰지 않는다.

### 3.3 배치

**정렬**: 모두 왼쪽 정렬. 가운데 정렬은 빈 상태 문구에만. 숫자 표의 숫자 열만 오른쪽 정렬.

**머리줄**: "성장노트" 글자표 + 단계 줄. 단계 다섯 개를 가는 선 하나로 잇고(순서가 있는 내용이라 선이 정보다, 번호는 붙이지 않음) 지금 단계에 장부 녹색 3px 밑줄.

**자금 조달 — 넓은 화면**: 조건 칩 줄 → 안내 한 줄 → 빠른 거르기 → 두 갈래를 나란히(갈래 머리 3px 윗선만 갈래색). 중간·좁은 화면은 갈래 탭 둘이 단계 줄 아래 붙는다.

**심사 준비·노트**: 모든 폭에서 한 단, 글 폭 680px. 노트는 종이 비율에 가까운 문서 폭(약 760px)과 문서 머리.

### 3.4 작은 부품

**상태 낱말 7개** (눈에 띄는 순서대로, 낱말은 언제나 보인다)

| 낱말 | 모양 |
|---|---|
| 엇갈림 | 호박색 칠, 굵게, 테두리 없음 |
| 미확보 | 회색 칠(`wash`), 굵게, 점선 테두리(`sub`) |
| 추정 | 칠 없음, 파선 테두리, 잉크 글 |
| 보도 | 칠 없음, 실선 테두리, 보조 글 |
| 참고 | 칠 없음, 점 테두리, 보조 글 |
| 직접 입력 | 다른 계열: 테두리 대신 장부 녹색 밑줄과 펜 아이콘 |
| 원문 확인 | 가장 조용: 테두리·칠 없이 보조 글만 |

**상태가 아닌 작은 표시**(2단계에서 따로 정함): 상태 낱말이 테두리·칠로 구분되므로, 상태가 아닌 표시는 테두리·칠을 쓰지 않는다.
- 눈여겨볼 표시(`.tag`: 예시 회사, 이름이 같음, 저장된 분석 있음, 이미 투자함, 경쟁사에 투자, 회사 사업과 관련, 핵심 낱말 일치, 지금 조건과 다른 지역): 잉크 굵은 13px 글 앞에 작은 잉크 마름모. 색은 쓰지 않는다.
- 꼬리표(`.meta`: 공고 종류·지역, "펀드 {n}개"): 보조 글 13px만. 간격으로 나눈다(가운뎃점 없음).
- 카드의 "확인 {n}"은 보조 글, 7일 안 마감은 굵은 잉크(호박색은 엇갈림·확인 필요에만).

**판정 낱말**(자격 대조에만, 상태 낱말과 다른 모양): 낱말 앞에 작은 원 — 충족 = 꽉 찬 원(장부 녹색), 미충족 = 빈 원(잉크, "채우면 열리는 요건"), 확인 필요 = 반원(호박색), 판단 대상 아님 = 짧은 선(보조). 칠한 알약이 아니라 글과 표시.

**펼치기 줄**: 가로 전체, 높이 48px, 윗선 1px, 글은 잉크(흐리게 하지 않음), 오른쪽 끝에 장부 녹색 꺾쇠. 열면 꺾쇠가 돌고, 줄과 열린 영역 왼쪽에 장부 녹색 2px 선이 이어져 "이 줄에서 나왔다"를 보인다.

**줄 자세히**: 줄 전체가 단추. 열린 줄은 `wash` 바탕, 아래 내용은 같은 들여쓰기에 왼쪽 2px 보조 선. 열린 줄과 그 아래 내용은 모서리를 각지게 둔다(둥근 모서리면 왼쪽 선 끝이 휜다, 2단계).

**더 보기**: 펼친 영역 끝의 가로 전체 단추, 테두리 1px, "{k}건 더 보기 ({남은 수}건 남음)".

**출처 줄**: 24px 짧은 각주선 → "{자료 이름} ({종류})" 보조 글 → 작게 "{기준일}, {기준}". 원문이 있으면 끝에 "원문 열기"(새 창 아이콘 + 화면 읽기용 "새 창").

**자리 표시**: 움직이지 않는 `wash` 막대. 채워질 내용과 같은 높이(차트 자리는 차트 높이 그대로).

**차트**: 높이 160~180px, 가는 축, 값은 막대·점 옆에 직접. 매출 = 잉크 칠, 영업이익 = 빗금, 음수 = 기준선 아래. 국민연금 선은 세로축이 0이 아니면 축 아래에 "세로축은 {n}명부터". 특허 선은 최근 2년에 빗금 띠 + "공개 전 기간". 여러 회사면 우리 회사만 잉크, 나머지 보조색, 이름은 선·막대 끝에.

### 3.5 원칙

1. **숫자가 주인공이다.** 고정폭 숫자, 단위는 숫자에 붙이고, 기준은 숫자 바로 밑. 숫자와 기준을 떼어 놓지 않는다.
2. **힘은 한 곳에.** 재무제표식 숫자 띠(핵심 값 네 칸)만 굵은 선을 쓴다. 나머지는 여백과 가는 선.
3. **칠은 주의와 층에만.** 엇갈림·미확보·담은 항목 막대, 그리고 한 층 아래를 보이는 옅은 회색(펼친 내용, 표 머리줄, "지금 확인할 것", 5절) 말고는 면을 칠하지 않는다. 그림자, 그라데이션 없음.
4. **접힌 것은 무엇이 몇 건 숨었는지 말한다.** 펼치기 장치는 세 가지 모양뿐이고 화면마다 같다.
5. **움직임은 사용자에게 답할 때만.** 펼침 0.15초, 들어오며 떠오르는 움직임 없음, 자리 표시는 반짝이지 않는다. 움직임 줄이기 설정이면 모두 끈다.
6. **누르는 곳은 44px.** 줄·칩·단추 모두. 마우스 올리기에만 있는 정보는 없다.

### 3.6 스스로 볼 것 (브리프 12절 대응)

- 흰 바탕 하나, 미색 없음. 그림자·그라데이션 없음.
- 3초 안에 숫자 넷과 기준이 읽히는가(숫자 띠).
- 원문 확인은 조용하고, 엇갈림·미확보는 칠로 바로 보이는가.
- 펼치기 줄·더 보기·줄 자세히가 화면마다 같은 모양인가.
- 390px에서 위에 붙은 줄이 둘 이하인가(단계 줄, 단락 목차 줄 또는 갈래 탭).
- 점수판·게이지·신호등·별점·그림 문자가 없는가.

## 5. 가독성 조정 (2026-11-23, `frontend-design` 다시 한 번)

> 사용자 평가: "전반적으로 안정됐지만 가독성이 일부 떨어진다." 사용자는 iPad로 본다. 원래 요구(꼭 필요한 정보만 압축, 나머지는 눌러서 펼침, 흰 바탕 전문 자료 사이트)는 그대로다.
> 사용자가 준 시안 두 장(인포그래픽, 임대관리 대시보드)에서 승인한 결론: 또렷함은 ① 본문 글자가 진하다 ② 영역 경계가 분명하다 ③ 크기·굵기로 위계를 크게 준다 — 에서 온다. 팔레트(잉크, 장부 녹색은 누르는 것에만, 호박색은 엇갈림에만, 빨강 없음, 상태는 모양)와 3.5절 원칙은 유지한다.
> 고치기 전 셈(`globals.css` 토큰 기준): 본문 대부분 14px(`text-sm` 249회, `text-base` 22회), 작은 부품 12px, 보조 회색 `text-sub` 223회 대 `text-ink` 10회, 구분선 `#DDE2E9`는 흰 바탕 대비 1.3:1.

### 5.1 첫 계획

- **글**: 본문을 모두 16px로 통일, 작은 부품 14px.
- **색**: `text-sub`를 모두 잉크로 바꾼다.
- **선**: 모든 구분선과 단락 경계를 2px 진한 선으로.
- **단락 머리**: 회색 띠(칠한 머리 줄) 위에 단락 이름.
- **① 지금 확인할 것**: 노란 경고 상자 안에 큰 숫자 타일 4개("엇갈림 1", "미확보 2", …).
- **② 목록 줄**: 오른쪽 끝에 색깔 알약("D-12" 녹색, "마감 임박" 주황).
- **③ 핵심 숫자**: 48px, 아래 작은 회색 이름표.
- **④ 층**: 단락마다 회색 바탕 카드.
- **⑤ 단계 옆 개수**: 빨간 알림 점과 숫자.

|---|---|
| 값(숫자·이름·제목·미확보 사유), 문장(설명·안내·결과·이어지는 곳), 묶음 이름(굵게: "최근 라운드", "핵심 기술", "제품·서비스 3개"), 표 값, 단계 메뉴·단락 목차·탭 글(지금 위치는 굵기와 녹색 밑줄로) | 이름표-값 쌍의 이름표("대표", "설립"), 출처 줄, 기준일·조회일·분석 시각, 꼬리표(분류·지역·펀드 수), 단위 표기, 한계 안내 한 줄(브리프 3절 위계 5), 진행·대기 글("확인 중", "불러오는 중"), 비용 줄("보통 30~50초"), 비활성 |

**선**: `rule #C9D0DA` 목록 줄 사이·표 안·펼치기 줄 윗선 / `edge #8A95A5`(3.0:1) 카드·입력·단추·칩 테두리(입력은 WCAG 1.4.11 3:1을 채움) / 잉크 1px 단락 경계·숫자 띠 아랫줄 / 잉크 2px 숫자 띠 윗줄만.

**단락 머리**: 잉크 1px 윗줄 → 위 여백 24~32px → 단락 이름 18px 굵게 → 한 줄 요약 21px.

**①~⑤ 모양과 정의**: 정의는 `screens.md`(① 4.0.3절, ② 1.12절, ⑤ 1.1절). 모양:
- ① 핵심 값 띠 바로 아래 옅은 회색 띠. 제목 "지금 확인할 것"(15 굵게) + 흰 단추(44px, `edge` 테두리) 한 줄. 값 단추는 꺾쇠가 있고 누르면 띠 안에 흰 목록이 펼쳐진다(값 이름, 두 값 또는 사유, "{단락} 단락에서 보기").
- ② `.lrow` 격자: 왼쪽(꼬리표 줄 / 제목 / 부가 정보), 오른쪽 끝 칸(`.lrow-end`). 640px 미만은 오른쪽 칸이 꼬리표 줄 끝으로 올라가 한 줄.
- ③ 위 5.2절 7번.
- ④ 위 5.2절 8번(`.panel` 바탕, 펼친 `.disclosure` 바탕, `thead` 바탕).
- ⑤ 단계 이름 옆 둥근 숫자(13px 굵게, 옅은 녹색). 0이면 없음. 390 폭에서 다섯 단계와 숫자 둘이 한 줄에 들도록 좁은 화면만 칸 안쪽 여백을 8→6px로 줄였다.

**글꼴 다듬기**: `<html>`의 `antialiased`(`-webkit-font-smoothing: antialiased`)를 뺐다. macOS에서 획을 가늘게 그려 Plex 400 본문이 옅게 보였다. iPad(iOS)에는 이 설정이 없어 영향이 없다. 기본 글꼴은 IBM Plex Sans KR 그대로 두고, Pretendard와의 비교는 사진으로만 했다(제품 코드에 넣지 않음).

**함께 고친 것**
- 좁은 화면 칩 좌우 여백 14→10px: 15px 글에서 회사 표시줄 "확인 중" 칩 셋이 두 줄로 꺾였다가 공식 자료가 오며 한 줄로 줄어 아래가 52px 올라붙었다(A-23).
- 좁은 화면 회사 표시줄 분석 시각 칸은 두 줄 높이를 먼저 잡는다: 단추가 "회사 정보 수정"으로 길어져 "YYYY-MM-DD HH:mm 분석"이 두 줄로 꺾이며 글이 10px 움직였다(A-23).
- 핵심 값 칸 최소 높이는 그대로(내용 최대 390 161px/164, 820 141px/144, 1180 165px/168, 실측), 개요 격자 최소 높이 336→344px(기준 기업 사실 칸 333px).
- 목록·정의 목록 행 안의 링크(`.link-fit`): 누르는 영역 44px는 두고 배치 높이는 글 한 줄로. "기업 정보 더 보기"의 홈페이지 행만 높던 문제(사용자 지적)와 같은 모양의 미팅 예상 질문 관련 자료·실사 자료 "분석에 있음" 줄.

**바꾸지 않은 것**: 팔레트의 장부 녹색·호박색·갈래 표시선, 상태 낱말 7개 모양, 펼치기 장치 세 가지, 차트(그림 안 글 크기는 인쇄 기준 PR-06에 묶여 있음), 노트(종이 문서라 인쇄 크기 규칙을 따로 둠).

## 6. 화면 구조 개편: 경쟁사 분석, 판로 갈래 (2026-11-23, `frontend-design`)

> 팀원 제안("회사 분석 다음은 경쟁사 분석", VC 심사역 관점)을 사용자가 받아들였다. 상단 메뉴를 회사 분석 · 경쟁사 분석 · 자금 조달 · 심사 준비 · 노트로 바꾸고, 판로는 자금 조달의 셋째 갈래로 옮긴다. 구조·문구는 `screens.md` 4B절(경쟁사 분석)·5절(자금 조달 갈래)·5.2절(판로 갈래). 1~5절의 토큰과 원칙은 그대로 쓴다.
> 이 세계의 물건: 투자심사보고서의 "경쟁사 현황" 표. 열은 "당사 | A사 | B사", 줄은 설립·매출·인원·투자·특허, 칸 아래 출처 각주.

### 6.1 첫 계획

- **색**: 지금 토큰 그대로. 판로 갈래 표시선은 장부 녹색(`ledger`)을 빌린다.
- **글**: 지금 단계 그대로.
- **경쟁사 분석 배치**: 첫 화면에 경쟁사마다 카드(둥근 상자, 큰 매출 숫자, 작은 이름표) 세 장을 가로로 → 그 아래 맞음/아님 목록 → 맨 아래 비교 표.
- **비교 표**: 줄 = 회사, 열 = 항목 7개. 우리 회사 줄을 옅은 녹색으로 칠한다. 값이 가장 큰 칸을 굵게.
- **단계 메뉴**: 다섯 단계를 지금 이름 그대로, 390 폭에서 넘치면 옆으로 민다.
- **자금 조달**: 넓은 화면에서 세 갈래를 세 열로 나란히.

### 6.2 브리프와 대조해 고친 것

| # | 첫 계획 | 무엇이 기본값이고 왜 안 되는가 | 고친 것 |
|---|---|---|---|
| 1 | 판로 표시선에 장부 녹색 | 녹색은 누르는 것에만(3.1). 갈래 선이 단추처럼 읽힌다 | **판로 표시선 `#6B4E8A`**(옅은 보라, 흰 바탕 6.8:1). 빌리는 돈 갈색·투자받는 돈 남색과 셋이 서로 다르고, 호박색(엇갈림)·녹색(누름)과 겹치지 않는다. 쓰는 곳은 지금 두 갈래와 같다: 넓은 화면 갈래 머리 3px 윗선, 중간·좁은 화면 갈래 탭 밑줄 |
| 2 | 경쟁사마다 둥근 카드 + 큰 숫자 | 브리프 7절이 피하라는 KPI 타일. 회사 분석의 숫자 띠와 힘이 두 곳으로 나뉜다. 카드마다 숫자 하나라 같은 항목을 견주려면 눈이 카드 사이를 오간다 | **비교 표가 이 화면의 주인공**: 심사보고서 "경쟁사 현황" 그대로 열 = 회사(우리 회사 첫 열), 줄 = 항목. 같은 항목이 한 줄에 놓여 좌우로 읽힌다. 이 화면에서 굵은 2px 잉크 윗줄은 이 표 한 곳(회사 분석 화면에는 표가 없으므로 원칙 2 "힘은 한 곳에"를 화면마다 지킨다) |
| 3 | 줄 = 회사, 열 = 항목 7개 | 열 7개면 820 폭에서 한 칸 90px로 기준(사업연도·연결/별도)이 세 줄로 꺾인다. 그리고 지금 표(옛 경쟁사 단락)는 고른 곳이 늘면 아래로 길어진다 | **줄 = 항목, 열 = 회사**(경쟁사는 최대 5곳이라 열은 최대 6). 첫 열(항목 이름)은 옆으로 밀어도 붙어 있다. 640px 미만은 표 대신 **항목마다 한 덩어리**(회사마다 한 줄) — 같은 항목끼리 견주는 표의 뜻을 휴대폰에서도 지킨다(옛 표는 회사마다 한 덩어리라 항목을 견주려면 위아래로 오갔다) |
| 4 | 우리 회사 줄을 녹색으로 칠, 가장 큰 값 굵게 | 녹색 칠은 담은 것·고른 것에만. "가장 큰 값 굵게"는 순위를 매기는 일이다(CLAUDE.md: 점수·순위·종합 판정 금지) | 우리 회사 열은 **머리만** 굵은 이름 + 작은 "우리 회사". 칸은 모두 같은 무게. 정렬은 고른 순서이고 값 크기로 바꾸지 않는다. 차이(±)·합계·"우세" 줄을 두지 않는다 |
| 5 | 칸마다 값만, 출처는 표 아래 | 경쟁사 칸은 상태가 서로 다르다(우리 매출은 원문 확인, 경쟁사는 미확보, 설립은 엇갈림). 묶음 출처 줄 하나로는 어느 칸이 무엇인지 모른다 | **칸 = 값(16) → 기준(13, 보조) → 상태 낱말 + 짧은 출처(13)**. 원문 확인은 가장 조용한 낱말이라 칸이 많아도 시끄럽지 않다. 전체 출처(기관·자료 이름·종류)와 기준 시각은 표 아래 각주 줄 |
| 6 | 단계 메뉴 이름 그대로, 넘치면 옆으로 밀기 | 390 폭에서 "경쟁사 분석"(+개수)이 들어가면 약 430px로 넘친다. 마지막 단계("노트")가 화면 밖에 숨는다 | **좁은 화면(640px 미만)만 짧은 이름**: "회사", "경쟁사", "자금", "심사", "노트". 화면 읽기 이름은 늘 전체 이름(+개수)이라 보이는 글이 이름 안에 들어 있다(WCAG 2.5.3). 화면 제목(h1)이 전체 이름을 쓴다 |
| 7 | 넓은 화면 세 갈래 세 열 | 열 폭이 384px로 줄어 판로 안의 두 덩어리(입찰공고 목록·지원사업 카드)와 검색어 고치기가 들어가지 않는다. 판로는 자금이 아니라 다른 질문이다 | **두 갈래 나란히는 그대로, 판로는 그 아래 화면 폭 단**(갈래 머리 윗선 판로 색). 중간·좁은 화면은 탭 셋. 위 빠른 거르기는 두 갈래에만 걸린다 |
| 8 | 경쟁사 사업 요약을 카드로 늘어놓기 | 비교 표 아래에 글 덩어리 다섯 개가 펼쳐져 화면이 길어진다(사용자 원칙: 꼭 필요한 것만, 나머지는 펼침) | 경쟁사마다 **펼치기 줄 하나**(모두 접힘). 줄 글에 이름·관계·"최근 변화 {n}줄"을 써서 무엇이 숨었는지 말한다(원칙 4) |

### 6.3 최종(구현 기준)

- 토큰: `--color-sales: #6B4E8A` 하나를 더한다(3.1절 갈래 표시선과 같은 쓰임만).
- 경쟁사 분석: 한 단. 고르기·글은 760px, 비교 표만 화면 폭(최대 1152px). 위에 붙는 줄은 단계 메뉴 하나.
- 비교 표: 잉크 2px 윗줄, 머리줄 `wash`, 칸 사이 `rule` 1px, 첫 열 붙음(흰 바탕), 회사 열 최소 9.5em. 표 상자 안에서만 옆으로 밀리고 화면은 넘치지 않는다.
- 자금 조달 판로 단: 넓은 화면에서 두 갈래 아래, 위 여백 48px + 판로 색 3px 윗선 + 갈래 머리.
- 단계 메뉴: 640px 미만 짧은 이름, 개수 표시는 지금 모양(옅은 녹색 원).
