- **밀림(재어 본 값)**: 맨 위에 있을 때 개요 단락 시작 위치가 499px → 506px(12.6초) → 528px(16.7초)로 첫 화면 안에서 29px 내려갔다. 핵심 값 칸이 잡아 둔 높이(132px)보다 값(기준 줄 2~3줄)이 길어서다. 끝나면 진행 줄이 사라져 482px로 올라간다. 아래 단락은 자리 표시보다 훨씬 길어진다(경쟁사 단락 시작 2527px → 4449px). 화면 밖 아래쪽이라 보던 곳은 움직이지 않았고, Chrome은 스크롤 고정(scroll anchoring)으로 읽는 위치를 지킨다. ## 4. 오류·보안(비용 없음)

- 요청 제한: 같은 주소에서 `POST /api/analysis`(예시 회사 새로 분석, 409라 비용 없음) 7번 → 6번째까지 409 `example_readonly`, **7번째 429 `rate_limited`**("요청이 잠시 많았습니다. 1분 뒤 다시 눌러 주세요.", `retryAt` = 60초 뒤). 이어서 화면(예시 회사 판로 "다시 찾기")에서도 같은 문장이 보임.
- 404 `not_found`: 없는 작업(화면 통로·분석 서버), 없는 작업의 기사, 저장된 분석 없는 회사, 통로에 없는 경로, 지운 옛 회사 조회 경로.
- 413 `bad_request`: 통로에 4000자 넘는 본문. 400 `bad_request`: 공백뿐인 회사 이름, 단락에 맞지 않는 본문(뉴스에 경쟁사·낱말, 판로에 경쟁사).
- 422: 요청 모양이 틀림(이름 1자, 깨진 JSON, 모르는 단락 키) — 계약 3절대로 FastAPI 기본 모양. 깨진 JSON 은 해석기 문구("Expecting property name …")가 `detail` 안에 들어가지만 경로·키·예외 이름은 없다.
- 응답 본문 전체에서 내부 경로, `Traceback`, 예외 이름, 키 이름·값을 찾지 못함. 분석 서버 기록에도 Traceback 0건. 화면 글에서도 내부 글 0건(단계마다 검사).
- 원문 확인(내부망 차단 모듈)이 공개 사이트는 연다: 업스테이지 `facts`가 검색 4회 뒤 공개 원문 8쪽을 읽어 원문 확인 투자자 9곳을 얻음. 내부망 차단은 단위 테스트(`tests/test_security.py`)로 확인.
- 참고: 화면 통로는 분석 서버의 `Retry-After` 머리글을 넘기지 않는다(본문 `retryAt`은 넘김). 계약에 머리글 요구는 없다.

## 8. 오케스트레이터 피드백 반영(같은 날, 유료 호출 없음)

### 8.1 진행 중 첫 화면 밀림

- **재는 법**: 저장된 실제 분석 3개(업스테이지, 기준 기업 두 법인)를 단락 도착 순서대로 7단계로 되돌려 주는 재생 서버(scratchpad `verify/replay_server.py`, 포트 8600, 합친 값은 서버 코드 `growth.merge.merged`로 단계마다 다시 계산, 7단계 모두 계약 타입 검사 통과)에 화면을 붙이고, 맨 위에 둔 채 단계를 넘기며 브라우저 layout-shift 기록에서 첫 화면 안 요소의 세로 이동을 모았다. 웹 매출 글은 지금 코드의 표기(5절 7)로 바꿔 재생했다(진행 중 분석은 새 코드로 나오므로).
- **고치기 전(업스테이지)**: 1180 폭 최대 96px, 820 폭 "기업 정보 더 보기"가 첫 화면 밖으로 밀림, 390 폭 최대 54px. 원인은 넷: ① 진행 줄 "아직 확인 중" 목록 줄 수가 바뀜(+22px)·끝날 때 진행 줄이 사라짐(−96px), ② 핵심 값 칸이 잡아 둔 132px보다 길어짐(+3~7px), ③ 단락 "확인 중" 머리 두 줄 → 요약 한 줄(−22px)·개요 자리 표시가 실제보다 낮음, ④ `facts`가 오며 설립 엇갈림(두 값)이 본사 줄을 108px 밀고, 업종 웹 값이 길어 개요 요약이 1줄 → 2줄(+30px).
- **고친 것**:
  - 진행 줄: 높이를 고정한 자리(넓은 화면 두 줄, 좁은 화면 세 줄). "아직 확인 중" 목록은 한 줄로 자르고 말줄임(전역 `p { text-wrap: pretty }`가 `truncate`의 줄바꿈 금지를 덮어써 `div`로 둠). 끝나면 같은 자리·같은 최소 높이에 "분석이 끝났습니다."(미확보가 있으면 기존 문구)와 "닫기"를 남긴다(이 화면에서 진행을 본 경우만, 저장된 분석을 열면 지금처럼 없음).
  - 핵심 값 칸 최소 높이: 390 폭 164px, 640~1023 폭 144px, 1024 이상 168px(실측 끝난 칸 높이 최대 162·140·167px).
  - 단락 "확인 중" 머리: "보통 n초 안에 끝납니다"를 같은 줄에 두어 한 줄 요약과 같은 높이.
  - 개요: 자리 표시를 끝난 모양 높이로(설명 두 줄 + "더 읽기", 제품 한 줄, 기술 낱말 한 줄), 넓은 화면에서 본문 격자 최소 높이 336px(실측 끝난 높이 291~327px)와 한 줄 요약 두 줄 자리(두 줄로 자르고 전체 값은 "기업 정보 더 보기"의 업종 줄), 사실 표 순서를 대표·본사·설립·직원 수로(늦게 바뀌는 줄을 아래로), "기업 정보 더 보기"를 펼치기 줄 맨 앞으로.
- **고친 뒤**: 실데이터 3곳 × 1180·820·390 폭 모두 첫 화면 세로 밀림 **0px**(CLS 0.001~0.008, 가로 이동·첫 화면 밖만 남음). 가짜 응답 `F-STAGED`도 ux-check `A-23 (첫 화면 밀림 {폭})`으로 세 폭 8px 이하 확인.

### 8.2 화면 읽기 알림 영역의 경과 초

- 알림 영역 안에 매초 바뀌는 경과 초가 있던 곳 4곳을 고쳤다: 진행 줄(`role="status"` 뺌. 단락 준비·분석 끝은 원래 있던 알림 영역이 한 번씩 알림), 열 때 실행 진행 글(바뀌지 않는 글만 `role="status"`, 경과 초는 밖), 공고문 대조 카드(`aria-live` 상자를 없애고 카드마다 "공고문을 읽고 있습니다"/"대조가 끝났습니다…"/"대조하지 못했습니다"만 담는 숨은 알림 줄), 운용사 요약 진행 글(열 때 실행과 같은 방식). 보이는 글은 그대로다.
- ux-check `G-20`: 분석 진행 중(F-STAGED t0), 논문 열 때 실행 중, 공고문 대조 중, 운용사 요약 중에 알림 영역 글을 0.7초 간격으로 3~4번 모아 한 가지인지 본다. 가짜 서버에 운용사 요약 지연 조종(`gpDelayMs`)을 더했다.
- 화면 읽기 프로그램으로 소리 내어 듣지는 않았다.

### 8.3 인쇄 차트 글 7pt 이상

- 근거 묶음 인쇄에서 차트 높이 제한(96px)을 없애고 차트를 폭 260px로 그린다(그림 폭 300·글 12 → 약 7.8pt). 실제 데이터 PDF에서 가장 작은 글 **7.79pt**(이전 4.4pt).
